# インフラ / Docker — 既知の落とし穴

## PostgreSQL 18+ の公式イメージはボリュームマウント方式が変更
`/var/lib/postgresql/data` への直接マウントはクラッシュループを起こす
（PGDATA が `/var/lib/postgresql/<major>/docker` に自動配置される方式に
変わったため）。親ディレクトリ `/var/lib/postgresql` を単一マウントする。
バージョンを一つ上げる時は「動くはず」で終わらせず、実機でログを確認する。

## ローカル DB のホスト側ポートは 5433
同じマシンの別の PostgreSQL（5432）と同時に起動できるよう、`docker/compose.yaml` のホスト側ポートを 5433 にしている。
接続先を書くときに 5432 と取り違えない。

## 適用済みマイグレーションと食い違うローカル DB はボリュームごと作り直す
適用済みのマイグレーションが差し替わっている場合（ブランチの切替後など）、
既存コンテナのボリュームには旧スキーマが残っているため、Flyway が
チェックサム不一致で失敗する。`docker compose -f docker/compose.yaml
down -v` でボリュームごと作り直してから再起動する。
