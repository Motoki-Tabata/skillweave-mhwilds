# `.claude/**`・`CLAUDE.md` を直す2つの経路と許可の列挙の書き方

`.claude/**` と `CLAUDE.md` は、区間 A〜E の中では書かない。直すときは、次の2つの経路から選ぶ。どちらの経路でも、直す前に `tasks/lessons.md` に起票してよい（書式は [lessons-guide.md](./lessons-guide.md)）。

## `.claude/**` と `CLAUDE.md` を直す2つの経路

ここで「canon」は、`.claude/**` と `CLAUDE.md` を生成した canon のリポジトリを指す。経路 (b) はそこで run を回す。

| 経路 | 内容 | 選ぶ条件 |
|---|---|---|
| (a) 対象側で直す | 区間の外の `chore/*` ブランチで、メインが直接直す | 数行の文面の修正、1ファイルの規約の追従 |
| (b) canon の run で直す | canon の run が worktree に差分を作り、人間がその差分をマージする | Skill・Agent の新設・廃止、モデル割当、複数の Skill にまたがる手順の変更 |

- どちらの経路でも、起票した台帳の項目は、直したコミットの中で消す（[lessons-guide.md](./lessons-guide.md)）。
- 区間の中で見つけた不備は、その場で直さず台帳に起票し、区間の外で上の経路を選んで直す。その場しのぎの実装を対象側に入れない。
- 同じ規約・同じ手順が `.claude/**`・`CLAUDE.md` と、それ以外のファイル（`README.md`・`specs/README.md`・`design/*.md` 等）の両方に書かれているとき、片方だけを直して満足しない。両方を同じ作業単位で直す。
- **`.claude/**`・`CLAUDE.md` から、それ以外のファイルへの参照は、行番号でなく節見出しで書く。** 例: 「`README.md` の『main への直接 push を防ぐ』節」。行番号は、参照先の編集で無言でずれる。

## 許可の列挙には「列挙に無いもの」の扱いを併記する

許可の列挙を書くときは、その列挙に無いものをどう扱うか（続行／停止／要判断）も同時に定義する。advisory な許可リスト（例: 役割別の常設書込スコープ）は、載っている対象の扱いだけを決めても不十分で、「リストに無いもの」への振る舞いを未定義のままにすると、そこが自己チェックの発火しない死角になる。

実装例は `.claude/skills/impact-scope/SKILL.md` の「書込許可フォルダ」節（許可リスト方式で、列挙に無いものは deny）と、`direct-edit.md` のメインの書込区分（列挙に無いものは書かない）である。ここが、この規律の唯一の正（教訓文面の置き場）。
