# canon 管理境界と許可の列挙の書き方

`.claude/**` と `CLAUDE.md` は、canon（このリポジトリの設定の生成元）が管理する配置対象である。管理範囲の唯一の正は `.claude/README.md` の「管理境界」節。

## 管理境界の規律

- **管理ファイルと非管理ファイルに同内容がある場合、非管理側だけ先に直さない。** 同じ規約・同じ手順が管理ファイルと非管理ファイル（`README.md`・`specs/README.md`・`design/*.md` 等）の両方に書かれているとき、非管理側だけを直して満足しない。管理ファイル側（canon 側の生成規約）を直さない限り、次回の canon の配置で、非管理側の修正だけが浮いた状態になる。
- **管理ファイルから非管理ファイルへの参照は、行番号でなく節見出しで書く。** 例: 「`README.md` の『main への直接 push を防ぐ』節」。行番号は対象プロジェクト側の編集で無言でずれる。canon の検査もこの規律を強制している。
- **canon 側を直さないと、配置対象の修正は次回の配置で上書きされる。** 配置後のファイルを直接編集して問題を解決しても、管理下にある限り恒久ではない。恒久的な修正は canon 側の生成規約に対して行う。
- **`.claude/**` と `CLAUDE.md` への変更要求は、実装せず「canon への要求」として文書化する。** 対象プロジェクト側でその場しのぎの実装をしない。要求内容を `tasks/lessons.md` に起票し（書式は [lessons-guide.md](./lessons-guide.md)）、canon 側の生成規約に反映して恒久化する。
- **`tasks/lessons.md` は、canon の配置時に反映済みの項目だけが削除される。** `.claude/skills/lessons-ledger` のスクリプトが、canon が生成時に記録したスナップショットと照合してから削除する。台帳が無い状態から始まるときは、削除する項目が0件で、台帳に触れない。追記は対象プロジェクト側で行う。範囲の正は `.claude/README.md` の「管理境界」節。

## 許可の列挙には「列挙に無いもの」の扱いを併記する

許可の列挙を書くときは、その列挙に無いものをどう扱うか（続行／停止／要判断）も同時に定義する。advisory な許可リスト（例: 役割別の常設書込スコープ）は、載っている対象の扱いだけを決めても不十分で、「リストに無いもの」への振る舞いを未定義のままにすると、そこが自己チェックの発火しない死角になる。

実装例は `.claude/skills/impact-scope/SKILL.md` の「書込許可フォルダ」節（許可リスト方式で、列挙に無いものは deny）と、`direct-edit.md` のメインの書込区分（列挙に無いものは書かない）である。ここが、この規律の唯一の正（教訓文面の置き場）。
