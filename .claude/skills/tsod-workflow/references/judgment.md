# 調査・判断の規律

重要な技術判断や削除の可否を決める前に読む。

## 一次情報で裏取りする

Web 検索結果や記事は誤りを含みうる。ライブラリの対応状況・非推奨・版の互換性のような重要な技術判断は、ソースコード・配布物（jar・パッケージ）の中身・公式のリリースノート・公開レジストリのメタデータなどの一次情報で裏取りする。複数の記事が同じことを書いていても、一次情報と食い違うことがある。

## 他プロジェクトの構成・標準は取捨選択する

他プロジェクトの CI 構成・設計標準が「推奨」の看板を掲げていても、そのまま丸ごと持ち込まない。このプロジェクトの規模・費用対効果・既存の設計判断（`CLAUDE.md` の憲法や `design/` 配下の標準）と照らして、採用するかどうかを個別に判断する。

## 「念のため残す」と決める前に、復元できないかを確かめる

判断保留のまま「様子見のため残す」と決める前に、削除しても git 履歴や別の保存先から復元できないかを、一次情報（`git log`・`git show` 等）で確かめる。ロールバック経路があると確認できれば、多くの場合、判断保留自体が不要になる。参照関係（参照元を横断 grep で数える）と復元経路の両方を確かめてから、削除の可否を決める。追跡外（gitignore 済み）のファイルは git 履歴から戻らないので、追跡状況も確かめる。
