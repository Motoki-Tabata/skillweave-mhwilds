# UI デザイン標準

> 全機能が従う横断標準。TSOD の画面設計（`/tsod-screen-table`）はこの標準に従うこと。
>
> 作成日: 2026-10-02（**暫定版**）
> 対象: `skillweave-mhwilds`（swv） `apps/web` 全体
>
> **ゲーム用途に合わせた見直しは、画面を持つ最初の機能（003 solver-ui）の画面設計で行う。**
> 特に「未決」と書いた項目（対応画面サイズ・密度・画面骨格・カテゴリ色）はそこで決める。

---

## 適用範囲

- `apps/web/src/main/**` のすべての画面・コンポーネントに適用する。
- 実装上のトークンの置き場は `apps/web/src/main/assets/main.css` に集約する
  （Tailwind v4 は設定ファイルを持たない）。
- 本標準は「何を守るか」を定める。個々の画面のレイアウトは
  `specs/NNN-<slug>/screen-design.md` が定める。

## 1. 色

### 1.1 原則

**色は情報に割り当て、器には使わない。** 背景・枠線・文字などの UI クロームは無彩色に保ち、
有彩色は「データの区別」と「操作の誘導」にだけ使う。器が有彩色だとデータの色と競合して読み取れなくなる。

### 1.2 UI クローム

`shadcn-vue` の `baseColor: neutral`（彩度0）を維持する。有彩色を使うのは次の2つだけ。

| 用途 | トークン | 値（light） |
|---|---|---|
| 主要ボタンの背景 | `--primary` | `oklch(0.52 0.17 252)` |
| 主要ボタンの文字 | `--primary-foreground` | `oklch(0.985 0 0)` |
| フォーカスリング | `--ring` | `oklch(0.52 0.17 252)` |

副次ボタン・枠線・背景は無彩色のまま（`--secondary` / `--border` / `--muted`）。

### 1.3 セマンティック色

| 意味 | トークン | 値（light） | 使いどころ |
|---|---|---|---|
| 破壊的・エラー | `--destructive` | `oklch(0.577 0.245 27.325)` | 削除ボタン、エラーメッセージ |
| 警告 | `--warning` | `oklch(0.75 0.15 70)` | 条件を満たさない構成の注意など |
| 成功 | `--success` | `oklch(0.60 0.13 150)` | 保存完了トースト |

### 1.4 カテゴリ色（未決）

スキル系統・属性などをデータとして色分けするかは 003 で決める。色分けする場合も、
**色だけで区別させず、名称テキストや形を併記する**（§7 の2）。公式の配色・アイコンは使わない。

## 2. タイポグラフィ

### 2.1 フォント

```css
font-family: 'BIZ UDPGothic', 'Yu Gothic UI', 'Meiryo', system-ui, sans-serif;
```

- **外部フォントを読み込まない。** Google Fonts 等の CDN もセルフホストも使わない。
  依存を増やさない方針と整合し、読込遅延・オフライン時の表示崩れ・利用者IPの外部送信をいずれも避けられる。
- フォントスタックは暫定値。スマートフォン（iOS・Android）での表示を含めて 003 で見直す。

### 2.2 サイズ

| 用途 | サイズ | 行間 |
|---|---|---|
| 基準（本文・入力欄・表） | 14px | 1.5 |
| 補助テキスト（説明・注記） | 12px | 1.5 |
| 見出し（画面タイトル） | 20px | 1.4 |
| 小見出し（セクション） | 16px | 1.4 |

- 数値を縦に並べる表（スキルレベル・火力の数値など）には `font-variant-numeric: tabular-nums` を指定し、
  桁を揃える。

## 3. レイアウトと情報密度

### 3.1 対応画面サイズ（未決）

PC とスマートフォンのどちらを主に想定するか、最小対応幅をいくつにするかは 003 で決める。
どの幅でも**ページ全体の横スクロールは発生させない**。収まらない表はその表の中だけで横スクロールさせる
（`overflow-x: auto` を表のコンテナに置き、ページ本体には置かない）。

### 3.2 密度（未決）

表の行・フォームコントロールの高さ、余白は 003 で決める。間隔スケールは 4px 基準（Tailwind 既定のまま）。

### 3.3 画面骨格（未決）

ヘッダー・ナビゲーションの構成は 003 で決める。ただし次の2点は先に決めておく。

- **二次創作である旨を常に見える場所に表記する。** `©CAPCOM` は表記しない（`temp/initial-design.md` §1）。
- ログイン状態による出し分けは1箇所に集約し、コンテンツ側に判定を散らさない。サーバー側でも必ず拒否する
  （画面の出し分けは導線の整理であって、権限制御そのものではない）。

## 4. フォーム

| 規約 | 内容 |
|---|---|
| ラベル位置 | 入力欄の**上**。`shadcn-vue` の既定構成をそのまま使う |
| 必須表示 | ラベルの右に「必須」バッジ。`※` や色だけの表現は使わない |
| エラー表示 | 該当項目の**直下**に赤文字。フォーム先頭に総括メッセージは出さない |
| 検証タイミング | フォーカスを外した時 ＋ 送信時。**入力中は出さない** |
| 送信中 | ボタンを無効化し、ラベルを「保存中…」に変える（二重送信防止） |

---

## 5. 状態表現

| 状態 | 表現 |
|---|---|
| 読込中（300ms未満の想定） | **何も出さない**（ちらつきを避ける） |
| 読込中（一覧） | スケルトン |
| 読込中（ボタン起因） | ボタン内スピナー＋無効化 |
| 操作成功 | トースト（画面右上・数秒で自動的に消える） |
| 項目起因のエラー | 該当項目の直下（§4） |
| 通信・サーバーエラー | トースト（`--destructive`） |
| 破壊的操作の確認 | ダイアログ |
| 空 | 「護石が登録されていません」等の文言＋次の操作への導線 |

- トーストの実装には **Reka UI の Toast プリミティブ**を使う。`vue-sonner` 等の
  追加依存は入れない（依存削減の方針）。

## 6. 日本語 UI 文言

| 規約 | 内容 |
|---|---|
| ラベル | 体言止め（「護石名」「スロット」） |
| メッセージ | 敬体（「保存しました」「入力してください」） |
| 新規登録のボタン | 「登録」 |
| 既存の変更のボタン | 「保存」 |
| 取り消し | 「キャンセル」 |
| モーダルを閉じるだけ | 「閉じる」 |
| エラー文言 | 原因と次の行動をセットで書く |
| 日時 | `YYYY/MM/DD hh:mm`（ブラウザのローカル時刻で表示する。保存は UTC） |
| 日付のみ | `YYYY/MM/DD` |

**禁止事項**

- 「エラーが発生しました」だけの文言（何をすればよいか分からない）
- 英語のままの表示（「Loading...」「No data」等）

### 6.1 用語の統一

ゲーム内の用語（スキル名・部位名など）は、マスターデータの日本語辞書（`packages/data`）の表記に合わせる。
UI 独自の言い換えはしない。表記の揺れが見つかったら本節に追記する。

## 7. アクセシビリティ

**WCAG 2.2 レベル AA 相当を設計時の判断基準とする。** 適合宣言や第三者監査は行わない
（コストに見合わないため）が、次の5点は標準として守る。

1. 文字と背景のコントラスト比は **4.5:1 以上**。UI 部品・境界線は **3:1 以上**。
2. **情報を色だけで伝えない。** 色には必ず文字・形・位置のいずれかを併記する
3. **キーボードだけで全操作ができる。** 護石の手入力を素早く行えるため、実利も大きい。
4. **フォーカス位置が常に見える。** `--ring` によるフォーカスリングを消さない。
5. フォームの入力欄には必ず `<label>` を関連付ける（プレースホルダをラベル代わりにしない）。
