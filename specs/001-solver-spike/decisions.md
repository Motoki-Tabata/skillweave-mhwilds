# 001 solver-spike の決定記録

## Q1（決定: 2026-10-03）
- 問い: 001 solver-spike のコードを 003 solver-engine の土台として残すか、測定後に捨てて 003 で書き直すか。あわせて、数秒以内に解けなかったときの代替（別の ILP ライブラリ・自前の探索・問題の縮約）をどの機能で扱うか（仮: ILP の定式化と HiGHS の呼び出しは `packages/solver` に残し、003 で拡張する。合格基準と不合格時の代替は 001 の spec で決める）
- 決定: 残す。ILP の定式化と HiGHS の呼び出しを `packages/solver/src/main` に置き、003 で拡張する。型は `temp/solver-types.ts` から 001 で使う分だけを移す。
- 不合格時: 001 の中で、縮約（必須スキルに寄与しない防具を部位ごとに代表へまとめる）を1回だけ試して再測定する。それでも不合格なら 001 を「不合格」の結論で閉じ、代替（別の ILP ライブラリ・自前の探索）の選定を新しい Q として起票し、003 の着手前に決める。合格基準は Q8。

## Q2（決定: 2026-10-03）
- 問い: 001 の「実データ規模」の入力を、002 より前にどう用意するか。マスターデータは `packages/data` のパイプラインだけで生成する（憲法）ので、MHDB の JSON をスパイクで直接読むことが憲法に触れないかの線引きも要る（仮: 001 は件数・スロット・スキル分布を MHDB に合わせた合成データで測り、002 の完了後に実データで再測定する。合成データは `packages/solver/src/test/` のフィクスチャに限る）
- 決定: シード固定の合成データ生成器を `packages/solver/src/test/` に置く。件数とスロット・スキルの分布は MHDB の実測値に合わせ、数値だけを出典（取得日）付きでコードに書く。MHDB の JSON はリポジトリにもテストにも取り込まない（憲法の線引き: マスターデータを生成しない・読まない）。
- 実データでの再測定は 003 の受入基準に入れる（003 は 002 に依存するため）。
- MHDB の実測値（`wilds.mhdb.io/en/*` を 2026-10-03 に取得）:
  - 防具 714（頭164・胴140・腕135・腰137・脚138。下位を除くと582）。1部位あたりのスキル数の平均 2.97
  - 装飾品 361（武器用295・防具用66。スロット Lv 1〜3。スキルを2つ持つ装飾品 173）
  - スキル 179（武器66・防具71・シリーズ25・グループ17。最大 Lv 7）
  - 生産護石 64 種（ランク込みで187）

## Q8（決定: 2026-10-03）
- 問い: 001 の合格基準（「数秒以内」の数値）と測定環境をどうするか。
- 決定: Node（Vitest。HiGHS の初期化は時間に含めない）で、防具は上位の全件（582）、必須スキル 3／6／10 個、解あり／解なしの各ケースを測る。
- 1回の検索では構成（解）を列挙し、30件に達したら打ち切る（得た解を除く制約を足して解き直す）。30件に達するか解が尽きるまでの合計時間の最大が 3 秒以内なら合格とする。1回の求解ごとの時間も記録する。003 の複数解の上限は、この 30 件を起点にする。
- 結果は `design/tech-stack.md` に記録する。CI では時間を検査しない（環境で揺れるため）。ブラウザ（Worker）での測定は 004 で行う。
