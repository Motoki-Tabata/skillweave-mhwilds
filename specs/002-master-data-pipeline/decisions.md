# 002 master-data-pipeline の決定記録

## Q7（決定: 2026-10-04）
- 問い: アセンダンス（2027年予定）の「極意」スキル（`MasterSkill.raisesMaxLevel`）を、002・003 で今から扱うか（仮: 型だけ残し、002・003 では扱わない。拡張の発売後に `/tsod-discover` で機能を足す）
- 決定: 仮のとおり。002 は `raisesMaxLevel` を型に残すが、値を出力しない（MHDB の現行データにも該当が無い）。003 も扱わない。拡張の発売後に `/tsod-discover` で機能を足す。

## Q9（決定: 2026-10-04）
- 問い: オーバーレイ（MHDB に無いもの・MHDB の誤りの訂正を手作業で重ねる定義）の書式と、その読込みに使う依存をどうするか。
- 決定: YAML で書く。読込みには `yaml`（依存0）を `packages/data` の devDependencies に足す。ブラウザへは配信しない（パイプラインの実行時だけ使う）。版の選定は区間 C で `pnpm-workspace.yaml` のサプライチェーン設定に従って行う。

## Q10（決定: 2026-10-04）
- 問い: パイプラインのコードとオーバーレイの置き場をどうするか。
- 決定: コードは `packages/data/src/main/` に置き、Node 24 の型除去で `node` から直接実行する（実行器の依存を足さない）。オーバーレイは `packages/data/overlays/*.yaml` に置き、コードと分ける。
- data-agent の書込許可に `packages/data/overlays/**` を足すよう、canon への改修要求を `tasks/lessons.md` に起票する。反映されるまでは、オーバーレイのファイルを spec の「常時許可外の変更予定」に挙げ、メインが書く。

## Q11（決定: 2026-10-04）
- 問い: MHDB の取得物（統合 JSON）をリポジトリに入れるか。CI でパイプラインをどう扱うか。
- 決定: 取得物はコミットしない。`LartTyler/mhdb-wilds-data` の `output/merged` を、コミット SHA を固定して raw.githubusercontent.com から取得し、git 管理外のキャッシュに置く。コミットするのは生成物の `packages/data/dist/` だけ。
- CI はネットワークから取得しない。コミット済みの `dist/` をテスト（参照切れ・範囲の検査）で検証する。再生成して `dist/` と差分が無いことの確認はローカル限定とする。

## Q12（決定: 2026-10-04）
- 問い: `master_version` をどう決め、`dist/` にどの版を残すか。
- 決定: 版（例: `2026.10.1`）は、MHDB のコミット SHA と並べて設定ファイルに人が書く。同じ版のまま出力の中身が変わったら、生成を失敗させる（版の上げ忘れを防ぐ）。
- `dist/` には現行の版だけを置く。保存済みの構成が参照する旧版の扱いは 011 build-save で決める。
