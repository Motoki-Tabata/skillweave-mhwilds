# 003 solver-engine の決定記録

## Q13（決定: 2026-10-04）
- 問い: Worker・キャンセル・タイムアウトの境界をどこに引くか。HiGHS の1回の求解は同期処理で、途中で割り込めない。
- 決定: 003 は Worker とのメッセージ型と、`self` に触れない純粋なメッセージハンドラ（`loadMaster`・`solve`・`cancel` を受けて送信メッセージを返す）までを `packages/solver/src/main` に持つ。Worker の起動スクリプトと HiGHS の WASM の読み込みは 004 が `apps/web` に書く。HiGHS のインスタンスは引数で受け取る（001 と同じ）。
- キャンセルとタイムアウトは求解と求解の合間に判定する。合間でイベントループに処理を返し、`cancel` を受け取れるようにする。1回の求解の上限には HiGHS の時間制限を使う。
- タイムアウトしたときは、それまでに見つけた構成を `status: 'timeout'` で返す。キャンセルされた要求には結果を送らない。
- 同時に処理する要求は1件。実行中に別の `solve` を受けたら、実行中の要求をキャンセル扱いで打ち切り、新しい要求を始める。
- 構成を1件見つけるごとに進捗（見つけた件数）を送る。

## Q14（決定: 2026-10-04）
- 問い: 目的関数（`feasible`・`maximize: defense | freeSlots | expectedDamage`）の意味を、003 でどう決めるか。
- 決定: 003 は `feasible`・`defense`・`freeSlots` を実装する。`expectedDamage` は 006 まで、不正な要求として扱う。
- `defense`: 防具の防御力の合計を最大化する。
- `freeSlots`: 防具用の空きスロットの Lv の合計を最大化し、同点なら武器用の空きスロットの Lv の合計が大きい方を選ぶ（辞書式）。結果には、防具用・武器用それぞれの空き Lv の合計を分けて返す。
- 主目的が同点の構成では、`freeSlots` と同じ順（防具用、次に武器用の空き Lv の合計）で決める。必須スキルに要らない装飾品を付けた構成を返さないため。`feasible` も同じ扱いにする。
- 状態: 1件以上見つかったら、`maximize` は `optimal`、`feasible` は `feasible`。1件も無ければ `infeasible`。タイムアウトは `timeout`（Q13）。

## Q15（決定: 2026-10-04）
- 問い: 防具の候補をどの範囲にするか。複数解の件数の上限をいくつにするか。
- 決定: マスターの全防具（下位を含む）から、除外の指定を引いたものを候補にする。下位を外すかどうかは、呼び出し側（004）が除外の指定で決める。
- `maxResults` は 1〜30 を受け付け、範囲外は不正な要求として扱う（001 Q8 の 30 件を上限にする）。
- 列挙の重複の定義は 001 のまま（防具と護石の組が同じ構成を2回返さない）。

## Q16（決定: 2026-10-04）
- 問い: 001 Q2 で 003 に回した実データでの再測定の合格基準と、不合格のときの扱い。
- 決定: 合格基準は 001 と同じ（検索1回の合計時間の最大が 3 秒以下。HiGHS の初期化は含めない。Node で測る）。必須スキルの組は実データ（`packages/data/dist/` の現行の版）から固定で選び、シリーズ／グループスキルを含む 3／6／10 個 × 解あり／解なしを測る。
- 結果は `design/tech-stack.md` に記録し、CI では測らない（001 と同じ）。
- 3 秒を超えたら、対策を `specs/open-questions.md` に新しい Q として起票し、004 の着手前に決める。003 はその記録をもって閉じてよい。

## Q17（決定: 2026-10-04）
- 問い: ソルバーがマスターデータをどの型で受け取るか。
- 決定: `@swv/data` の `MasterBundle` 型をそのまま受け取る（`initial-design.md` §8.6 の `loadMaster`）。`packages/solver` の dependencies に `@swv/data`（workspace）を足し、型だけを import する。001 で `packages/solver` に複製した ID 型・`Slot`・`SkillLevel` などは `@swv/data` のものに寄せる。
- `@swv/data` の入口は import 文を持たず DOM・Node に依存しないので、憲法（ソルバーを API の型と DOM に依存させない）に触れない。

## Q18（決定: 2026-10-04）
- 問い: 解けない要求と、要求そのものの誤りをどう分けるか。
- 決定: 次は解なし（`infeasible`）ではなく、不正な要求としてエラーを返す（Worker では `error` メッセージ）。
  - マスターを読み込んでいない、または `masterVersion` が読み込んだマスターの版と一致しない。
  - マスターに無い ID（武器・防具・スキル）を指定した。
  - 部位の固定に、その部位ではない防具を指定した。同じ防具を固定と除外の両方に指定した。
  - 必須スキルの下限が 1 未満か、そのスキルの最大レベルを超える。
  - `maxResults` が 1〜30 の外、`timeoutMs` が 0 以下、目的関数が `expectedDamage`。
- 部位の固定・除外・候補の絞り込みの結果として条件を満たせないものは、解なしとして返す。

## Q19（決定: 2026-10-04）
- 問い: シリーズ／グループスキルの部位数を、何から数えるか。
- 決定: 装備した防具の `setBonusIds` と、武器の `setBonusIds`（個体差のある武器を含む）をそれぞれ1部位として数える（`temp/solver-types.ts` の設計どおり）。護石と装飾品は数えない。部位数が閾値以上の最大の段のレベルを、そのスキルのレベルとする。
- 必須スキルにシリーズ／グループスキルを指定できる。下限は段のレベルで判定する。
- 実装で足した扱い（ゲート D-1・2026-10-04 承認）: `SetBonus` が無いシリーズ／グループスキル、段が無い下限は、エラーにせず解なし（`infeasible`）として返す。実データでは起きない入力（マスターの不整合）の扱いで、テストで固定している。
