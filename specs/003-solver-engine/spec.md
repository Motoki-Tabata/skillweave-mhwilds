# 003: solver-engine

## 目的 / ユーザーストーリー
開発者（オーナー）として、001 で確かめた HiGHS の定式化を、実際のマスターデータ（002 の `MasterBundle`）と画面からの要求（`SolverRequest`）を受けて構成（`SolverResponse`）を返すソルバー本体に広げたい。画面（004）が Worker に結線するだけで検索できるように、シリーズ／グループスキル・部位の固定と除外・個体差のある武器・装飾品の配置・複数解・タイムアウトとキャンセル・`masterVersion` の照合・Worker のメッセージを、DOM に依存しない形で `packages/solver` に揃える。001 で合成データにしか測っていない時間を、実データで測り直す（001 decisions.md Q2）。

用語:
- 構成: 防具5部位（頭・胴・腕・腰・脚）と護石1つの組と、それに付ける装飾品の配置。
- 不正な要求: 解けるかどうか以前に、要求そのものが誤っているもの（decisions.md Q18）。解なしとは分けて返す。

## 受入基準（EARS記法）
- THE system SHALL `packages/solver` に、マスター（`MasterBundle`）・HiGHS のインスタンス・要求（固定の武器・護石候補・必須スキル・部位の固定と除外・目的関数・件数の上限・時間の上限）を受け取り、必須スキルのレベルがすべて下限以上になる構成を求める関数を提供しなければならない。武器は、マスターの武器か、スロット・スキル・シリーズ／グループスキルを直接持つ個体差のある武器のどちらかを受け取る。
- THE system SHALL シリーズ／グループスキルのレベルを、装備した防具と武器の `setBonusIds` を1部位ずつ数えた部位数が閾値以上になる最大の段のレベルとし、必須スキルにも指定できるようにしなければならない（decisions.md Q19）。
- THE system SHALL 固定されていない部位について、マスターの全防具から除外された防具を引いた候補から1つを選び、固定された部位はその防具に（固定が null なら何も付けない状態に）限らなければならない（decisions.md Q15）。
- THE system SHALL 護石候補が空でなければちょうど1つを選び、空なら護石なしで解かなければならない。装飾品は、武器用の珠を武器用のスロットへ、防具用の珠を防具用のスロットへ、珠の Lv 以上のスロットにだけ付けなければならない。
- WHEN 目的関数が `defense` のとき THE system SHALL 防具の防御力の合計を最大化し、`freeSlots` のとき防具用の空きスロットの Lv の合計を最大化し、同点なら武器用の空きスロットの Lv の合計が大きい構成を選ばなければならない（decisions.md Q14）。
- THE system SHALL 主目的が同点の構成のあいだでは（`feasible` を含む）、防具用、次に武器用の空きスロットの Lv の合計が大きい構成を選び、必須スキルに要らない装飾品を付けた構成を返してはならない。
- WHEN 構成が見つかったとき THE system SHALL 得た防具と護石の組を除いて解き直し、件数の上限に達するか解が尽きるまで列挙しなければならず、1回の検索で防具と護石の組が同じ構成を2回返してはならない。状態は、1件以上あれば `maximize` で `optimal`・`feasible` で `feasible`、1件も無ければ `infeasible` とする。
- THE system SHALL 構成ごとに、装飾品を付けたスロット（持ち主と添字）、空きスロット、発動スキル（最大レベルで頭打ちした値と頭打ち前の合計）を返し、目的関数が `freeSlots` のときは防具用・武器用それぞれの空き Lv の合計を分けて返さなければならない。
- IF 要求が不正なとき（マスター未読込・`masterVersion` の不一致・マスターに無い ID・部位の違う防具の固定・同じ防具の固定と除外・最大レベルを超える下限・`maxResults` が 1〜30 の外・`timeoutMs` が 0 以下・目的関数が `expectedDamage`） THEN システムは、解なしではなくエラーを返さなければならない（decisions.md Q18）。
- IF 時間の上限を超えたとき THEN システムは、求解と求解の合間で列挙を打ち切り、それまでに見つけた構成を状態 `timeout` で返さなければならない（decisions.md Q13）。
- THE system SHALL Worker とのメッセージ型と、Worker のグローバル（`self`）に触れない純粋なメッセージハンドラを提供し、`loadMaster` でマスターを保持して読み込んだ版を返し、`solve` で構成を1件見つけるごとに進捗を送って最後に結果を送り、不正な要求には `error` を送らなければならない。
- WHEN `cancel` を受けたとき、または実行中に別の `solve` を受けたとき THE system SHALL 次の求解の合間で実行中の要求を打ち切り、打ち切った要求には結果を送ってはならない。
- THE system SHALL 返すすべての構成について、ソルバーと独立に数え直したスキルのレベル（シリーズ／グループスキルを含む）と装飾品の配置が、必須スキルの下限・スロットの種別と Lv を満たしていることを、テストで検算しなければならない。
- WHEN 測定を実行したとき THE system SHALL `packages/data/dist/` の現行のマスターを使い、実データから固定で選んだ必須スキル（シリーズ／グループスキルを含む）3／6／10 個 × 解あり／解なしの各ケースについて検索1回の合計時間を出力し、3 秒の基準に対する合否とともに `design/tech-stack.md` に記録しなければならない。CI では時間を測らず、3 秒を超えたら対策を `specs/open-questions.md` に新しい Q として起票しなければならない（decisions.md Q16）。
- THE system SHALL `packages/solver/src/main` のコードを DOM・Node の API と API の型に依存させてはならない。マスターの型は `@swv/data` から型だけを読む（decisions.md Q17）。

## スコープ外
- 火力（`expectedDamage`）の最大化と、発動条件（`activeConditionIds`）の扱い（006）
- Worker の起動スクリプト・HiGHS の WASM の読み込み・ブラウザ（Worker）での測定（004）
- 下位防具を候補から外すかどうかの判断（004 が除外の指定で決める）
- 武器を探索の対象にすること（`initial-design.md` §8.7。武器は固定で受け取る）
- 防具・装飾品の所持の管理（すべて持っているものとする）
- 護石の入力と、鑑定護石の抽選テーブルによる妥当性検査（005）
- 極意スキル（`raisesMaxLevel`）の扱い（002 decisions.md Q7）
- 31 件以上の構成の列挙
- 再測定で 3 秒を超えたときの対策の実装（新しい Q で決める）

## 契約差分
- なし（API を持たない。ソルバーはブラウザ内で動く）
