## 0. 前提

## 2. C1 共通レイアウトと S1・D2 の変更

### 2.1 ヘッダー（テーマの切り替え）

```
┌ ヘッダー（sticky・48px）──────────────────────────────┐
│ SkillWeave [非公式の二次創作]            [☀]  （将来: 認証導線） │
└────────────────────────────────────────┘
```

| 部品 | 内容 |
|---|---|
| テーマの切り替え | アイコンだけのボタン（ghost・44×44px）。認証導線の空きの左に置く（認証導線は右端のまま）。ダークのときは太陽のアイコンで `aria-label`・`title` は「ライトテーマに切り替える」。ライトのときは月のアイコンで「ダークテーマに切り替える」。アイコンは lucide |
| 動作 | 押すと `<html>` の `dark` クラスを付け外しし、`localStorage` の `swv-theme` に `light` か `dark` を書く。既定はダーク。OS の設定は見ない。`localStorage` が使えないときも、その場の切り替えは効かせる（エラーは出さない） |

### 2.2 ナビの行

```
┌ ヘッダー ─────────────────────────────┐
├ ナビの行（44px・下に罫線。固定しない）─────────┤
│  装備検索   護石                                  │
│  ━━━━                                           │
```

- `<nav aria-label="画面の切り替え">` の中にリンクを2つ（「装備検索」→ `/`・「護石」→ `/charms`）。各リンクの高さは 44px。
- 今の画面のリンクに `aria-current="page"` を付け、太字と下端の 3px の差し色の線で示す（色だけにしない）。
- ヘッダーと一緒に固定しない（基準幅で作業領域を狭めないため）。横幅はページのコンテンツと同じ最大幅にそろえる。
- 基準幅（360px）ではヘッダーに収まらないため、ヘッダーとは別の行にする（2.6 の見積もり）。

### 2.3 S1 検索画面の変更

条件パネルのカードを「武器」「必須スキル」「護石」「検索条件」の順にする（「護石」を足すだけで、パネルの並べ方は変えない）。

「護石」カード（見出しは h2「護石」）:

| 状態 | 表示 |
|---|---|
| 読込中 | 300ms 未満は何も出さない。超えたら「護石を読み込んでいます…」（`role="status"`） |
| 候補が1件以上 | 「候補にする護石: <N> 件」（N は Inter・`tabular-nums`）。検索対象外の護石があるときは、下に補助文「登録した <M> 件のうち <K> 件は、スキルが現行のマスターに合わないため候補から外しています。」 |
| 登録が0件 | 「護石が登録されていません。護石なしで検索します。」 |
| 読込失敗 | 警告の帯（MASTER.md の「警告の帯」）「護石を読み込めませんでした（<原因>）。護石なしで検索します。」。検索は止めない |
| 共通 | カードの下に、S2 へのリンク（見た目は outline のボタン・高さ 40px）「護石の一覧へ」 |

- 検索は、送信した時点の候補を `SolverRequest` に渡す。
- 検索条件の要約に「／ 護石 <N> 件」を足す。

構成カード（004 の 3.2.5）に「護石」の節を足す。左の列の「防具」と「装飾品」のあいだに置く。

```
護石
  レア度    8
  スキル    攻撃 Lv2・見切り Lv1
  スロット  武器用 Lv1・防具用 Lv2
```

| 項目 | 内容 |
|---|---|
| 構成が護石を使っている | 上の3行（ラベルは補助テキスト・幅 56px）。スキルはチップで折り返して並べる。スキルが無ければ「スキルなし」、スロットが無ければ「スロットなし」 |
| 構成が護石を使っていない | 検索の候補に護石が1件以上あったときは「護石なし」。候補が0件のときは節ごと出さない |
| 装飾品の表・空きスロット | 持ち主「護石」の行・チップに、護石のスロットの Lv を出す（004 では護石が出なかったため Lv が「−」になる作り） |

- 表示する護石は、検索した時点の内容にする（検索の後に護石を編集・削除しても、表示中の結果は変えない）。

## 3. S2 護石画面

### 3.1 画面構成

基準幅から `lg` 未満は、上から次の順に並べる。`lg` 以上は、左に入力フォーム（400px）、右に一覧を置く（間隔 24px。MASTER.md の Page Pattern の「条件」と「結果」の型）。

1. h1「護石」
2. 入力フォームのカード（h2「護石を登録」。編集中は「護石を編集」）
3. 一覧（h2「登録済みの護石（<N>）」）

画面の主要ボタン（差し色の面）は、フォームの「登録」（編集中は「保存」）の1つだけ。

### 3.2 入力フォーム

```
護石を登録
 レア度 [必須]   ( 5 )( 6 )( 7 )(●8 )
 スキル1         [ 攻撃              ▾][Lv2 ▾][×]
 スキル2         [ 見切り            ▾][Lv1 ▾][×]
 スキル3         [ スキルを検索       ▾][ −  ▾][×]
 スロット1       [ 武器用 Lv1            ▾]
 スロット2       [ 防具用 Lv2            ▾]
 スロット3       [ なし                  ▾]
 ┌ 照合の結果 ──────────────────────┐
 │ ✓ 抽選テーブルに合います（レア8）。          │
 └─────────────────────────────┘
 [        登録        ] [入力を空にする]
```

| 項目 | 部品 | 必須 | 既定 | 入力規則・動作 |
|---|---|---|---|---|
| レア度 | RadioGroup（横並び・ラベル「レア度」と「必須」バッジ）。選択肢「5」「6」「7」「8」。各選択肢の高さ 44px、数字は Inter | 必須 | 未選択。登録した後は直前のレア度を残す | 矢印キーで移動する。範囲（5〜8）は `apps/web` の定数に持つ（Q32） |
| スキル1〜3 | 行ごとに、ラベル「スキル<i>」、Combobox（スキル名の入力と候補の一覧）、レベルの Select（ラベルは画面に出さず `aria-label="スキル<i>のレベル"`）、空にするボタン（アイコン・44×44px・`aria-label="スキル<i>を空にする"`） | 任意 | 空 | 候補は武器スキルと防具スキルだけ（シリーズ・グループは出さない）。検索の規則は 2.4。候補の各行に、スキル名と、右に種類（「武器」「防具」・補助テキスト）を出す。入力が空のときはすべてを種類ごと（武器→防具）・名前の順に出す。入力があるときは、候補の下に補助の行「「<語>」を含むスキル: <N> 件（名前と読み）」を出す。0件のときは「該当するスキルがありません。名前か読みを変えてください。」。スキルを選ぶとレベルは Lv1 になる。レベルの選択肢は「Lv1」〜「Lv<最大>」で、スキルが空のあいだは無効 |
| スロット1〜3 | 行ごとに Select（ラベル「スロット<i>」）。選択肢「なし」「武器用 Lv1」「武器用 Lv2」「武器用 Lv3」「防具用 Lv1」「防具用 Lv2」「防具用 Lv3」 | 任意 | なし | — |

構造上の制約のエラー（Q32。項目の直下に `--destructive` の文字で出す。Select と RadioGroup は変更した時点、Combobox はフォーカスを外した時点と送信時に検証する）:

| 条件 | 出す場所 | 文言 |
|---|---|---|
| レア度が未選択で送信した | レア度の直下 | 「レア度を選んでください。」 |
| 同じスキルが2つある | 後の行の直下 | 「スキル<j>と同じスキルです。別のスキルを選ぶか空にしてください。」 |
| 空の行の下にスキルがある | 空の行の直下 | 「スキル<i>が空です。スキルは上の行から順に入力してください。」 |
| 空のスロットの下にスロットがある | 空の行の直下 | 「スロット<i>が「なし」です。スロットは上の行から順に入力してください。」 |
| スキルが現行のマスターに無い（編集で読み込んだ護石） | その行の直下 | 「このスキルは現行のマスターにありません。別のスキルを選ぶか空にしてください。」 |
| レベルが現行のマスターの最大を超える（同上） | その行の直下 | 「Lv<n> は最大レベル（Lv<m>）を超えています。レベルを選び直してください。」 |
| Combobox に文字があるのに候補を選んでいない | その行の直下 | 「候補からスキルを選んでください。」 |

- 構造上の制約に反するあいだは保存しない。送信したときは、最初の不正な項目にフォーカスを移す。

照合の結果（Q33。構造上の制約を満たし、レア度を選んでいるときだけ出す。入力を変えるたびに求め直す。`role="status"` で読み上げる）:

| 結果 | 表示 |
|---|---|
| 合格 | チェックのアイコンと「抽選テーブルに合います（レア<r>）。」 |
| 未検査 | 情報のアイコンと「レア<r>の抽選テーブルは未整備のため、照合していません。このまま登録できます。」 |
| テーブル不一致 | 警告の帯（MASTER.md の「警告の帯」）。見出し「抽選テーブルに合いません（レア<r>）」、合わない点の箇条書き、その下にチェックボックス「テーブルに合わないことを確認しました」（行の高さ 44px） |

テーブル不一致の合わない点の文言（どの点を出すかの判定は、区間 C で照合の関数とともに決める）:

- 「スキル<i>「<名前> Lv<n>」は、レア<r>のスキル<i>の枠に出ません。」
- 「スキル<i>の枠は、レア<r>にはありません。」（スキルの数が多すぎる）
- 「スロットの並び「<並び>」は、レア<r>にありません。」
- 「スキルとスロットの組み合わせが、レア<r>のどのパターンにも当てはまりません。」（個々には合うが、1つのパターンにそろわない）

テーブル不一致のときは、確認のチェックを入れるまで保存しない。チェックを入れずに送信したら、チェックボックスの直下に「確認のチェックを入れてください。」を出す。入力を変えたらチェックは外す。

操作:

| モード | ボタン | 動作 |
|---|---|---|
| 登録 | 「登録」（primary）・「入力を空にする」（outline） | 「登録」で新しい UUIDv7 を振って保存する。保存中は「保存中…」で無効にする。保存したらトースト「護石を登録しました。」を出し、スキルとスロットを空にして（レア度は残す）、スキル1にフォーカスを移す。「入力を空にする」はレア度も含めて既定に戻す |
| 編集 | 「保存」（primary）・「キャンセル」（outline） | 一覧の「編集」でその護石をフォームに読み込む。「保存」で同じ ID のまま上書きし、トースト「護石を保存しました。」を出して登録のモードに戻り、フォーカスを一覧のその護石の「編集」に戻す。「キャンセル」は変更を捨てて登録のモードに戻り、フォーカスを同じ「編集」に戻す |

- Combobox で Enter を押したときは候補を選ぶだけで、送信しない。
- IndexedDB を開けないあいだは、フォーム全体を無効にし、フォームの先頭に「端末に保存できないため、護石を登録できません。」を出す（原因は一覧の側に出す。3.4）。

### 3.3 一覧

```
登録済みの護石（12）
┌──────────────────────────────────┐
│ レア8 [✓合格]                          [編集] [削除] │
│ 攻撃 Lv2  見切り Lv1                                 │
│ スロット 武器用 Lv1・防具用 Lv2                      │
├──────────────────────────────────┤
│ レア7 [△テーブル不一致]                [編集] [削除] │
│ ...                                                  │
├──────────────────────────────────┤
│ レア6 [ⓘ未検査] [⊘検索対象外]          [編集] [削除] │
│ 超会心 Lv4  …                                        │
│ 「超会心 Lv4」が最大レベル（Lv3）を超えています。    │
│ 編集して直すまで、検索の候補から外します。           │
└──────────────────────────────────┘
```

| 項目 | 内容 |
|---|---|
| 並び | 登録の新しい順（ID の UUIDv7 の時刻の降順）。編集しても並びは変えない |
| 1行目 | 「レア<r>」（太字・数字は Inter）と、状態のラベル。右に「編集」（outline）と「削除」（MASTER.md の破壊的なボタン。枠線だけで、文言を必ず出す）。ボタンの高さは 44px |
| 状態のラベル | Badge（outline）にアイコンと文言を併せて出す（色だけにしない）。「合格」（チェック）・「テーブル不一致」（三角形）・「未検査」（情報）のどれか1つ。加えて、検索の候補から外れる護石には「検索対象外」（禁止の円）を出す |
| 2行目 | スキルのチップ「<名前> Lv<n>」（並び順のまま・折り返す）。スキルが無ければ「スキルなし」 |
| 3行目 | 「スロット <武器用 Lv1・防具用 Lv2>」。スロットが無ければ「スロットなし」 |
| 検索対象外の理由 | 3行目の下に補助テキストで、理由（「スキル「<名前>」が現行のマスターにありません。」「「<名前> Lv<n>」が最大レベル（Lv<m>）を超えています。」）と「編集して直すまで、検索の候補から外します。」 |
| 編集中の行 | 左端の 3px の差し色の線と `--muted` の背景（MASTER.md の表の「選択中の行」） |
| 件数 | 見出しに登録の件数。検索対象外があるときは、見出しの下に補助文「検索の候補になるのは <N> 件です。」 |
| 各ボタンの読み上げ | `aria-label` は「<要約>を編集」「<要約>を削除」。要約は「レア<r>・<名前> Lv<n>・…・<スロット>」 |

- 一覧は `<ul>` で、行の区切りは `--border` の 1px（MASTER.md の表と同じ。縞模様は使わない）。
- `lg` 未満で「編集」を押したら、フォームまでスクロールし、レア度にフォーカスを移す。

### 3.4 状態

| 状態 | 条件 | 表示 |
|---|---|---|
| 読込中 | IndexedDB とマスターの読み込みが終わっていない | 300ms 未満は何も出さない。超えたら一覧の位置にスケルトン |
| 空 | 登録が0件 | 一覧の位置に「護石が登録されていません。」と、導線のボタン「入力欄へ移動」（outline。押すとレア度にフォーカスを移す） |
| 一覧あり | 登録が1件以上 | 3.3 |
| マスターの読込失敗 | マスターか辞書を取得できない | 004 の P2 と同じ Alert（エラー）と「再読み込み」。フォームと一覧は出さない（スキル名と照合にマスターが要るため） |
| 端末に保存できない | IndexedDB を開けない | 一覧の位置に Alert（エラー。消えないインラインの表示）。見出し「護石を保存できません」、原因を1行、次の行動「ブラウザの設定でこのサイトのデータの保存を許可するか、プライベートブラウズをやめてから、「再読み込み」を押してください。護石なしの検索は引き続き使えます。」と「再読み込み」（outline）。フォームは無効（3.2） |
| 書き込みの失敗 | 登録・保存・削除が失敗した | トースト（`--destructive`）「護石を保存できませんでした。<原因> もう一度お試しください。」（削除のときは「削除できませんでした。」）。フォームの入力は残す |

原因の文言:

### 3.8 キーボード・フォーカス・読み上げ

## 4. 端末に保存する護石の形（IndexedDB）

010 charm-save のサーバー側（`temp/initial-design.md` §5.2 の `charms`）と同じ形にする（Q32・`design/data-model-standard.md`「所有者と監査カラム」）。サーバーだけが付ける `userId`・`version`・`deletedAt` は、端末では持たない。

| 項目 | 型 | 内容 |
|---|---|---|
| `id` | string | UUIDv7（クライアント採番）。キー |
| `payload` | object | `{ rarity: number, skills: { skillId, level }[], slots: { target, level }[] }`。並びはゲーム内の表示順。`SolverCharm` の `rarity`・`skills`・`slots` と同じ形 |
| `schemaVersion` | number | `payload` の形の版。005 は 1 |
| `createdAt` | string | 登録した日時（UTC の ISO 8601） |
| `updatedAt` | string | 最後に保存した日時（UTC の ISO 8601） |

- データベースの名前・ストアの名前・版の付け方は区間 C で決める。
- 削除は端末から消す（物理削除）。同期は扱わないため（009・010・014）。
- 照合の結果と検索対象外かどうかは保存しない（0 節）。
- プロパティ名の camelCase とサーバーの列名（snake_case）の対応は 010 で決める。
