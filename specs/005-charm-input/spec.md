# 005: charm-input

## 目的 / ユーザーストーリー
プレイヤー（ログインしていないゲスト）として、手持ちの鑑定護石を手で入力して端末に保存し、その護石を使った構成をソルバーで探したい。入力の誤りに気づけるよう、抽選テーブルに照らして、ありえない組み合わせの護石には警告が出てほしい。あわせて、ヘッダーからライトテーマに切り替えられるようにする（decisions.md Q26）。

用語:
- 鑑定護石: スキル（最大3個）とスロット（最大3枠）が個体ごとに異なる護石。005 で扱う護石はこれだけで、生産護石（マスターの `charms`）は扱わない（decisions.md Q30）。
- 抽選テーブル: レア度ごとのスキル枠グループとスロットパターン（マスターの `appraisedCharm`）。手作業の overlay で作る（decisions.md Q3）。
- 照合の結果: 「合格」「テーブル不一致」「未検査（そのレア度のテーブルが無い）」の3つ（decisions.md Q33）。
- 読み: スキル名のひらがなの読み。手作業の overlay で作り、ja の辞書に出す（decisions.md Q34）。

## 受入基準（EARS記法）
- THE system SHALL ログインなしで、鑑定護石のレア度（5〜8）、スキル（0〜3個。武器スキルか防具スキルを名前か読みで検索して選び、レベルを 1 からそのスキルの最大レベルまでで選ぶ）、スロット（0〜3枠。各枠で武器用か防具用と Lv 1〜3 を選ぶ）を、ゲーム内の表示順のとおりに入力して登録できなければならない（decisions.md Q32）。
- WHEN スキルを名前で検索するとき（護石の入力と、004 の必須スキルのダイアログ） THE system SHALL 入力をスキル名と読みの両方に部分一致で照らし、ひらがなとカタカナ、全角と半角の違いを同一視しなければならない。読みが無いスキルは名前だけで照らす（decisions.md Q34）。
- WHEN 護石を登録・編集・削除したとき THE system SHALL それを端末内の IndexedDB に保存し、再読み込みの後も一覧に残さなければならず、護石をサーバーへ送ってはならない。新しい護石の ID はクライアントで採番した UUIDv7 とし、保存する形は 010 charm-save のサーバー側と同じにしなければならない（decisions.md Q32）。
- THE system SHALL 登録した護石を一覧で、レア度・スキル（名前とレベル）・スロット（武器用か防具用と Lv）・照合の結果とともに表示し、それぞれを編集・削除できるようにしなければならない。
- IF 入力した護石が構造上の制約（スキルの重複・シリーズ／グループスキル・最大レベルの超過・レア度やスロットの範囲外）に反するとき THEN システムは、保存を拒否し、どの項目が反するかを示さなければならない（decisions.md Q29・Q32）。
- WHEN 入力した護石のレア度の抽選テーブルがマスターにあるとき THE system SHALL スキルとスロットを並び順どおりにテーブルと照合しなければならない。IF 照合が不一致のとき THEN システムは、合わない点を示し、ユーザーが確認したうえで保存できるようにし、一覧に「テーブル不一致」と示さなければならない（decisions.md Q29・Q33）。
- IF 入力した護石のレア度の抽選テーブルがマスターに無いとき THEN システムは、照合せずに登録を受け付け、入力画面と一覧に「未検査」と示さなければならない（decisions.md Q3）。
- WHEN 検索を実行したとき THE system SHALL 登録した護石のうち構造上の制約を満たすものすべて（未検査・テーブル不一致を含む）を護石の候補として `SolverRequest` に渡し、護石が1つも無ければ護石なしで解かなければならない。検索の前に、候補にする護石の件数を検索画面に表示しなければならない（decisions.md Q32）。
- WHEN 構成が護石を使っているとき THE system SHALL 構成ごとに、使った護石のレア度・スキル・スロットと、護石のスロットに付けた装飾品を表示しなければならない。
- IF 登録した護石のスキルが現行のマスターに無い、または現行のマスターの最大レベルを超えるとき THEN システムは、その護石を検索の候補から外し、一覧にその旨を示さなければならない（decisions.md Q32）。
- IF IndexedDB を開けない、または書き込みに失敗したとき THEN システムは、護石を保存できないことと原因を表示し、護石なしの検索は引き続き使えるようにしなければならない。
- WHERE オーナーが抽選テーブルを起こしたレア度があるとき THE system SHALL それを `packages/data/overlays/` の `appraisedCharm` に書き、マスターの版を上げて `dist/` を再生成しなければならない。照合のテストは、実データではなくテスト用のテーブルで行う（decisions.md Q3）。
- THE system SHALL すべてのスキルの読みを `packages/data/overlays/` に書き、ja の辞書のスキルの項目に読みを出し、マスターの版を上げて `dist/` を再生成しなければならない（decisions.md Q34）。
- THE system SHALL ヘッダーにダークとライトを切り替える操作を置き、既定をダークにし、OS の設定に追従せず、選んだテーマを `localStorage` の `swv-theme` に保存して再読み込みの後も保たなければならない（decisions.md Q26）。
- THE system SHALL Playwright（Chromium）の e2e テストで、「護石を登録し、再読み込みの後も一覧に残り、その護石を使った構成が検索で表示される」流れと、構造上の制約に反する護石の保存が拒否されることを検証しなければならない。

## スコープ外
- 生産護石の入力と、生産護石を検索の候補にすること（decisions.md Q30。方式は open-questions.md Q31）
- 護石のサーバーへの保存・同期と、ログイン後のゲスト下書きの取り込み（009・010）
- 護石の OCR 入力（016）と、抽選テーブルを使った逆引き（017）
- 護石ごとに検索の候補から外す切り替え（decisions.md Q32）
- 抽選テーブルをレア度 5〜8 のすべてで揃えること（005 の完了条件にしない。decisions.md Q3）
- 抽選テーブルを持たせるための `MasterBundle` の型の変更と、鑑定護石のレア度の範囲のパイプラインへの移設（decisions.md Q32）
- テーマの OS の設定への追従（decisions.md Q26）
- PC を主にしたブレークポイントの見直しと、検索画面のレイアウトの変更（open-questions.md Q28）
- 護石の一覧の並べ替え・絞り込みと、ファイルへの書き出し・読み込み
- 武器名・防具名・装飾品名の読みでの検索（decisions.md Q34）
- 検索条件と結果の端末への保存（004 decisions.md Q23 のまま）
- 画面の英語対応（004 decisions.md Q4 のまま）

## 契約差分
- なし（API を持たない。護石は端末内の IndexedDB に保存し、ソルバーはブラウザの Worker で動く）
