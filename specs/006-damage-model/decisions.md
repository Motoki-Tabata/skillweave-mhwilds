# 006 damage-model の決定記録

## Q35（決定: 2026-10-24）
- 問い: `expectedDamage` が最大化する「期待値」に何を含め、どう計算するか。
- 決定: 物理の期待値だけを扱う。属性（`element_add`・`element_mul`・会心撃【属性】）は 006 の対象外とし、未確定事項 Q40 として `open-questions.md` に申し送る。
- 計算式:
  - 攻撃力 = 武器の攻撃力 × `attack_mul` の値の積 ＋ `attack_add` の値の和。
  - 会心率 = 武器の会心率 ＋ `affinity_add` の値の和。−100〜100（%）の範囲に丸める。
  - 会心倍率 = 1.25。`crit_mul` の値は会心時の倍率そのもの（例: 超会心 Lv1 は 1.28）とし、有効な `crit_mul` があればその最大値を使う。
  - 会心補正 = 会心率が 0 以上なら 1 ＋ 会心率 ÷ 100 × (会心倍率 − 1)、負なら 1 ＋ 会心率 ÷ 100 × 0.25（負会心は 0.75 倍）。
  - 期待値 = 攻撃力 × 会心補正。ソルバーは丸めない（表示の丸めは 007）。
- 効果を数えるスキルのレベルは、発動スキルのレベル（最大レベルで頭打ちした後の値。シリーズ／グループスキルは部位数から決まる段のレベル）とし、`effectsByLevel` のそのレベルの効果を使う。
- 斬れ味・モーション値・肉質・アイテム・食事は含めない。武器を固定して解くため、構成の並びに影響しない。
- 倍率を武器の攻撃力にかけ、加算をその後に足す順序は、ゲームの説明文（「攻撃力を１．０２倍し、基礎攻撃力＋８」）に合わせた。最終確認はオーナー（`design/master-data.md`「ゲーム仕様の確認結果」と同じ扱い）。

## Q36（決定: 2026-10-24）
- 問い: 期待値は攻撃力と会心補正の積で非線形のため、ILP の線形の目的にそのまま載らない。`maximize: expectedDamage` をどこまで厳密にするか。
- 決定: 厳密な最大を保証する。返す構成は、要求を満たす構成のうち期待値が最大のものから順に並べる（2件目以降は、それまでに返した構成を除いた中での最大）。期待値が同点の構成は、003 の Q14 と同じ順（防具用、次に武器用の空き Lv の合計）で決める。
- 求解の方式（期待値の離散化・線形化など）は区間 C で決める。近似で候補を絞ってから並べ替える方式は採らない。
- 性能の目標は 003 の Q16 と同じ（検索1回の合計時間の最大が 3 秒以下。HiGHS の初期化は含めず Node で測る）。実データの必須スキル 3／6／10 個 × 解あり／解なしを、条件をすべて有効にした `expectedDamage` で測り、`design/tech-stack.md` に記録する。CI では測らない。3 秒を超えたら、対策を `open-questions.md` に新しい Q として起票し、007 の着手前に決める。006 はその記録をもって閉じてよい。
- 結果の `score` には期待値を入れる。

## Q37（決定: 2026-10-24）
- 問い: 006 で `effectsByLevel` を埋めるスキルの範囲と、数値の出典。
- 決定: ja の辞書の説明文（`levelDescriptions`）に攻撃力・会心率・会心倍率の数値が明記され、`attack_add`・`attack_mul`・`affinity_add`・`crit_mul`（条件付きを含む）で表せるスキルをすべて埋める。種別（武器・防具・シリーズ・グループ）は問わない。
- 数値の出典はゲーム内の説明文とする（攻略サイトはスクレイピングしない方針のまま）。最終確認はオーナー。
- 説明文に数値が無いもの（例: 連撃・黒蝕竜の力の「上昇する」）、属性・状態異常・オトモに効くものは空のままにする。

## Q38（決定: 2026-10-24）
- 問い: 検索画面の目的関数の選択肢に「火力（期待値）」を足すのを 006 と 007 のどちらで行うか。
- 決定: 007 damage-ui で、発動条件のトグルと一緒に足す。006 は `packages/data` と `packages/solver` だけを触り、単体テストで検証する。

## Q39（決定: 2026-10-24）
- 問い: 発動条件をどこで定義し、ソルバーの要求でどう扱うか。
- 決定: 発動条件は overlay で定義して `MasterBundle` に収め、名前を ja・en の辞書に持たせる（007 のトグルの表示に使う）。条件の単位は効果の発動のきっかけ（例: 有効部位への攻撃・傷口への攻撃・各スキルの「スキル発動中」）とし、同じきっかけは1つの条件にまとめる。
- 条件は二値（発動している／していない）で扱い、発動率は扱わない（`initial-design.md` §8.5 のトグル）。
- `activeConditionIds` の指定が無い、または空のときは、条件付きの効果をすべて無効として計算する。マスターに無い条件 ID を指定した要求は、003 の Q18 と同じく不正な要求としてエラーを返す。
- 条件 ID の形式・overlay の書式・検証規則は区間 C で決め、`design/master-data.md` に反映する。
