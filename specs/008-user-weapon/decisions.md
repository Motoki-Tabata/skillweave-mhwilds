# 008 user-weapon の決定記録

## Q51（決定: 2026-10-26）
- 問い: 個体差のある武器の攻撃力・会心率・属性値を、どう入力させるか。生産ボーナス・復元ボーナスを選ばせて計算するか、最終値を直接入力させるか。
- 決定: ゲーム内の装備画面に出る最終値（攻撃力・会心率・属性の種類と値）を直接入力させる。生産ボーナス・復元ボーナスの内訳は持たず、ボーナスから値を計算しない。
- 理由: MHDB（`output/merged`）にはアーティアの生産ボーナス・復元ボーナスの数値表も巨戟アーティアの武器も無く、計算させるにはオーナーが数値表を overlay に起こす必要がある。最終値の入力なら数値表が要らず、アップデートで表が変わっても壊れない。002 で 008 に委ねた「個体差武器の選択肢」の overlay は、008 では埋めない。

## Q52（決定: 2026-10-26）
- 問い: ソルバーの `SolverWeapon`（`kind: 'custom'`）が要求する基の武器（`baseWeaponId`）を、どこから選ばせるか。
- 決定: マスターのアーティア武器（14 武器種それぞれのアーティアⅠ・Ⅱ。2026.10.4 の版で 28 本）から選ばせる。巨戟アーティアはマスターに無いので、同じ武器種のアーティアⅡを基にして登録する。武器には任意の名前を付けられ、空なら基の武器の名前で表示する。
- 理由: 基の武器は武器種と表示名の手がかりにしか使わず、アーティア以外を基にする必要が無いため。全武器（1188 本）から選ばせると、個体差の無い武器が紛れて選びにくい。

## Q53（決定: 2026-10-26）
- 問い: 個体差のある武器に入力できるスキルとスロットの範囲（構造上の制約）。
- 決定: スキルは付与のシリーズスキル 0〜1 個（マスターのスキルの種別が `series` の `setBonuses`）とグループスキル 0〜1 個（種別が `group`）だけを入力でき、それぞれ武器の1部位として数える（`design/master-data.md`「ゲーム仕様の確認結果」）。武器スキルは入力させない（アーティアは武器スキルを持たないため）。スロットは 0〜3 枠で、各枠は武器用の Lv 1〜3 とする。
- 理由: 対象の巨戟アーティアの付与はシリーズ・グループ各1つで、武器スキルの入力欄を足すと入力画面が広がるだけで使い道が無いため。

## Q54（決定: 2026-10-26）
- 問い: 登録した武器の保存先と、検索での使い方の範囲。
- 決定（保存）: 005 の護石と同じく、端末内の IndexedDB にネイティブの API で保存し、ログインもサーバーへの送信もしない。ID はクライアント採番の UUIDv7。保存する形は 013 user-weapon-save のサーバー側と同じにする（`design/data-model-standard.md`「所有者と監査カラム」）。項目の確定は区間 B で行う。
- 決定（検索）: 検索画面の武器の選択で、マスターの武器と並べて登録した武器を選べるようにし、`SolverRequest` に `kind: 'custom'` の武器として渡す。目的関数 `expectedDamage` と結果の火力の表示（007）にも、入力した攻撃力・会心率を使う。
- 理由: 007 で「個体差のある武器の火力」を 008 に送っており、ソルバーは `custom` の武器の攻撃力・会心率をすでに期待値の計算に使えるため。
