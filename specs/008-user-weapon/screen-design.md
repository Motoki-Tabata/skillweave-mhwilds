## 0. 前提

- 個体差のある武器は、マスターのアーティア武器（28 本）を基にしたものだけを扱う（decisions.md Q52）。ゲストの端末内（IndexedDB）にだけ保存し、サーバーへ送らない（Q54）。
- 攻撃力・会心率・属性は、ゲーム内の装備画面に出る値をそのまま入力させる（Q51）。生産ボーナス・復元ボーナスは扱わない。
- 属性値は、装備画面の表示値（マスターの値の 10 倍。例: マスターで毒 21 の武器は装備画面で 210）を入力させ、保存とソルバーへの受け渡しはマスターと同じ単位（表示値 ÷ 10）にする。属性は火力に反映しない（open-questions.md Q40）。
- 武器スキルは入力させない（Q53）。付与スキルはシリーズスキル 0〜1 個とグループスキル 0〜1 個で、レベルは持たない（武器の1部位として数える）。
- 検索の候補から外す判定（基の武器・付与スキルが現行のマスターに無い）は保存しない。表示のたびに現行のマスターで求める。
- MASTER.md の Layout（ブレークポイント・最大幅）は変えない。新しい画面も、005 の護石画面と同じ3段のブレークポイントに従う。
- 属性の種類の表示名は、`apps/web/src/main/constants/` の定数に持つ（武器種と同じく、004 decisions.md Q25 の前例）。
- 追加する ui 部品は無い（`select`・`combobox`・`input`・`alert-dialog`・`badge` は既存）。

## 2. C1・S1・D1 の変更

### 2.1 ナビの行

```
│  装備検索   護石   個体差のある武器                     │

- リンクを3つにする（「装備検索」→ `/`・「護石」→ `/charms`・「個体差のある武器」→ `/weapons`）。並べ方・高さ・現在地の示し方は MASTER.md の「画面骨格」のまま。

### 2.2 S1 「武器」カード

```
武器
┌──────────────────────────────┐
│ 武器 [必須]                                        │
│ 巨戟ブレイド [個体差]                            > │
│ 大剣 ／ 攻撃力 200 ／ 会心 15% ／ 火属性 300 ／     │

└──────────────────────────────┘

| 状態 | 表示 |
|---|---|
| 通常の武器を選んでいる | 004 のまま |
| 個体差のある武器を選んでいる | 1行目に表示名（太字）と Badge（outline）「個体差」。2行目に「<武器種> ／ 攻撃力 <n> ／ 会心 <n>% ／ <属性> <値> ／ スロット Lv<n>・…」（12px。属性が無ければ属性の項を出さない。スロットが無ければ「スロット なし」）。3行目に「付与スキル: <名前>（シリーズ）・<名前>（グループ）」（12px。付与スキルが無ければ行ごと出さない） |

- 表示名は、名前が空でなければ名前、空なら基の武器の名前（以下、本書で「表示名」と書く）。
- 数値は Inter・`tabular-nums`。属性値は装備画面の表示値（保存した値 × 10）で出す。
- 選んでいる個体差のある武器を S3 で編集したら、カードは編集後の内容を出す（選択は外さない）。
- 選んでいる個体差のある武器を S3 で削除したら、武器の選択を外す（未選択に戻す。武器欄のエラーは、送信するまで出さない）。

### 2.4 S1 検索と結果

- 検索は、送信した時点の個体差のある武器の内容を `SolverRequest` の `kind: 'custom'` の武器として渡す（`baseWeaponId`・`attack`・`affinity`・`element`・`slots`・付与スキルの `setBonusIds`。`skills` は空）。
- 検索条件の要約の武器を「武器: <表示名>（個体差）」にする。結果の構成の武器は全構成で共通なので、武器の名前は要約に出す（構成カードには武器の行を足さない）。
- 構成カードの装飾品の表・空きスロットで、持ち主「武器」の行・チップに、個体差のある武器のスロットの Lv を出す（通常の武器と同じ形）。
- 火力（007 の期待値と内訳）は、個体差のある武器の攻撃力・会心率から求める。目的関数「火力の最大化」も同じ値で解く。
- 発動スキルは、武器の付与スキルを防具のシリーズ／グループスキルと合わせて部位数に数えた結果（ソルバーの結果のまま）を出す。表示の形は 004 のまま。
- 表示する武器の名前・スロット・火力は、検索した時点の内容にする（検索の後に武器を編集・削除しても、表示中の結果は変えない）。

## 3. S3 個体差のある武器の画面

### 3.1 画面構成

基準幅から `lg` 未満は、上から次の順に並べる。`lg` 以上は、左に入力フォーム（400px）、右に一覧を置く（間隔 24px。005 の S2 と同じ）。

1. h1「個体差のある武器」
2. 入力フォームのカード（h2「武器を登録」。編集中は「武器を編集」）
3. 一覧（h2「登録済みの武器（<N>）」）

画面の主要ボタン（差し色の面）は、フォームの「登録」（編集中は「保存」）の1つだけ。

### 3.2 入力フォーム

```
武器を登録
 基の武器 [必須]
 [ アーティアブレイドⅡ                 ▾]
 武器種: 大剣
 名前
 [                                      ]
 空なら基の武器の名前で表示します。30 文字まで。
 攻撃力 [必須]          会心率 [必須]
 [ 200            ]    [ 15           ] %
 属性
 [ 火属性        ▾]    [ 300          ]
 スロット1   [ Lv3                     ▾]
 スロット2   [ Lv3                     ▾]
 スロット3   [ なし                    ▾]
 シリーズスキル
 [ 巨戟龍の黙示録                  ▾][×]
 グループスキル
 [ 護竜の脈動                      ▾][×]
 [        登録        ] [入力を空にする]
```

| 項目 | 部品 | 必須 | 既定 | 入力規則・動作 |
|---|---|---|---|---|
| 基の武器 | Select（ラベル「基の武器」と「必須」バッジ）。選択肢は武器種ごとのグループ（SelectGroup。グループの見出しは武器種の正式名）に、その武器種のアーティア武器の名前を並べる。下に補助テキスト「武器種: <武器種>」（選んだときだけ） | 必須 | 未選択。登録した後は直前の基の武器を残す | グループは武器種の定数の並び順、グループの中はマスターの並び（Ⅰ→Ⅱ）。アーティア武器の見分け方は区間 C で決める |
| 名前 | Input（ラベル「名前」）。下に補助テキスト「空なら基の武器の名前で表示します。30 文字まで。」 | 任意 | 空 | 前後の空白を除いて保存する。30 文字（前後の空白を除いた後の文字数）まで |
| 攻撃力 | Input（ラベル「攻撃力」と「必須」バッジ。`inputmode="numeric"`）。攻撃力と会心率は1行に2つ並べる | 必須 | 空 | 1〜999 の整数。全角の数字は半角に直して読む |
| 会心率 | Input（ラベル「会心率」と「必須」バッジ）と、右に「%」。`inputmode` は指定しない（iOS の数字キーボードに「-」が無いため） | 必須 | 空 | -100〜100 の整数。全角の数字と「－」は半角に直して読む |
| 属性 | 行ごとに、種類の Select（ラベル「属性」）と値の Input（ラベルは画面に出さず `aria-label="属性値"`・`inputmode="numeric"`） | 任意 | 種類は「なし」、値は空 | 種類の選択肢は「なし」と、マスターの武器にある属性の種類（表示名は定数。並びは 火属性・水属性・雷属性・氷属性・龍属性・毒属性・麻痺属性・睡眠属性・爆破属性）。値は装備画面の表示値で、10〜990 の 10 の倍数。種類が「なし」のあいだは値を無効にして空にする |
| スロット1〜3 | 行ごとに Select（ラベル「スロット<i>」）。選択肢「なし」「Lv1」「Lv2」「Lv3」 | 任意 | なし | 武器のスロットなので種別（武器用）は書かない |
| シリーズスキル | Combobox（ラベル「シリーズスキル」）と、空にするボタン（アイコン・44×44px・`aria-label="シリーズスキルを空にする"`） | 任意 | 空 | 候補はマスターのスキルの種別が `series` のシリーズスキルだけ。検索の規則は 005 の 2.4（名前と読み）。入力が空のときはすべてを名前の順に出す。入力があるときは候補の下に「「<語>」を含むシリーズスキル: <N> 件（名前と読み）」。0件のときは「該当するシリーズスキルがありません。名前か読みを変えてください。」 |
| グループスキル | シリーズスキルと同じ形（ラベル「グループスキル」・`aria-label="グループスキルを空にする"`） | 任意 | 空 | 候補は種別が `group` のグループスキルだけ。補助の行の文言は「シリーズスキル」を「グループスキル」に替える |

構造上の制約のエラー（Q53。項目の直下に `--destructive` の文字で出す。Select は変更した時点、Input と Combobox はフォーカスを外した時点と送信時に検証する）:

| 条件 | 出す場所 | 文言 |
|---|---|---|
| 基の武器が未選択で送信した | 基の武器の直下 | 「基の武器を選んでください。」 |
| 基の武器が現行のマスターのアーティア武器に無い（編集で読み込んだ武器） | 基の武器の直下 | 「この基の武器は現行のマスターにありません。選び直してください。」 |
| 名前が 30 文字を超える | 名前の直下 | 「名前は 30 文字以内で入力してください。」 |
| 攻撃力が空 | 攻撃力の直下 | 「攻撃力を入力してください。」 |
| 攻撃力が整数でない・範囲外 | 攻撃力の直下 | 「攻撃力は 1〜999 の整数で入力してください。」 |
| 会心率が空 | 会心率の直下 | 「会心率を入力してください。」 |
| 会心率が整数でない・範囲外 | 会心率の直下 | 「会心率は -100〜100 の整数で入力してください。」 |
| 属性の種類を選んだのに値が空 | 属性の行の直下 | 「属性値を入力してください。」 |
| 属性値が 10 の倍数でない・範囲外 | 属性の行の直下 | 「属性値は 10〜990 の 10 の倍数で入力してください。」 |
| 空のスロットの下にスロットがある | 空の行の直下 | 「スロット<i>が「なし」です。スロットは上の行から順に入力してください。」 |
| Combobox に文字があるのに候補を選んでいない | その行の直下 | 「候補からシリーズスキルを選んでください。」（グループは「グループスキル」） |
| 付与スキルが現行のマスターに無い（編集で読み込んだ武器） | その行の直下 | 「このシリーズスキルは現行のマスターにありません。別のスキルを選ぶか空にしてください。」（グループは「グループスキル」） |

- 構造上の制約に反するあいだは保存しない。送信したときは、最初の不正な項目にフォーカスを移す。
- 付与スキルの種別違い・個数の超過は、フォームでは起きない（候補を種別で分け、欄を1つずつにしているため）。保存と読み込みの検証の関数（4 節）では検査する。

操作:

| モード | ボタン | 動作 |
|---|---|---|
| 登録 | 「登録」（primary）・「入力を空にする」（outline） | 「登録」で新しい UUIDv7 を振って保存する。保存中は「保存中…」で無効にする。保存したらトースト「個体差のある武器を登録しました。」を出し、基の武器を残して他を既定に戻し、名前にフォーカスを移す。「入力を空にする」は基の武器も含めて既定に戻す |
| 編集 | 「保存」（primary）・「キャンセル」（outline） | 一覧の「編集」でその武器をフォームに読み込む。「保存」で同じ ID のまま上書きし、トースト「個体差のある武器を保存しました。」を出して登録のモードに戻り、フォーカスを一覧のその武器の「編集」に戻す。「キャンセル」は変更を捨てて登録のモードに戻り、フォーカスを同じ「編集」に戻す |

- Combobox で Enter を押したときは候補を選ぶだけで、送信しない。
- IndexedDB を開けないあいだは、フォーム全体を無効にし、フォームの先頭に「端末に保存できないため、個体差のある武器を登録できません。」を出す（原因は一覧の側に出す。3.4）。

### 3.8 キーボード・フォーカス・読み上げ

- Tab の順: 基の武器 → 名前 → 攻撃力 → 会心率 → 属性の種類 → 属性値 → スロット1〜3 → シリーズスキル・空にする → グループスキル・空にする →「登録」→「入力を空にする」→ 一覧。
- Combobox は、文字の入力で絞り込み、上下の矢印キーで候補を移り、Enter で選び、Esc で閉じる（005 と同じ）。
- 構造のエラーは、項目に `aria-invalid` と `aria-describedby` で関連づける。補助テキスト（名前の説明・武器種）も `aria-describedby` で関連づける。

## 4. 端末に保存する武器の形（IndexedDB）

013 user-weapon-save のサーバー側と同じ形にする（Q54・`design/data-model-standard.md`「所有者と監査カラム」）。サーバーだけが付ける `userId`・`version`・`deletedAt` は、端末では持たない。

| 項目 | 型 | 内容 |
|---|---|---|
| `id` | string | UUIDv7（クライアント採番）。キー |
| `payload` | object | 下の表 |
| `schemaVersion` | number | `payload` の形の版。008 は 1 |
| `createdAt` | string | 登録した日時（UTC の ISO 8601） |
| `updatedAt` | string | 最後に保存した日時（UTC の ISO 8601） |

`payload`:

| 項目 | 型 | 内容 |
|---|---|---|
| `baseWeaponId` | WeaponId | 基の武器（マスターのアーティア武器） |
| `name` | string | 前後の空白を除いた名前。空文字を許す（表示は基の武器の名前） |
| `attack` | number | 1〜999 の整数 |
| `affinity` | number | -100〜100 の整数 |
| `element` | `{ type: string, value: number }` か無し | `type` は MHDB の属性の種類（`fire`・`water`・`thunder`・`ice`・`dragon`・`poison`・`paralysis`・`sleep`・`blastblight`）。`value` はマスターと同じ単位（装備画面の表示値 ÷ 10）で 1〜99 の整数 |
| `slots` | Slot[] | 0〜3 個。`target` は常に `weapon`、`level` は 1〜3。並びはゲーム内の表示順 |
| `seriesBonusId` | SetBonusId か null | 付与のシリーズスキル（マスターのスキルの種別が `series` の `setBonuses` の ID） |
| `groupBonusId` | SetBonusId か null | 付与のグループスキル（種別が `group`） |

- `SolverWeapon`（`kind: 'custom'`）へは、`id`・`baseWeaponId`・`attack`・`affinity`・`element`・`slots` をそのまま写し、`setBonusIds` は `seriesBonusId`・`groupBonusId` のうち null でないものをこの順に並べ、`skills` は空にする（変換は `apps/web` のアダプタが行う）。
- 付与スキルをシリーズとグループで別の項目に持つのは、現行のマスターに無い ID でも、どちらの欄の値かを失わずに一覧とフォームへ出すため。
- 生産ボーナス・復元ボーナスは持たない（Q51）。`temp/initial-design.md` §5 の `user_weapons` の説明にある「復元ボーナス」は、013 でもこの決定に合わせる。
- 構造の検証の関数は、保存の前と読み込みの後の両方で、この表の範囲・付与スキルの種別（`seriesBonusId` が `series`、`groupBonusId` が `group`）を検査する。現行のマスターに無い ID は、構造のエラーではなく「検索対象外」として扱う（3.3）。
- データベースの名前・ストアの名前・版の上げ方は区間 C で決める（005 の `swv` データベースにストアを足すかを含む）。
- 削除は端末から消す（物理削除）。同期は扱わないため（009・013）。
