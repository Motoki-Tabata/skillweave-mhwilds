# 008: user-weapon

## 目的 / ユーザーストーリー
プレイヤー（ログインしていないゲスト）として、巨戟アーティアなど個体ごとに性能が違う手持ちの武器を、ゲーム内の装備画面に出る値のまま手で入力して端末に保存し、その武器を固定した構成と火力を検索で確かめたい。004 の検索はマスターの武器しか選べず、007 の火力も個体差のある武器では計算できなかったため、ソルバーがすでに受け付ける個体差のある武器（`SolverWeapon` の `kind: 'custom'`）を画面から使えるようにする。

用語:
- 個体差のある武器: 基の武器・攻撃力・会心率・属性・スロット・付与スキルを個体ごとに持つ武器。008 ではアーティア武器を基にしたものだけを扱う（decisions.md Q52）。
- 基の武器: マスターのアーティア武器（14 武器種それぞれのアーティアⅠ・Ⅱ）。武器種と既定の表示名に使う。巨戟アーティアは同じ武器種のアーティアⅡを基にする（decisions.md Q52）。
- 付与スキル: 武器に付いたシリーズスキル（0〜1 個）とグループスキル（0〜1 個）。それぞれ武器の1部位として数える（decisions.md Q53）。

## 受入基準（EARS記法）
- THE system SHALL ログインなしで、基の武器（アーティア武器から選ぶ）、任意の名前、攻撃力（1 以上の整数）、会心率（整数の %）、属性（なし、またはマスターの武器にある属性の種類と 1 以上の整数の値）、スロット（0〜3 枠。各枠が武器用の Lv 1〜3）、付与スキル（シリーズスキル 0〜1 個とグループスキル 0〜1 個）を入力して、個体差のある武器を登録できなければならない（decisions.md Q51・Q52・Q53）。
- THE system SHALL 付与スキルを、マスターのスキルの種別が `series` のシリーズスキルと `group` のグループスキルからそれぞれ名前で選ばせ、武器スキルと防具スキルを入力させてはならない（decisions.md Q53）。
- WHEN 個体差のある武器を登録・編集・削除したとき THE system SHALL それを端末内の IndexedDB に保存し、再読み込みの後も一覧に残さなければならず、武器をサーバーへ送ってはならない。新しい武器の ID はクライアントで採番した UUIDv7 とし、保存する形は 013 user-weapon-save のサーバー側と同じにしなければならない（decisions.md Q54）。
- THE system SHALL 登録した武器を一覧で、名前（空なら基の武器の名前）・武器種・攻撃力・会心率・属性・スロット・付与スキルとともに表示し、それぞれを編集・削除できるようにしなければならない。
- IF 入力した武器が構造上の制約（基の武器がアーティア武器でない・攻撃力や会心率や属性値の範囲外・スロットの枠数や Lv の範囲外・付与スキルの種別違いや個数の超過）に反するとき THEN システムは、保存を拒否し、どの項目が反するかを示さなければならない（decisions.md Q53）。
- WHEN 検索画面で武器を選ぶとき THE system SHALL マスターの武器と並べて、登録した個体差のある武器を選べるようにしなければならない（decisions.md Q54）。
- WHEN 個体差のある武器を選んで検索したとき THE system SHALL その武器を `kind: 'custom'` の `SolverWeapon`（基の武器の ID・攻撃力・会心率・属性・スロット・付与スキルのシリーズ／グループの ID）として `SolverRequest` に渡し、武器スキルは空にしなければならない（decisions.md Q54）。
- WHEN 個体差のある武器で検索したとき THE system SHALL 結果の構成に、その武器の名前・スロットに付けた装飾品を表示し、火力（007 の期待値と内訳）を入力した攻撃力と会心率から計算して表示しなければならない。目的関数「火力の最大化」も同じ値で解かなければならない（decisions.md Q54）。
- WHEN 個体差のある武器で検索したとき THE system SHALL その武器の付与スキルを、防具のシリーズ／グループスキルと合わせて部位数に数えた発動スキルを結果に表示しなければならない（decisions.md Q53）。
- IF 登録した武器の基の武器・付与スキルが現行のマスターに無いとき THEN システムは、その武器を検索画面の選択肢から外し、一覧にその旨を示さなければならない。
- IF 検索条件で選んでいる個体差のある武器を削除したとき THEN システムは、検索条件の武器の選択を外さなければならない。
- IF IndexedDB を開けない、または書き込みに失敗したとき THEN システムは、武器を保存できないことと原因を表示し、マスターの武器での検索は引き続き使えるようにしなければならない。
- THE system SHALL ヘッダーから個体差のある武器の一覧の画面へ移れるようにしなければならない。
- THE system SHALL Playwright（Chromium）の e2e テストで、「個体差のある武器を登録し、再読み込みの後も一覧に残り、その武器を選んで検索すると、付与スキルを数えた構成と火力が表示される」流れと、構造上の制約に反する武器の保存が拒否されることを検証しなければならない。

## スコープ外
- 生産ボーナス・復元ボーナスの入力と、ボーナスから攻撃力・会心率を計算すること。002 で 008 に委ねた「個体差武器の選択肢」の overlay は埋めない（decisions.md Q51）
- アーティア武器以外を基にした個体差のある武器と、巨戟アーティアの武器をマスターに足すこと（decisions.md Q52）
- 武器スキルの入力（decisions.md Q53）
- 武器のサーバーへの保存・同期と、ログイン後のゲスト下書きの取り込み（009・013）
- 斬れ味・属性の火力への反映（属性の期待値は open-questions.md Q40。斬れ味はソルバーが扱わない）
- 武器の一覧の並べ替え・絞り込みと、ファイルへの書き出し・読み込み
- 検索条件と結果の端末への保存（004 decisions.md Q23 のまま）
- 画面の英語対応（004 decisions.md Q4 のまま）

## 契約差分
- なし（API を持たない。武器は端末内の IndexedDB に保存し、ソルバーはブラウザの Worker で動く）
