# 009 discord-login の決定記録

## Q5（決定: 2026-10-27）
- 問い: デプロイ（Web: Cloudflare Pages / API: Cloud Run / DB: Neon または Supabase）を TSOD の機能として切るか、区間外の運用作業とするか。フレンドに使ってもらう時期と、独自ドメイン（Cookie の同一サイト化）・マネージド DB の未決事項（§11）にも関わる（仮: 機能にはしない。004 solver-ui の後に Web だけ区間外で先に公開し、API・DB の公開は 009 discord-login の ship の前に区間外で行う）
- 決定: デプロイは機能にせず、区間外の運用作業とする。009 はローカル（Vite の proxy で Web と API を同一オリジンに見せた環境）で完結させ、ship は API・DB の公開を待たない。API・DB の公開と独自ドメインの決定は、保存機能（010 以降）をフレンドに使ってもらう前に区間外で行う。
- 理由: 独自ドメイン（Cookie の同一サイト化の前提）が未決のまま 009 の ship を公開に結び付けると、009 が区間外の作業待ちで止まる。009 だけではログインしてもできることが増えず、公開を急ぐ理由が無い。

## Q55（決定: 2026-10-27）
- 問い: Discord から得るユーザー情報のうち、何をサーバーに保持し、画面に何を出すか。
- 決定: Discord に求めるスコープは `identify` だけとし、メールアドレスは取らない。DB の `users` には Discord のユーザー ID（と内部の ID・監査日時）だけを持つ。表示名はログインのときに Discord から得た値をセッションにだけ持ち、ヘッダーに出す。アバター画像は出さない。
- 理由: 保持する個人情報を最小にするため。表示名は Discord 側で変わりうるので、DB に写すと同期の責務が生じる。アバターを出すと外部（Discord の CDN）からの画像の読み込みが増える。

## Q56（決定: 2026-10-27）
- 問い: ログインの持続（セッションの有効期間）。
- 決定: ブラウザを閉じてもログインを保ち、最後の利用から 30 日使わなければ切れるようにする（セッション Cookie に有効期限を付け、Spring Session のタイムアウトも同じ長さにする）。
- 理由: フレンド向けの道具で、開くたびに Discord の認可をやり直させると手間になるため。値は設定キーで持ち、後から変えられるようにする。

## Q57（決定: 2026-10-27）
- 問い: ログイン・ログアウトの後、どの画面に戻すか。
- 決定: ログインの後は、ログインを押した画面に戻す。戻り先は Web 側で覚え、API はログインの成功・失敗のどちらでも Web のトップへ固定でリダイレクトする（任意の URL へのリダイレクトを API に持たせない）。ログアウトは画面を移らず、その場に留まる。
- 理由: 護石・武器の画面からログインしたときに検索画面へ飛ばされないようにするため。戻り先を API のパラメータにすると、オープンリダイレクトの検査が要る。
