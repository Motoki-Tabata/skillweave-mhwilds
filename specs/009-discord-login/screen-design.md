## 0. 前提

- 認証の部品は、ヘッダーの右端の「ログインの導線の場所」（MASTER.md の「画面骨格」。今の `AppHeader.vue` の `data-slot="header-auth"`）に置く。テーマの切り替えはその左のまま。ログイン状態による出し分けはこの1か所に集約し、検索・護石・武器の画面には判定を置かない。
- 認証状態は、Web の起動のときに `GET /api/auth/me` を1回呼んで決める。200 ならログイン中、401 なら未ログイン、それ以外（API に届かない・401 以外のエラー・応答の形の不正）は「取得できない」として扱う。画面の切り替えのたびには呼び直さない。
- 表示名は Discord の `global_name`（無ければ `username`）で、`GET /api/auth/me` の `displayName` をそのまま出す。アバター画像は出さない（decisions.md Q55）。
- Discord のロゴは使わない。アイコンは lucide に統一する（MASTER.md の Anti-Patterns）。
- ログインはページを離れて Discord の認可画面へ移るため、検索条件など端末に保存していない入力は、戻ったときに残らない。009 では離れる前の確認を出さない（受入基準に無く、護石・武器は IndexedDB に保存済みのため）。
- 追加する ui 部品: `dropdown-menu`（基準幅のアカウントのメニュー。区間 D でメインが shadcn-vue の CLI で足す）。

## 2. C1 ヘッダーの認証の部品

### 2.1 画面構成

`md`（768px〜）以上:

```
未ログイン
│ SkillWeave [非公式の二次創作]                  [☀] [→ Discord でログイン] │
ログイン中
│ SkillWeave [非公式の二次創作]          [☀] 👤 モンハン太郎  [⎋ ログアウト] │
```

基準幅（〜767px）:

```
未ログイン                                   ログイン中
│ SkillWeave [非公式の二次創作] [☀] [→] │   │ SkillWeave [非公式の二次創作] [☀] [👤] │
                                                                     ▼ 押すと M1
```

### 2.2 部品と項目定義

| 状態 | 幅 | 部品 | 内容 |
|---|---|---|---|
| 未ログイン | `md` 以上 | ログインのリンク（見た目は outline のボタン・高さ 40px） | lucide の `LogIn`（16px・`aria-hidden`）と「Discord でログイン」（14px・500）。`href` は `/api/oauth2/authorization/discord` |
| 未ログイン | 基準幅 | ログインのリンク（見た目は ghost のアイコンボタン・44×44px） | lucide の `LogIn`（20px）。`aria-label` と `title` は「Discord でログイン」。`href` は同上 |
| ログイン中 | `md` 以上 | 表示名 | lucide の `User`（16px・`--muted-foreground`・`aria-hidden`）と表示名（14px・400・`--foreground`）。表示名は最大幅 240px で1行に切り詰め、末尾を「…」にする。`title` に表示名の全文を持つ。読み上げ用に、表示名の前に視覚的に隠した「ログイン中: 」を置く |
| ログイン中 | `md` 以上 | ログアウトのボタン（outline・高さ 40px） | lucide の `LogOut`（16px・`aria-hidden`）と「ログアウト」（14px・500） |
| ログイン中 | 基準幅 | アカウントのボタン（ghost のアイコンボタン・44×44px） | lucide の `CircleUser`（20px）。`aria-label` は「アカウント（<表示名>）」、`title` は表示名。押すと M1 を開く |
| 判定中・取得できない | すべて | なし | 部品を出さない（場所の幅も取らない）。テーマの切り替えが右端に来る |

- ヘッダーの主要ボタン（橙の面）は使わない。各画面の主要ボタン（「検索」「登録」）と数が重ならないようにするため。
- ログインのリンクは `<a>` にする（ページを移る操作のため）。押したとき、移る前に戻り先（2.4）を覚える。
- サイト名・バッジ・テーマの切り替え・認証の部品は縮めない（`shrink-0`）。表示名だけが切り詰めの対象。

### 2.3 M1 アカウントのメニュー（基準幅のログイン中だけ）

```
                    ┌────────────────────┐
                    │ ログイン中              │ 12px・--muted-foreground
                    │ モンハン太郎            │ 14px・500
                    │──────────────────│
                    │ ⎋ ログアウト            │ 高さ 44px
                    └────────────────────┘
```

- `dropdown-menu`。アカウントのボタンの下、右端にそろえて開く。幅は 240px（画面の幅から左右 16px を引いた幅を超えない）。面は `--popover`、枠は `--border` の 1px、角丸 4px、影は付けない。
- 上段はラベル（選べない）。「ログイン中」（12px・`--muted-foreground`）の下に表示名（14px・500）。表示名は折り返して全文を出す（長い英数字は `break-all`）。
- 区切り線の下に、項目「ログアウト」（lucide の `LogOut` と文言・高さ 44px）。
- キーボード: Enter・Space・↓ で開き、最初の項目「ログアウト」にフォーカスする。Esc で閉じてアカウントのボタンへフォーカスを戻す（Reka UI の既定のまま）。

### 2.4 状態と遷移

| 状態 | 表示 | 次の状態 |
|---|---|---|
| 判定中（`GET /api/auth/me` の応答待ち） | 部品を出さない（MASTER.md の States「300ms 未満の読込中」）。スケルトンも出さない | 応答に応じて下の3つのどれか |
| 未ログイン（401） | ログインのリンク | 押すと Discord の認可画面へ移る |
| ログイン中（200） | 表示名とログアウト（基準幅はアカウントのボタン） | ログアウトを押すとログアウト中 |
| 取得できない | 部品を出さない。トーストもインラインの表示も出さない。検索・護石・武器の画面はそのまま使える | 再読み込みまで変えない |
| ログアウト中 | `md` 以上: ログアウトのボタンを無効にし、アイコンを lucide の `Loader2`（回転）に替える。文言は「ログアウト」のまま。基準幅: メニューを閉じ、アカウントのボタンを無効にしてアイコンを `Loader2` に替える | 成功・失敗 |
| ログアウトの成功（204、または 401 = 既に切れていた） | 未ログインの表示に戻す。画面は移らない。トースト「ログアウトしました」。フォーカスはログインのリンクへ移す（押したボタンが消えるため） | 未ログイン |
| ログアウトの失敗（API に届かない・403・5xx など） | ログイン中の表示のまま、ボタンを有効に戻す。トースト（`--destructive`）「ログアウトできませんでした。通信の状態を確かめて、もう一度「ログアウト」を押してください。」 | ログイン中 |

ログインからの戻り:

- ログインのリンクを押したとき、Web は `sessionStorage` の `swv-login-return` に、今の画面の `fullPath` を書いてから移る。`sessionStorage` が使えないときは書かずに移る（エラーは出さない）。
- Web の起動のとき、`swv-login-return` があれば読んで消し、`GET /api/auth/me` の結果で次のように振る舞う。戻り先は、`/` で始まり `//` で始まらず、ルートに一致するパスだけを使い、それ以外は `/` にする（端末の値を信じない）。

| 戻り先の記録 | `GET /api/auth/me` | 表示 |
|---|---|---|
| あり | 200 | 戻り先へ `router.replace` する。トースト「Discord でログインしました」 |
| あり | 401 | 戻り先へ `router.replace` する。トースト（`--destructive`）「Discord でログインできませんでした。もう一度「Discord でログイン」を押してください。」 |
| あり | 取得できない | 戻り先へ `router.replace` する。トーストは出さない（受入基準「認証状態を取得できないときはエラーを通知しない」） |
| なし | どれでも | 戻り先の処理をしない（通常の起動。トーストも出さない） |

- `sessionStorage` が使えずに戻ったときは、Web のトップ（`/`）に留まる。成功ならヘッダーに表示名が出る。失敗はトーストを出せない（記録が無く、ログインからの戻りと判別できないため）。
- 戻り先へ移るまでの間（`GET /api/auth/me` の応答待ち）に、トップの検索画面が一瞬出てよい（`/` から戻り先への `replace` のため）。

### 2.6 キーボード・フォーカス・読み上げ

- Tab の順は、サイト名の後ろのテーマの切り替え → 認証の部品（ログインのリンク、または表示名を飛ばしてログアウトのボタン／アカウントのボタン）→ ナビのリンク。表示名はフォーカスを持たない。
- フォーカスリングは MASTER.md の Buttons のまま（`--ring` の 2px）。
- 認証状態が決まって部品が現れても、フォーカスは動かさない。
- トーストは既存の `AppToaster`（Reka UI の Toast）で出す。読み上げは Toast の既定のまま。

## 3. 受入基準との対応

| 受入基準 | 対応する箇所 |
|---|---|
| 未ログインで「Discord でログイン」を押すと Discord の認可画面へ移る（スコープは `identify` だけ） | 2.2 のログインのリンク（スコープは API の設定。区間 C） |
| 初回はユーザーを作り、2回目以降は同じユーザーでセッションを確立する。メール・表示名を DB に保存しない | 画面の変更なし（API とテーブル設計） |
| ログインの後、押した画面へ戻す。API は Web のトップへ固定でリダイレクトする | 1 の遷移、2.4 の「ログインからの戻り」 |
| 認可の拒否・失敗でセッションを確立せず、ログインできなかったことを表示する | 2.4 の「ログインからの戻り」の 401 の行 |
| ログイン中はヘッダーに表示名と「ログアウト」を出し、アバターを出さない | 2.2（`md` 以上はヘッダーに直接、基準幅は M1） |
| ログアウトでセッションを無効にし、ヘッダーを未ログインに戻し、その場に留まる | 2.4 のログアウト中・成功 |
| CSRF トークンの無いログアウトを拒否する | 2.4 のログアウトの失敗（403 も失敗として扱う。拒否そのものは API） |
| Spring Session JDBC・再起動でもログインを保つ | 画面の変更なし |
| Cookie の属性・30 日 | 画面の変更なし |
| 未ログインの `GET /api/auth/me` は 401 を返し、リダイレクトしない | 0 の認証状態の決め方（401 を未ログインとして扱う） |
| 認証状態を取得できないとき、ログインの導線を出さず、エラーを通知せず、ゲストの機能を使える | 2.2 の「判定中・取得できない」、2.4 の「取得できない」 |
| ログインしなくても検索・護石・武器を使え、端末内の護石・武器をサーバーへ送らない | 0（出し分けはヘッダーの1か所だけ。他の画面は変えない） |
| Discord のクライアント ID とシークレットを環境変数から読む | 画面の変更なし |
| API のテスト | 画面の変更なし |
| e2e（未ログインの導線・ログイン中の表示名とログアウト・取得できないときのゲストの機能） | e2e は既定の幅（`md` 以上）で、本書の文言（「Discord でログイン」「ログアウト」「ログアウトしました」）と `aria-label` で要素を操作する |

## 4. MASTER.md に足す内容（区間 D でメインが書く）

- Layout の「画面骨格」: ログインの導線の場所の中身を書く。`md` 以上は「Discord でログイン」のリンク（outline）／表示名（最大幅 240px で切り詰め）と「ログアウト」（outline）。基準幅は 44×44px のアイコンだけにし、ログイン中はアカウントのメニュー（`dropdown-menu`）に表示名と「ログアウト」を出す。認証状態を取得できないときは何も出さない。
- Component Specs に「アカウントのメニュー」を足す（2.3 の面・幅・項目の高さ）。
- UI Copy の用語: 「Discord でログイン」「ログアウト」「ログイン中」。
