## 0. 前提

- 護石の保存先は、認証状態（009 の `GET /api/auth/me` の結果）で決める。ログイン中はアカウント（サーバー）、未ログインと「取得できない」は端末内（IndexedDB）。両方を混ぜて表示・検索しない（decisions.md Q58）。
- 保存先の切り替えは、護石の一覧を持つ1か所（今の `stores/charms.ts`）に集約する。画面（S1・S2）は、保存先の種類を表示に使うだけで、どちらから読むかを判定しない。
- 認証状態の判定中は、護石の一覧も読み込まない（読込中のまま待つ）。判定の結果を待たずに端末内の護石を出して、あとからアカウントの護石に差し替えることはしない（一瞬だけ別の一覧が出るのを避ける）。
- 入力フォーム・照合・候補の判定・一覧の行の表示は、005 のまま変えない（AC-2）。
- ログインはページを離れて戻るため、ログインしたときの切り替えは起動のときの判定で済む。ページを離れずに保存先が変わるのは、ログアウトと、護石の API の 401（ログインの期限切れ）の2つだけ。
- 書き込みはオンラインのときだけ行い、失敗した要求を後で送り直さない（Q60）。
- 追加する ui 部品は無い（既存の `alert`・`alert-dialog`・Toast で足りる）。

### 2.5 競合・期限切れ・保存先の切り替え

| 事象 | 条件 | 一覧 | フォーム | 知らせ方 |
|---|---|---|---|---|
| 別の端末で変更されていた | 更新が 409 | サーバーから読み直す | 登録のモードに戻し、入力を捨てる。読み直しが終わったら、フォーカスをその護石の「編集」に移す（無ければ一覧の見出し） | トースト（`--destructive`）「この護石は別の端末で変更されていたため、保存しませんでした。一覧を読み直しました。内容を確かめて、もう一度編集してください。」 |
| 別の端末で削除されていた | 更新が 404 | サーバーから読み直す | 登録のモードに戻し、入力を捨てる。読み直しが終わったら、フォーカスを一覧の見出しに移す | トースト（`--destructive`）「この護石は別の端末で削除されていたため、保存しませんでした。一覧を読み直しました。」 |
| ログインの期限切れ | 護石の API（一覧・作成・更新・削除のどれか）が 401 | 端末内の護石に切り替える（005 の読み込み）。保存先の表示を「この端末」にし、帯を消す | 編集のモードなら登録のモードに戻し、入力を捨てる。登録のモードなら入力を残す（保存はしていない）。フォーカスは、押したボタンが残っていればそのまま、消えていれば一覧の見出しに移す | トースト（`--destructive`）「ログインの有効期限が切れたため、保存しませんでした。端末内の護石に切り替えました。アカウントに保存するには、もう一度「Discord でログイン」を押してください。」（一覧の読み込みでの 401 のときは「ログインの有効期限が切れました。端末内の護石に切り替えました。もう一度「Discord でログイン」を押すと、アカウントの護石を使えます。」）。ヘッダーは 009 の未ログインの表示に戻す |
| ログアウト | 009 のログアウトの成功 | 端末内の護石に切り替える。保存先の表示を「この端末」にし、帯を消す | 編集のモードなら登録のモードに戻し、入力を捨てる。登録のモードなら入力を残す | 009 のトースト「ログアウトしました」だけ（護石の側からは足さない） |

- 読み直し（409・404）が失敗したら、2.4 の「アカウントの護石の読込失敗」にする。
- 読み直しの間は、一覧を 005 の読込中の扱いにする（300ms 未満は何も出さない）。
- 保存中・削除中に保存先が変わった（ログアウト・別の要求の 401）ときは、その要求の応答を一覧に反映せず、トーストも出さない。
- 401 のトーストは、同時に複数の要求が 401 になっても1回だけ出す。
- 404 を受けた護石は、読み直した一覧に無いため、編集の対象から外れる。登録し直したいときは、ユーザーが改めて入力する（入力は残さない。別の端末で消した護石を、気づかずに作り直さないため）。

### 2.6 原因の文言（アカウントの保存先）

| 原因 | 文言 |
|---|---|
| API に届かない（通信の失敗） | 「サーバーに接続できませんでした。」 |
| 400・403・5xx・応答の形の不正など、それ以外 | 「サーバーで処理できませんでした。」 |

- 端末内の保存先の原因の文言は、005 の 3.4 のまま。
- 400（構造の制約の違反）は、フォームの検証（005）を通った入力では起きない想定のため、項目の直下には出さず、上の「それ以外」として扱う。

## 5. MASTER.md に足す内容（区間 D でメインが書く）

- Component Specs に「保存先の表示」を足す: 見出しの直下の1行（アイコン 16px・`--muted-foreground` と文言 14px・400）。カード・Badge・背景は付けない。ログイン中は `Cloud`「保存先: アカウント」、それ以外は `Smartphone`「保存先: この端末」。
- Component Specs に「端末内に残るデータの帯」を足す: ログイン中に、端末内に残るデータの件数を情報の Alert（見出しなし・閉じるボタンなし）で知らせる。中身は表示しない。数えられないときは出さない。
- UI Copy の用語: 保存先は「アカウント」「この端末」と書く。
