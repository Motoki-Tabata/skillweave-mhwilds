## 0. 前提

- 構成の保存・一覧・開く・名前の変更・削除は、ログイン中だけ使える。未ログインと「取得できない」（009 の 0 節）は、どちらもログインを促す（AC-2・Q65）。端末内には構成を保存しない。
- 認証状態の判定中は、保存した構成の一覧も読み込まず、ログインを促す表示も出さない（読込中のまま待つ。一瞬だけ別の表示が出るのを避ける。010 の 0 節と同じ）。
- 保存した構成の一覧は、`GET /api/builds` で全件を読む。開く画面（S5）も、この一覧から ID で引く（1件を取得する API は無い。Q66）。
- 開いた構成は閲覧だけ。発動条件の切り替え・中身の上書き・再計算はしない（Q63）。
- 書き込みはオンラインのときだけ行い、失敗した要求を後で送り直さない（Q69）。
- ログインはページを離れて戻る（009）。検索画面でログインすると、いまの検索結果は消える（検索結果は保存していないため）。このことをログインを促す表示で先に知らせる。
- 追加する ui 部品は無い（既存の `card`・`button`・`badge`・`dialog`・`alert-dialog`・`input`・`label`・`skeleton`・`alert`・Toast で足りる）。

### 6.2 D7 名前を変更

| 部品 | 内容 |

| 結果 | S4 | S5 | 知らせ方 |

### 6.4 ログインの期限切れ・ログアウト

| 事象 | 条件 | 表示 | 知らせ方 |
|---|---|---|---|
| ログインの期限切れ | 構成の API（一覧・作成・名前の変更・削除のどれか）が 401 | 開いているダイアログを閉じ、S4・S5 は 6.1 に替える。S1 のカードの「保存」は元のまま | トースト（`--destructive`）「ログインの有効期限が切れました。もう一度「Discord でログイン」を押すと、保存した構成を使えます。」（S1 の保存のときは 3.3 の文言）。ヘッダーは 009 の未ログインの表示に戻す |
| ログアウト | 009 のログアウトの成功 | 開いているダイアログを閉じ、S4・S5 は 6.1 に替える | 009 のトースト「ログアウトしました」だけ（構成の側からは足さない） |

- 401 のトーストは、同時に複数の要求が 401 になっても1回だけ出す。
- 保存中・名前の変更中・削除中にログイン中でなくなったときは、その要求の応答を画面に反映せず、トーストも出さない。

### 6.5 現在のマスターに無い ID（AC-5・Q67）

マスターの版が違う構成では、保存した ID が現在のマスターに無いことがある。画面は壊さず、次のように出す。

| 対象 | 表示 |
|---|---|
| 防具 | 名前の列に「不明な防具（<ID>）」、防御力の列に「−」。防御力の合計には数えない |
| 装飾品 | 「不明な装飾品（<ID>）」 |
| スキル（発動スキル・護石のスキル） | チップに「不明なスキル（<ID>） Lv<n>」。発動スキルでは、種類が分からないため、種類の行の最後に「不明」の行を足してそこに並べる。スキルの効果の一覧には出さない |
| マスターの武器 | 「不明な武器（<ID>）」。武器のスロットは「−」（装飾品の持ち主の行・空きスロットのレベル）。火力は計算できないため、火力の節に「武器が現在のマスターに無いため、火力を計算できません。」（14px）を出し、見出しの行の期待値は出さない |
| 発動条件 | 「不明な発動条件（<ID>）」 |

- 火力の計算では、引けないスキル・発動条件を除いて計算する。
- `<ID>` は保存した文字列のまま（Inter にしない）。色は変えない（`--foreground`）。

### 6.6 原因の文言

| 原因 | 文言 |
|---|---|
| API に届かない（通信の失敗） | 「サーバーに接続できませんでした。」 |
| 400・403・409（作成の ID の衝突）・5xx・応答の形の不正など、それ以外 | 「サーバーで処理できませんでした。」 |

- 400（構造の制約の違反）は、画面の検証を通った入力では起きない想定のため、入力欄の直下には出さず、上の「それ以外」として扱う（010 と同じ）。

### 6.7 キーボード・フォーカス・読み上げ

- Tab の順: S4 は h1 → 各カード（名前のリンク → 「名前を変更」→「削除」）。S5 は「保存した構成の一覧へ」→「名前を変更」→「削除」→ 構成のカードの中（「スキルの効果を表示」）。
- ダイアログは、閉じたらフォーカスを開いたボタンへ戻す（6.2・6.3 の表の行き先が優先）。
- トーストは既存の `AppToaster`。読み上げは Toast の既定のまま。

## 8. MASTER.md に足す内容（区間 D でメインが書く）

- Layout の「画面骨格」のナビゲーション: 基準幅でリンクが1行に収まらないときは、ナビゲーションの行だけを横にスクロールさせ（リンクは折り返さない・スクロールバーは隠さない）、画面を移ったら今の画面のリンクを見える範囲に入れる。
- Component Specs に「保存した構成の一覧の行」を足す: カード（全体はリンクにしない）に、名前のリンク（16px・700）・補助の行（12px）・状態の Badge・最下段に右揃えの操作のボタン。
- Component Specs に「ログインが必要の表示」を足す: 一覧の位置に、見出し・本文・「Discord でログイン」（primary のリンク）のカード。ログインを要する画面の未ログイン・取得できないときに使う。
- Component Specs に「現在のマスターに無い ID の表示」を足す: 「不明な<種類>（<ID>）」。数値は「−」にして合計に数えない。
- UI Copy の用語: 検索結果の構成を名前を付けて残す操作は「保存」と書き、その画面は「保存した構成」と書く（新規登録の「登録」の例外）。
