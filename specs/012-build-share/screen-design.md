## 0. 前提

- 共有の作成・自分の共有の一覧・取り消しは、ログイン中だけ使える（AC-12）。未ログインと「取得できない」は、011 の 6.1 と同じくログインを促す。
- 共有の閲覧（S7）は、ログインしていなくても開ける。ログインの状態で表示を変えない（AC-5・AC-11）。閲覧の API は 401 を返さないので、S7 は 401 の扱いを持たない。
- 共有は、保存した構成の画面（S5）からだけ作る（Q90）。検索結果や一覧の行からは作らない。
- 共有した内容は、作ったときの名前と構成の内容のまま変わらない（AC-7）。名前を変えた後の内容で共有し直すには、取り消してから作る（Q90）。
- 共有の URL は、Web が `location.origin` と `/s/<短縮 ID>` から組み立てる（Q71）。
- 書き込みはオンラインのときだけ行い、失敗した要求を後で送り直さない（011 の Q69）。
- 追加する ui 部品は無い（既存の `card`・`button`・`badge`・`dialog`・`alert-dialog`・`skeleton`・`alert`・Toast で足りる）。

| 状態 | 条件 | 表示 |

| 読込中 | 共有かマスターの読み込みが終わっていない | 300ms 未満は何も出さない。超えたらスケルトン（h1 の行・情報の4行・カードの形）と「共有された構成を読み込んでいます…」。h1 は「共有された構成」 |

## 7. 共通の振る舞い

### 7.1 ログインの期限切れ・ログアウト

011 の 6.4 に、共有の API を足す。

| 事象 | 条件 | 表示 | 知らせ方 |
|---|---|---|---|
| ログインの期限切れ | 共有の API（作成・一覧・取り消しのどれか）が 401 | 開いているダイアログ（D9・D10）を閉じる。S6 は 4.3 の「ログインが必要」に替える。S5 は 011 の 6.4 のとおり | トースト（`--destructive`）「ログインの有効期限が切れました。もう一度「Discord でログイン」を押すと、保存した構成と共有を使えます。」。ヘッダーは 009 の未ログインの表示に戻す |
| ログアウト | 009 のログアウトの成功 | D9・D10 を閉じ、S6 は 4.3 の「ログインが必要」に替える。S7 は変えない | 009 のトースト「ログアウトしました」だけ |

- 401 のトーストは、構成の API と共有の API が同時に 401 になっても1回だけ出す（011 の 6.4 と同じ）。
- 作成中・取り消し中にログイン中でなくなったときは、その要求の応答を画面に反映せず、トーストも出さない。

## 9. MASTER.md に足す内容（区間 D でメインが書く）

- UI Copy の用語: 保存した構成の URL を作って他の人に見せる操作は「共有」と書き、自分の共有の一覧の画面は「共有した構成」、受け手が開く画面は「共有された構成」と書く。共有をやめる操作は「共有を取り消す」と書く（ダイアログを閉じるだけの「キャンセル」とは別の操作のため、確認のダイアログのボタンも「取り消す」と略さない）。
- Component Specs に「URL の表示」を足す: 入力欄にせず、枠（`--input` の 1px・角丸 4px）の中に全文を `break-all`・`select-all` で出し、その下に「URL をコピー」（outline・lucide `Copy`）を置く。コピーの成否はトーストで知らせ、失敗したときは URL の文字を全選択する。
