## 0. 前提

- 個体差のある武器の保存先は、認証状態（009 の `GET /api/auth/me` の結果）で決める。ログイン中はアカウント（サーバー）、未ログインと「取得できない」は端末内（IndexedDB）。両方を混ぜて表示・検索しない（decisions.md Q98）。
- 保存先の切り替えは、個体差のある武器の一覧を持つ1か所（今の `stores/weapons.ts`）に集約する。画面（S1・D1・S3）は、保存先の種類を表示に使うだけで、どちらから読むかを判定しない。
- 認証状態の判定中は、個体差のある武器の一覧も読み込まない（読込中のまま待つ）。判定の結果を待たずに端末内の武器を出して、あとからアカウントの武器に差し替えることはしない。
- 入力フォーム・構造の検査・検索の候補の判定・一覧の行の表示は、008 のまま変えない（AC-2）。
- ログインはページを離れて戻るため、ログインしたときの切り替えは起動のときの判定で済む。ページを離れずに保存先が変わるのは、ログアウトと、個体差のある武器の API の 401（ログインの期限切れ）の2つだけ。
- 書き込みはオンラインのときだけ行い、失敗した要求を後で送り直さない（Q99）。
- 追加する ui 部品は無い（既存の `ResultAlert`・`alert-dialog`・Toast で足りる）。

### 2.2 保存先の表示

MASTER.md の Component Specs「保存先の表示」のとおり（h1 の直下・間隔 4px、下の要素との間隔 16px。読込中・マスターの読込失敗の間は出さない）。

| 保存先 | 表示 |
|---|---|
| ログイン中 | アイコン `Cloud`、文言「保存先: アカウント」 |
| 未ログイン・取得できない | アイコン `Smartphone`、文言「保存先: この端末」 |

- 保存先が変わったら（ログアウト・401）、その場で文言とアイコンを替える。フォーカスは動かさない。ライブリージョンにしない（ログアウト・401 はトーストが知らせるため）。

### 2.3 端末内に残る武器の帯

MASTER.md の Component Specs「端末内に残るデータの帯」のとおり（情報の `ResultAlert`・見出しなし・閉じるボタンなし。保存先の表示の直下・間隔 16px。`lg` 以上も幅いっぱい）。

| 項目 | 内容 |
|---|---|
| 出す条件 | ログイン中で、端末内（IndexedDB）の個体差のある武器が1件以上あるとき。件数を数えるだけで、中身は表示・送信・削除しない（AC-1） |
| 出さない条件 | 未ログイン・取得できない・端末内が0件・IndexedDB を開けない・数えられない（エラーは出さない。帯を出さないだけ） |
| 文言 | 「この端末には、ログインしていないときに登録した個体差のある武器が <N> 件残っています。ログインしている間は表示せず、検索にも使いません。ログアウトすると、ふたたび表示します。」 |
| 件数 | `<N>` は本文のフォントのまま（MASTER.md の Typography の「文中の数字」） |

- 端末内の武器を数えるのは、アカウントの武器の一覧を読むときに1回だけ。
- 端末内の武器をアカウントへ取り込む導線は置かない（014）。帯の文言でも予告しない。

### 2.4 状態（008 の 3.4 に足す・変える行）

| 状態 | 条件 | 表示 |
|---|---|---|
| 読込中 | 認証状態の判定中、または一覧（アカウントか端末内）とマスターの読み込みが終わっていない | 008 のまま（300ms 未満は何も出さない。超えたらスケルトンと「武器とマスターデータを読み込んでいます…」）。最初の読み込みのあとの読み直し（409・404・再読み込み・保存先の切り替え）は、フォームを残して一覧の位置だけを読込中にする（010 と同じ） |
| アカウントの武器の読込失敗 | ログイン中で、一覧の API に届かない・401 以外のエラー・応答の形の不正 | 一覧の位置に Alert（エラー。消えないインラインの表示）。見出し「個体差のある武器を読み込めません」、原因を1行（2.6）、次の行動「通信の状態を確かめて、「再読み込み」を押してください。通常の武器での検索は引き続き使えます。」と「再読み込み」（outline・高さ 44px）。フォームは無効にし、先頭に「個体差のある武器を読み込めないため、個体差のある武器を登録できません。」（008 の文言のまま）。保存先の表示は「保存先: アカウント」のまま |
| 書き込みの失敗 | 登録・保存・削除が、API に届かない・409／404／401 以外のエラーで失敗した | トースト（`--destructive`）「個体差のある武器を保存できませんでした。<原因> もう一度お試しください。」（削除のときは「個体差のある武器を削除できませんでした。<原因> もう一度お試しください。」）。一覧は変えない。フォームの入力は残す。要求は自動で送り直さない |
| 端末に保存できない・保存した武器を読み込めない・端末の書き込みの失敗 | 未ログイン・取得できないときの IndexedDB の失敗 | 008 のまま |

「再読み込み」は、アカウントの武器の一覧と端末内の件数を読み直す。認証状態は読み直さない（009 の 0 節。起動のときに1回だけ）。

### 2.5 競合・期限切れ・保存先の切り替え

| 事象 | 条件 | 一覧 | フォーム | 知らせ方 |
|---|---|---|---|---|
| 別の端末で変更されていた | 更新が 409 | サーバーから読み直す | 登録のモードに戻し、入力を捨てる。読み直しが終わったら、フォーカスをその武器の「編集」に移す（無ければ一覧の見出し） | トースト（`--destructive`）「この個体差のある武器は別の端末で変更されていたため、保存しませんでした。一覧を読み直しました。内容を確かめて、もう一度編集してください。」 |
| 別の端末で削除されていた | 更新が 404 | サーバーから読み直す | 登録のモードに戻し、入力を捨てる。読み直しが終わったら、フォーカスを一覧の見出しに移す | トースト（`--destructive`）「この個体差のある武器は別の端末で削除されていたため、保存しませんでした。一覧を読み直しました。」 |
| ログインの期限切れ | 個体差のある武器の API（一覧・作成・更新・削除のどれか）が 401 | 端末内の武器に切り替える（008 の読み込み）。保存先の表示を「この端末」にし、帯を消す | 編集のモードなら登録のモードに戻し、入力を捨てる。登録のモードなら入力を残す（保存はしていない）。フォーカスは、押したボタンが残っていればそのまま、消えていれば一覧の見出しに移す | トースト（`--destructive`）「ログインの有効期限が切れたため、保存しませんでした。端末内の個体差のある武器に切り替えました。アカウントに保存するには、もう一度「Discord でログイン」を押してください。」（一覧の読み込みでの 401 のときは「ログインの有効期限が切れました。端末内の個体差のある武器に切り替えました。もう一度「Discord でログイン」を押すと、アカウントの個体差のある武器を使えます。」）。ヘッダーは 009 の未ログインの表示に戻す |
| ログアウト | 009 のログアウトの成功 | 端末内の武器に切り替える。保存先の表示を「この端末」にし、帯を消す | 編集のモードなら登録のモードに戻し、入力を捨てる。登録のモードなら入力を残す | 009 のトースト「ログアウトしました」だけ（武器の側からは足さない） |

- 読み直し（409・404）が失敗したら、2.4 の「アカウントの武器の読込失敗」にする。
- 保存中・削除中に保存先が変わった（ログアウト・別の要求の 401）ときは、その要求の応答を一覧に反映せず、トーストも出さない。
- 401 のトーストは、同時に複数の要求が 401 になっても1回だけ出す。護石と個体差のある武器の要求が同時に 401 になったときも1回だけで、文言は先に 401 を受けた側のものにする（どちらの一覧も端末内に切り替わる）。
- 404 を受けた武器は、読み直した一覧に無いため、編集の対象から外れる。登録し直したいときは、ユーザーが改めて入力する（入力は残さない）。
- 一覧から消えた武器を検索条件で選んでいたときの扱いは 3.1。

### 2.6 原因の文言（アカウントの保存先）

010 の 2.6 と同じ。

| 原因 | 文言 |
|---|---|
| API に届かない（通信の失敗） | 「サーバーに接続できませんでした。」 |
| 400・403・5xx・応答の形の不正など、それ以外 | 「サーバーで処理できませんでした。」 |

- 端末内の保存先の原因の文言は、008 の 3.4 のまま。
- 400（構造の制約の違反）は、フォームの検証（008）を通った入力では起きない想定のため、項目の直下には出さず、上の「それ以外」として扱う。

## 3. S1 検索画面・D1 武器を選ぶダイアログ（変更）

### 3.1 検索条件の武器の選択（AC-5）

| 事象 | 扱い |
|---|---|
| 保存先が変わった（ログアウト・401） | 切り替えた一覧に、選んでいる個体差のある武器が無ければ、選択を外す |
| 一覧を読み直した（409・404 のあと・「再読み込み」） | 読み直した一覧に、選んでいる個体差のある武器が無ければ、選択を外す。読み直しに失敗して一覧が空になったときも外す |
| S3 で削除した | 008 のまま（選択を外す） |

- 外した後の「武器」カードは、008 の未選択の表示に戻す。武器欄のエラーは、検索を押すまで出さない（008 の 2.2 と同じ）。
- 選択を外したことは、別のトースト・帯では知らせない（ログアウトと 401 は 2.5 のトーストで、409・404 は 2.5 のトーストで、事象そのものを知らせているため）。
- 選んでいる武器が一覧に残っていれば、選択は外さず、カードは読み直した後の内容を出す（008 の 2.2 の「編集したら編集後の内容を出す」と同じ）。
- 検索の実行中に選択を外しても、実行中の検索はそのまま終える。表示中の結果は変えない（008 の 2.4）。
