# 013: user-weapon-save

## 目的 / ユーザーストーリー
Discord でログインしたプレイヤーとして、登録した個体差のある武器をサーバーに保存し、PC とスマホなどの複数の端末で同じ武器の一覧を使って構成を探したい。ログインしていないときは、これまでどおり端末内（IndexedDB）に保存して使える（008）。端末内の武器のサーバーへの取り込みは 014 で行い、013 では行わない（`temp/initial-design.md` §2.1）。あわせて、010・011 で持ち越した API の入力の検査を、護石・構成・武器のすべての API で契約どおりに直す（decisions.md Q72）。

用語:
- アカウントの武器: ログインしているユーザーがサーバーに保存した個体差のある武器。
- 端末内の武器: 008 で端末内の IndexedDB に保存した個体差のある武器。
- 行バージョン: 武器の行ごとにサーバーが持つ版（`version`）。010 の護石と同じく、別の端末での変更との競合の検出に使う。

## 受入基準（EARS記法）
- AC-1: WHILE ログインしているとき THE system SHALL 個体差のある武器の画面の一覧と検索の武器の選択肢に、アカウントの武器だけを使わなければならない。端末内の武器を表示・送信・削除してはならない（decisions.md Q98）。
- AC-2: WHILE ログインしているとき WHEN 武器を登録・編集・削除したとき THE system SHALL それをサーバーに保存し、同じアカウントでログインした別の端末でも同じ一覧を表示しなければならない。新しい武器の ID はクライアントで採番した UUIDv7 とし、入力・構造上の制約の検査・検索の候補の判定は 008 と同じに行わなければならない。
- AC-3: WHERE 未ログイン、または認証状態を取得できないとき THE system SHALL 008 のとおり端末内の武器を使わなければならない。WHEN ログアウトしたとき THE system SHALL 画面を移らずに、一覧と検索の武器の選択肢を端末内の武器に切り替えなければならない（decisions.md Q98）。
- AC-4: THE system SHALL 個体差のある武器の画面に、いまの保存先（この端末かアカウントか）を示し、ログインしている間に端末内に武器が残っていればその旨を示さなければならない（decisions.md Q98）。
- AC-5: IF 検索条件で選んでいる個体差のある武器が、保存先の切り替え（ログイン・ログアウト・401）や一覧の読み直しで一覧から消えたとき THEN システムは、検索条件の武器の選択を外さなければならない（decisions.md Q100）。
- AC-6: THE system SHALL 武器の一覧・作成・更新・削除の API をログインを要するものとし、一覧は自分の削除していない武器だけを ID の降順で全件返し（ページングしない）、作成日時・更新日時・行バージョンをサーバーで管理して、応答は端末内の武器と同じ形に行バージョンを加えて返さなければならない。他のユーザーの武器を返したり変えたりしてはならない（decisions.md Q99）。
- AC-7: IF 未ログインのまま武器の API を呼んだとき THEN API は 401 を返し、状態を変える要求が CSRF トークンを持たないときは拒否して、武器を変えてはならない。
- AC-8: IF 作成の ID が既存の行（自分・他のユーザー・削除済みを問わない）と衝突したとき THEN API は 409 で拒否し、既存の行を変えてはならない。IF 更新の行バージョンがサーバーの行と一致しないとき THEN API は 409 で拒否して上書きせず、更新する武器が自分の削除していない行に無いときは 404 を返さなければならない。Web は、どちらの場合も別の端末で変更・削除されたことを知らせて一覧をサーバーから読み直さなければならない（decisions.md Q99）。
- AC-9: WHEN 武器を削除したとき THE system SHALL 論理削除（`deleted_at`）にし、行バージョンを照合せず、削除済み・存在しない・他のユーザーの ID でも 204 を返さなければならない。他のユーザーの行を変えてはならない（decisions.md Q99）。
- AC-10: IF 作成・更新の内容がマスターに依らない構造の制約（ID は UUIDv7・スキーマ版は 1・基の武器の ID の形式・名前は 0〜30 文字・攻撃力は 1〜999・会心率は -100〜100・属性の種類と値は 1〜99・スロットは 0〜3 枠で武器用の Lv 1〜3・付与スキルの ID の形式）に反するとき THEN API は 400 で拒否し、保存してはならない。基の武器・付与スキルがマスターにあるかは検査してはならない（decisions.md Q99）。
- AC-11: IF 護石・保存した構成・個体差のある武器の API の要求が、文字列の項目に文字列以外の JSON の値を持つ、省略できる項目（`element` など）に明示の null を持つ、または文字列の項目に U+0000 を含むとき THEN API は 400 で拒否し、保存してはならない。値を変換・除去して保存してはならない（decisions.md Q72）。
- AC-12: IF 武器の API が 401 を返したとき THEN Web は、ログインの有効期限が切れたことを知らせ、ヘッダーを未ログインの表示に戻し、一覧と検索の武器の選択肢を端末内の武器に切り替えなければならない。一覧を取得できないときは、読み込めなかったことと再読み込みの操作を示し、マスターの武器での検索を使えるようにしなければならない。保存・削除に失敗したときは、トーストで知らせて一覧を変えず、要求を後で送り直してはならない（decisions.md Q99）。
- AC-13: THE system SHALL アカウントの武器を Flyway のマイグレーションで作るテーブルに保存し、その項目を `design/attributes.yaml` に確定しなければならない。
- AC-14: THE system SHALL API のテスト（Testcontainers）で、武器の作成・一覧・更新・削除、他のユーザーの武器の隔離、ID の衝突、行バージョンの不一致、構造の制約の違反、未ログインの 401、CSRF トークンの無い要求の拒否と、護石・構成・武器の API の AC-11 の 3 種の拒否を検証しなければならない。
- AC-15: THE system SHALL Playwright（Chromium）の e2e テストで、API の応答を差し替えて、ログインしているときに武器を登録すると一覧に出て検索の武器の選択肢に使われること、ログアウトすると端末内の武器に切り替わり検索条件の武器の選択が外れること、更新が 409 のときに知らせて読み直すことを検証しなければならない。

## スコープ外
- 端末内の武器のサーバーへの取り込み（014 guest-draft-import）
- オフラインでの閲覧、保存の要求の送り直しの待ち行列、アカウントの武器の端末への写し（018 pwa-offline。010 decisions.md Q60 と同じ）
- 武器の件数の上限とページング（010 decisions.md Q62 と同じく、一般公開の前に見直す）
- サーバーでの、マスターに依る検査（基の武器・付与スキルの存在と種別。decisions.md Q99）
- 削除した武器の復元と物理削除
- 保存した構成が持つ武器の写しの更新（構成は写しを使う。011 decisions.md Q64）
- 生産ボーナス・復元ボーナスの入力、アーティア以外を基にした武器、武器スキルの入力（008 のまま）
- 武器の一覧の並べ替え・絞り込み（008 と同じく扱わない）
- AC-11 の 3 種以外の API の入力の検査の見直し（文字列の長さの上限など）
- 本番環境へのデプロイ（009 decisions.md Q5 のとおり区間外の運用作業）

## 契約差分
- 追加: GET /api/weapons（res: 自分の削除していない武器の配列。ID の降順・ページングなし）
- 追加: POST /api/weapons（req: id・payload・schemaVersion。res: 201 保存した武器。409 ID の衝突・400 構造の違反）
- 追加: PUT /api/weapons/{id}（req: payload・schemaVersion・version。res: 200 保存後の武器。409 行バージョンの不一致・404 自分の行が無い・400 構造の違反）
- 追加: DELETE /api/weapons/{id}（res: 204。論理削除。冪等）
- 追加: スキーマ 武器（id・payload・schemaVersion・version・createdAt・updatedAt）・作成の要求・更新の要求（名前は区間 C で決める）。武器の内容は既存のスキーマ `CustomWeaponPayload` を使う（decisions.md Q99）
- 変更: 護石・構成・武器の要求の文字列の項目に U+0000 を含まないこと（書き方は区間 C で決める。decisions.md Q72）
- 追加: テーブル（id, user_id, payload, schema_version, version, created_at, updated_at, deleted_at）。テーブル名と項目の確定は区間 B で行う
