## 0. 前提

- 取り込みは、ログイン中に護石・個体差のある武器の画面の「端末内に残るデータの帯」（010 の 2.3・013 の 2.3）に置く操作から、利用者が始める。ログインの判定の時点では始めない（decisions.md Q103）。
- 護石の画面では護石を、個体差のある武器の画面では個体差のある武器を、それぞれ別々に取り込む。片方の画面の操作が、もう片方の帯に影響することは無い。
- 取り込む対象は、端末内に残っているものすべて。1件ずつ選ぶ部品は置かない（スコープ外）。
- 取り込みの手順（アカウントの一覧の読み直し、同じ ID の判定、1件ずつの送信、受け付けた1件の削除、件数の数え方）は、一覧を持つ1か所（今の `stores/charms.ts`・`stores/weapons.ts`）に置く。画面は、取り込み中かどうかと結果の件数を表示に使うだけ。
- 画面を離れても取り込みは続ける。戻ったときに取り込みが続いていれば、取り込み中の表示（2.3）にする。終わりの知らせ（2.4）は、どの画面にいても出す（トーストは全画面に共通のため）。
- 追加する ui 部品は無い（既存の `ResultAlert`・`alert-dialog`・Toast・`Button` で足りる）。

### 2.4 終わりの知らせと読み直し（AC-4〜AC-9）

取り込みが終わったら（止めたときも）、次の表の知らせを1回だけ出し、アカウントの一覧と端末内の件数を読み直す。件数は次のとおり数える。

- 取り込んだ件数 `<N>`: サーバーが受け付けた件数と、アカウントに同じ ID が既にあって送らずに端末から消した件数の合計（AC-4・AC-5）。受け付けたが端末から消せなかったものも含める。
- 残した件数 `<M>`: 400・409 で取り込めなかった件数と、止めたために送らなかった件数（失敗した1件を含む）の合計。どれも端末に残る。

| 終わり方 | 条件 | 知らせ |
|---|---|---|
| すべて取り込んだ | 最後まで送り、`<M>` が 0 | トースト（通常）「護石を <N> 件アカウントに取り込みました。」 |
| 一部を取り込めなかった | 最後まで送り、400・409 が1件以上（AC-6） | トースト（`--destructive`）「護石の取り込みが終わりました。取り込んだのは <N> 件で、<M> 件はアカウントに保存できなかったため、この端末に残しています。」 |
| 通信・サーバーの失敗で止めた | 作成が、API に届かない・401 以外のエラー（5xx など）で失敗した（AC-8） | トースト（`--destructive`）「護石の取り込みを途中で止めました。<原因> 取り込んだのは <N> 件で、<M> 件はこの端末に残しています。通信の状態を確かめて、もう一度「アカウントに取り込む」を押してください。」 |
| 期限切れで止めた | 作成が 401（AC-7） | トースト（`--destructive`）「ログインの有効期限が切れたため、取り込みを止めました。取り込んだのは <N> 件で、<M> 件はこの端末に残しています。端末内の護石に切り替えました。もう一度「Discord でログイン」を押すと、続きを取り込めます。」。ヘッダーは 009 の未ログインの表示に戻し、一覧を端末内の護石に切り替える（010 の 2.5 の期限切れと同じ。帯は消える）。010 の期限切れのトーストは出さない（この1回にまとめる） |
| 始める時点のアカウントの一覧を読めない | 取り込みの最初のアカウントの一覧の読み直しが、API に届かない・401 以外のエラーで失敗した | 「通信・サーバーの失敗で止めた」と同じ（`<N>` は 0、`<M>` は端末内の件数）。何も送らない |
| 始める時点のアカウントの一覧が 401 | 同じ読み直しが 401 | 「期限切れで止めた」と同じ（`<N>` は 0） |
| 取り込み中のログアウト | 009 のログアウトが成功した | 応答待ちの1件は、その応答まで扱う（受け付けたら端末から消す）。残りは送らずに止める。知らせは 009 のトースト「ログアウトしました」だけ（取り込みの側からは出さない）。一覧は 010 の 2.5 のとおり端末内に切り替わる |

- `<原因>` は 010 の 2.6 の文言（「サーバーに接続できませんでした。」「サーバーで処理できませんでした。」）。
- 件数は本文のフォントのまま（MASTER.md の Typography の「文中の数字」）。`<N>`・`<M>` が 0 でも同じ文にする。
- 要求は自動で送り直さない（AC-8）。取り込み直しは、利用者が帯の「アカウントに取り込む」を押す（AC-9）。
- 読み直しの結果、端末内の件数が 0 なら帯ごと消える。1件以上なら帯の件数を読み直した件数にし、「アカウントに取り込む」を押せる状態に戻す。
- 読み直しでアカウントの一覧が読めなければ、010 の 2.4「アカウントの護石の読込失敗」にする（知らせは上の表の1回だけで、読込失敗のトーストは足さない）。
- 読み直しの間に端末内の件数を数えられなければ、帯を出さない（010 の 2.3 のまま）。
