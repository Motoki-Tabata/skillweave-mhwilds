# 014: guest-draft-import

## 目的 / ユーザーストーリー
ログインせずに護石と個体差のある武器を端末内（IndexedDB）に登録してきたプレイヤーとして、Discord でログインした後に、それらを入力し直さずにアカウントへ移し、複数の端末で使いたい。取り込みは一方向・一回きりで、双方向のマージはしない（`temp/initial-design.md` §2.1）。取り込みは利用者の操作で始め、取り込んだものは端末から消す（decisions.md Q103・Q104）。構成はゲストの端末内に保存しないので、取り込みの対象にしない（decisions.md Q70）。

用語:
- 端末内の護石・武器: 005・008 で端末内の IndexedDB に保存した鑑定護石・個体差のある武器。
- アカウントの護石・武器: 010・013 でサーバーに保存した護石・武器。
- 残っている旨の表示: ログインしている間に、端末内に護石・武器が残っていることを護石・武器の画面に示す表示（010 decisions.md Q58・013 decisions.md Q98）。
- 取り込み: 端末内の護石（または武器）を、アカウントの護石（または武器）としてサーバーへ送り、受け付けられたものを端末から消すこと。

以下の受入基準は、護石の画面では護石を、武器の画面では武器を対象にする（画面ごとに別々に取り込む。decisions.md Q103）。

## 受入基準（EARS記法）
- AC-1: WHILE ログインしていて、端末内に護石（武器）が1件以上残っているとき THE system SHALL 護石（武器）の画面の残っている旨の表示に、端末内の護石（武器）をアカウントへ取り込む操作を示さなければならない。端末内に残っていないとき・未ログインのとき・認証状態を取得できないときは、その操作を示してはならない（decisions.md Q103）。
- AC-2: WHEN 取り込む操作をしたとき THE system SHALL 取り込む件数と、取り込んだものを端末から消すことを示して確認を求めなければならない。承認されるまでサーバーへ送ってはならず、取り消したときは何も送らずに端末内を変えてはならない（decisions.md Q103）。
- AC-3: WHEN 取り込みを承認したとき THE system SHALL 端末内の護石（武器）を、ID・内容・スキーマ版を変えずに、010（013）の作成 API で1件ずつ順に送らなければならない。ログインを判定した時点で自動で送ってはならず、マスターとの照合の結果で送るものを選んではならない（decisions.md Q103・Q105）。
- AC-4: WHEN サーバーが1件の作成を受け付けたとき THE system SHALL その1件を端末から消し、取り込んだものとして数えなければならない。端末から消せなかったときも取り込んだものとして数え、次の取り込みで AC-5 のとおり扱わなければならない。サーバーが受け付けていないものを端末から消してはならない（decisions.md Q104）。
- AC-5: IF 取り込みを始める時点で、アカウントの一覧に同じ ID が既にあるとき THEN システムは、その1件をサーバーへ送らずに端末から消し、取り込んだものとして数えなければならない（decisions.md Q104）。
- AC-6: IF 1件の作成が 400（構造の検査に反する）または 409（ID の衝突）で拒否されたとき THEN システムは、その1件を端末に残し、取り込めなかったものとして数えて、次の1件へ進まなければならない（decisions.md Q105）。
- AC-7: IF 作成が 401 を返したとき THEN システムは、そこで取り込みを止め、010 decisions.md Q60 のとおりログインの有効期限が切れたことを知らせ、ヘッダーを未ログインの表示に戻して、一覧を端末内の護石（武器）に切り替えなければならない。送っていないものを端末から消してはならない（decisions.md Q105）。
- AC-8: IF API に届かない、または 401 以外のサーバーのエラー（5xx など）で作成に失敗したとき THEN システムは、そこで取り込みを止め、失敗した1件と送っていないものを端末に残さなければならない。要求を後で送り直してはならない（decisions.md Q105）。
- AC-9: WHEN 取り込みが終わったとき（AC-7・AC-8 で止めたときを含む） THE system SHALL 取り込んだ件数と、取り込めなかった・送らなかった件数を知らせ、アカウントの一覧と端末内の件数を読み直さなければならない。端末に残ったものがあれば、AC-1 の操作から取り込み直せなければならない（decisions.md Q105）。
- AC-10: WHILE 取り込みの最中 THE system SHALL 取り込みが進んでいることを示し、同じ画面の取り込みの操作を重ねて受け付けてはならない。
- AC-11: WHEN 取り込みの後にログアウトしたとき THE system SHALL 端末の一覧に、取り込まなかったもの（端末に残ったもの）だけを表示しなければならない（decisions.md Q104）。
- AC-12: THE system SHALL Web の単体テストで、取り込みの操作の表示の条件（AC-1）、確認の取り消しで送らないこと（AC-2）、ID・内容を変えずに1件ずつ送ること（AC-3）、受け付けた1件だけを端末から消すこと（AC-4）、アカウントに同じ ID があるものを送らずに消すこと（AC-5）、400・409 の1件を残して進むこと（AC-6）、401 と通信の失敗で止めて残すこと（AC-7・AC-8）、件数の知らせと読み直し（AC-9）を、護石と武器の両方で検証しなければならない。
- AC-13: THE system SHALL Playwright（Chromium）の e2e テストで、API の応答を差し替えて、ログインしているときに端末内の護石と武器をそれぞれ取り込むと、アカウントの一覧に出て端末から消え残っている旨の表示が消えること、確認を取り消すと何も送らないこと、400 で拒否された1件が端末に残り取り込み直しの操作が残ることを検証しなければならない。

## スコープ外
- 構成の取り込みと、ゲストの構成の端末内の保存（decisions.md Q70）
- ログインを判定した時点での自動の取り込み（decisions.md Q103）
- 取り込む護石・武器を1件ずつ選ぶこと（端末内に残っているものをすべて取り込む）
- 取り込み済みの印を付けて端末に残すこと（decisions.md Q104）
- 一括の取り込みの API と、契約・API の変更（decisions.md Q105）
- 端末の作成日時・更新日時の引き継ぎ（サーバーが付け直す。decisions.md Q105）
- 取り込みでのマスターとの照合（005・008 の検査）による送るものの選別（decisions.md Q105）
- 件数の上限・一覧のページング・要求の頻度の制限（decisions.md Q106。一般公開の前に Q107 で決める）
- 双方向のマージと、アカウントの護石・武器の端末への写し（`temp/initial-design.md` §2.1。オフラインは 018 pwa-offline）
- 本番環境へのデプロイ（009 decisions.md Q5 のとおり区間外の運用作業）

## 契約差分
