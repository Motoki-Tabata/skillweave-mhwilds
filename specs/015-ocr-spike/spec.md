# 015: ocr-spike

## 目的 / ユーザーストーリー
開発者（オーナー）として、Tesseract.js でゲーム画面のスクリーンショットから鑑定護石のスキルとスロットを、実用的な精度と時間でブラウザ内で読み取れるかを、016 charm-ocr の前に確かめたい。OCR の方式は 016 の前提になる技術リスクなので、先に潰す。ここで書く前処理・認識・マスターの辞書との照合は捨てずに `apps/web/src/main/lib/ocr/` に残し、016 で拡張する（decisions.md Q111）。

用語:
- 読み取り結果: 1枚の画像から得た、護石のスキル（スキルの ID と Lv）の並びと、スロット（武器用・防具用の別と Lv）の並び。`CharmPayload` からレア度を除いた形（decisions.md Q116）。
- 完全一致: 読み取り結果のスキルとスロットが、並びも含めてすべて正解ラベルと一致すること（decisions.md Q110・Q115）。
- 1枚の認識時間: 画像を渡してから読み取り結果が返るまで（前処理・認識・照合を含む。Tesseract.js の初期化は含めない）。

## 受入基準（EARS記法）
- AC-1: THE system SHALL `apps/web/src/main/lib/ocr/` に、PC 版の護石の詳細画面の画像を受け取り、Tesseract.js（日本語）で読み取り結果を返す関数を提供しなければならない（decisions.md Q109・Q114）。
- AC-2: THE system SHALL 認識したスキル名を、マスターの ja 辞書のスキル名のうちもっとも近いものに照合してスキルの ID にし、認識したスキル Lv をそのスキルの最大 Lv 以下の整数として返さなければならない。
- AC-3: IF 照合で近いスキル名が見つからない、または Lv を読み取れないとき THEN システムは、その行を推測で埋めず、読み取れなかった行があることを読み取り結果に含めて返さなければならない。
- AC-4: THE system SHALL Tesseract.js の worker・WASM コア・日本語の言語データを npm パッケージからビルドに含めて自オリジンから読み込み、他のオリジンへ通信してはならない（decisions.md Q112）。
- AC-5: THE system SHALL 画像をサーバーへ送らず、画像の読み込みから読み取り結果までをブラウザ内で完結させなければならない（憲法）。
- AC-6: THE system SHALL 照合と読み取り結果の組み立てを、認識した文字列を入力とする単体テストで検査しなければならない（画像を使わず CI で実行する）。
- AC-7: THE system SHALL 測定用の画像をリポジトリにコミットせず `.gitignore` で除外した置き場から読み、画像ごとの正解ラベル（スキルとスロット）だけを JSON でコミットしなければならない（decisions.md Q108）。
- AC-8: IF 測定を実行したときに画像の置き場が無い、正解ラベルのある画像が 20 枚未満、または正解ラベルの無い画像があるとき THEN システムは、測定せずに理由を出力して失敗しなければならない（decisions.md Q114）。
- AC-9: WHEN 測定を実行したとき THE system SHALL Playwright の `measure` プロジェクトで、ブラウザ（Chromium）上で全画像を読み取り、画像ごとの完全一致の可否・不一致の項目・1枚の認識時間と、全体の完全一致率・1枚の認識時間の最大・初期化の時間を出力しなければならない。
- AC-10: WHEN 測定を実行したとき THE system SHALL 測定中のリクエストがすべて自オリジンであることを検査し、他のオリジンへのリクエストがあれば失敗にしなければならない（AC-4・AC-5 の確認）。
- AC-11: THE system SHALL 完全一致率が 90% 以上かつ1枚の認識時間の最大が 3 秒以内のときに合格と判定しなければならない（decisions.md Q110）。
- AC-12: IF 合格の基準を満たさないとき THEN システムは、前処理の改善（拡大・二値化・文字の許可リストなど）を1回だけ加えて再測定し、改善の前後の両方の結果を記録しなければならない（decisions.md Q113）。
- AC-13: IF 前処理の改善を加えても合格の基準を満たさないとき THEN システムは、代替（別の OCR エンジン・読み取り範囲の手動指定など）の選定を `specs/open-questions.md` に新しい Q として起票し、015 を「不合格」の結論で閉じなければならない（decisions.md Q113）。
- AC-14: THE system SHALL 測定結果（全体の完全一致率・1枚の認識時間の最大・初期化の時間・合否・画像の枚数と解像度・測定環境・Tesseract.js と言語データの版）と Tesseract.js の採否を `design/tech-stack.md` に記録しなければならない。
- AC-15: THE system SHALL 測定を CI の検証コマンドで実行してはならず、CI で実行するテストで時間と精度を検査してはならない（画像がリポジトリに無く、時間は環境で揺れるため）。

## スコープ外
- 護石を読み取って護石一覧に登録する画面・確認と修正の UI・画像の選択の導線（016）
- 護石のレア度の読み取り（decisions.md Q116。取り方は 016 で決める）
- 抽選テーブルによる読み取り結果の妥当性の検査（016。005 の検査を使う見込み）
- 家庭用機のキャプチャ・画面をスマホで撮った写真（decisions.md Q109）
- 護石の詳細画面以外の画面・解像度の違い・英語の画面（decisions.md Q114）
- 1枚の画像に複数の護石が写る場合
- 不合格時の代替の OCR エンジン・方式の実装
- PWA としてのオフライン配信（018。015 は自オリジンからの配信までにとどめる）

## 契約差分
- なし（API を持たない。OCR はブラウザ内で動き、画像をサーバーへ送らない）

## 影響範囲
触る領域: web
常時許可外の変更予定:
- `apps/web/package.json`（dependencies に tesseract.js と日本語の言語データのパッケージを追加する）
- `pnpm-lock.yaml`（tesseract.js の追加に伴う更新）
- `pnpm-workspace.yaml`（tesseract.js の postinstall（opencollective-postinstall）を allowBuilds で遮断する旨を明記する）
- `apps/web/vite.config.ts`（Tesseract.js の worker・WASM コア・言語データを自オリジンから配信できるようにビルドに含める）
- `.gitignore`（測定用の画像の置き場を除外する）
- `design/tech-stack.md`（測定結果と Tesseract.js の採否を記録する）
