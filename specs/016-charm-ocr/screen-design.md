## 護石（`/charms`）

### 画面構成
- 見出し（h1「護石」）・保存先の表示・端末内に残る護石の帯は変えない。
- 作業領域の左の列（`lg` 以上。幅 400px）を、上から「画像から読み取る」のカード → 登録のフォームのカード の順に積む（間隔 16px）。右の列の登録済みの一覧は変えない。
- `lg` 未満は1カラムで、「画像から読み取る」→ 登録のフォーム → 登録済みの一覧 の順に積む。
- 読込中・マスターの読込失敗のときは、今と同じく「画像から読み取る」のカードも出さない。

### 部品

#### A. 「画像から読み取る」のカード（新規）
カード（MASTER.md「Cards」）の中に、上から次を置く。

1. 小見出し（h2・「小見出し（セクション）」）「画像から読み取る」。
2. 受け取りの枠: 1px の `--input` の枠・角丸 4px・内側余白 16px。中に次を縦に並べる。
   - 説明（基準）: 「PC 版の護石の詳細画面のスクリーンショットを、ここへドラッグ＆ドロップするか、この画面で貼り付けてください。1回に 20 枚まで読み取れます。」
   - 「画像を選ぶ」（outline のボタン・lucide `ImagePlus`）。押すとファイル選択を開く（`accept="image/*"`・複数選択）。
   - ドラッグ中（画像のファイルが枠の上にあるとき）は、枠線を `--ring` にし、背景を `--muted` にする（色の変化だけ。MASTER.md「Motion」）。
3. 注記（補助テキスト・`--muted-foreground`）: 「画像はこのブラウザの中だけで読み取り、送信も保存もしません。」
4. 進み具合（`<output>`。ライブリージョン・基準）: 状態の節のとおりに文言を変える。何も無いときは空。
5. 読み取らなかった画像の帯（`ResultAlert` の `warning`）: 読み取らなかった画像があったときだけ出す。
6. 読み取りの失敗の帯（`ResultAlert` の `error`）: 失敗したときだけ出す。
7. 「待ち列を空にする」（outline のボタン）: 待ち列に1件以上あるときだけ出す。押すと、確認なしで待ち列と画像を捨て、フォームを空の登録のモードに戻す（画像をもう一度渡せば読み直せるため、破壊的操作の確認のダイアログは出さない）。

#### B. 登録のフォーム（変更）
待ち列があり、登録のモードのときだけ、次を足す・変える。編集のモードの見た目と動きは変えない。

1. 読み取りの帯（`ResultAlert` の `info`。見出しなし）: 見出し（h2「護石を登録」）の直下、フォームの先頭に置く。文言は項目定義の節。
2. 切り抜き: 帯の下に、いま仮入力している画像の、スロットの行とスキルの3枠を含む矩形を切り出して表示する（`<img>`・1px の `--border` の枠・角丸 4px）。幅はカードの内幅と切り抜きの実寸の小さいほう、縦横比は保つ。代替テキストは「読み取った画像の、スキル欄とスロット欄の切り抜き」。切り出しの矩形は 015 の読み取り範囲（`lib/ocr/preprocess.ts`・`lib/ocr/slots.ts`）から区間 C で決める。
3. 未読の行の印: 読み取り結果で `null` だった行（読めなかった行）の入力欄の直下に、補助テキストで lucide `TriangleAlert`（16px・`aria-hidden`）と「読み取れませんでした。画像を見て選んでください。」を出す。入力欄の `aria-describedby` に含める。その行で値を選んだら消す（スロットは「なし」を選んでも消す）。色は `--muted-foreground`（エラーではないので `--destructive` にしない）。
4. スロットの「未選択」: 読めなかったスロットの行は、Select の値を空にしてプレースホルダ「未選択」を出す（「なし」と区別する）。
5. ボタンの行: 「登録」（primary）の右の「入力を空にする」を「飛ばす」（outline）に置き換える。

読み取り結果の無い行（画像に無かったスキル・スロット）は、今と同じく空のスキル行・スロット「なし」で入れ、印は出さない。

### 項目定義（文言）
| 場所 | 文言 |
|---|---|
| 進み具合（準備中） | 「読み取りの準備をしています…」 |
| 進み具合（読み取り中） | 「画像を読み取っています（<k> / <n> 枚）…」 |
| 進み具合（次の1件を入れたとき） | 「次の護石を入れました。残り <m> 件です。」 |
| 進み具合（待ち列を終えたとき） | 「読み取った護石をすべて終えました。」 |
| 読み取り中の「画像を選ぶ」 | スピナー（lucide `Loader2`）と「読み取り中…」 |
| 読み取り中の受け取りの枠の説明 | 「読み取り中です。読み終えてから、続きの画像を渡してください。」 |
| 読み取らなかった画像の帯の見出し | 「読み取らなかった画像があります（<n> 枚）」 |
| 同・16:9 でない | 「<名前>: 16:9 の画像ではないため、読み取りませんでした。」 |
| 同・画像として読めない | 「<名前>: 画像として開けないため、読み取りませんでした。」 |
| 同・20 枚を超えた | 「1回に読み取れるのは 20 枚までのため、21 枚目以降の <n> 枚は読み取りませんでした。続きは、待ち列を終えてから渡してください。」 |
| 失敗の帯の見出し | 「画像を読み取れませんでした」 |
| 失敗の帯の本文（準備の失敗） | 「読み取りに使うデータを読み込めませんでした。通信状況を確かめて、もう一度画像を渡してください。手入力での登録はそのまま使えます。」 |
| 失敗の帯の本文（読み取りの失敗） | 「<k> 枚目の読み取りの途中で失敗したため、残りの画像は読み取っていません。読み取れた分は待ち列に入れました。残りの画像は、もう一度渡してください。手入力での登録はそのまま使えます。」 |
| フォームの読み取りの帯 | 「画像から読み取った内容を入れました（この護石を含めて残り <m> 件）。切り抜きと見比べて直し、レア度を選んでから登録してください。」 |
| 同・未読の行があるとき（2文目に足す） | 「読み取れなかった行が <r> 行あります。」 |
| 同・読み取りが続いているとき（末尾に足す） | 「残りの画像は読み取り中です。」 |
| スロットの未選択のエラー | 「スロットを選んでください。無ければ「なし」を選んでください。」 |

- `<名前>` はファイル名（長いときは折り返す。切り詰めない）。貼り付けた画像のようにファイル名が無いときは「貼り付けた画像 <i>」（その回に渡した順の番号）。
- 数は本文のフォントのまま（MASTER.md「Typography」の文中の数字）。

### 入力規則
- 受け取る経路は3つ（AC-1）。どれも複数枚を受け付け、渡した順を保つ。
  - ファイル選択: 「画像を選ぶ」。
  - 貼り付け: 護石の画面のどこでも（入力欄にフォーカスがあっても）、クリップボードに画像のファイルがあるときだけ読み取りに回し、ブラウザの既定の貼り付けを止める。文字だけのときは何もしない（入力欄への通常の貼り付けのまま）。ダイアログを開いているあいだは受け付けない。
  - ドラッグ＆ドロップ: 受け取りの枠の上に落としたときだけ受け付ける。枠の外に落としたときは何もせず、ブラウザが画像を開いて画面を離れないようにする。
- 1回に渡された画像のうち、先頭の 20 枚だけを読み取る（AC-2）。16:9 でない画像・画像として開けないファイルは、20 枚の数に含めたうえで読み取らずに理由を出す（AC-3）。
- 読み取り中に渡された画像は受け付けない（項目定義の「読み取り中」の文言を出す）。読み終えて待ち列が残っているときに渡された画像は、読み取って待ち列の末尾に足す。先頭の1件の仮入力は変えない。
- フォームが無効（護石を読み込めない・端末に保存できない）のあいだは、「画像を選ぶ」を無効にし、貼り付けとドロップも受け付けない。
- 仮入力は登録のモードの入力（レア度を含む）を上書きする。レア度は未選択にする（AC-4）。スキルは画面の表示順のまま、名前を Combobox の入力欄に、Lv をレベルの Select に入れる。
- 検査は今の登録と同じ（構造上の制約・抽選テーブルの照合・不一致のときの確認のチェック）。これに、未選択のスロットのエラー（項目定義）を足す。エラーの出し方は MASTER.md「Forms」のまま（送信時・フォーカスを外した時）。読めなかったスキルの行は、空のまま登録できる（空のスキル行は今もスキルなしの意味）。

### 状態
| 状態 | 「画像から読み取る」のカード | 登録のフォーム |
|---|---|---|
| 待ち列なし | 枠・注記だけ | 今と同じ |
| 準備中（最初の読み取りで、worker・WASM・言語データを読み込む） | 進み具合「読み取りの準備をしています…」・「画像を選ぶ」はスピナーと「読み取り中…」で無効（`aria-disabled`） | 今のまま操作できる |
| 読み取り中 | 進み具合「画像を読み取っています（k / n 枚）…」・「画像を選ぶ」は無効 | 1件目を読み終えた時点で仮入力する（読み終わりを待たない）。残りの件数は読むたびに増える |
| 待ち列あり | 「待ち列を空にする」 | 先頭の1件を仮入力（帯・切り抜き・印・「飛ばす」） |
| 一部を読み取らなかった | 読み取らなかった画像の帯（次に画像を渡すか、待ち列を空にするまで出したまま） | 読み取れた分で上の行のとおり |
| 失敗（AC-8） | 失敗の帯（次に画像を渡すまで出したまま）。worker は終了する | 読み取れた分があれば待ち列あり、無ければ今と同じ |
| 編集のモード | 今のまま操作できる（読み取り・待ち列への追加もできる） | 編集を優先し、仮入力しない。編集を終えたら（保存・キャンセル・409 などで編集のモードを抜けたら）、待ち列の先頭を仮入力し直す（先頭に加えていた修正は失われる） |

- 待ち列は端末のメモリにだけ持つ。画面を離れたら、確認なしで待ち列・画像・worker を破棄する（AC-10）。戻っても復元しない。
- 準備中・読み取り中の進み具合は、300ms 未満で終わっても出してよい（ボタン起因の読込中。MASTER.md「States」）。

### 遷移とフォーカス
- 画像を渡して1件目を仮入力したら、フォーカスをレア度の選択肢へ移す（今の `focusRarity`）。待ち列が残っているときに画像を足しても、フォーカスと仮入力は変えない。
- 「登録」で保存に成功したとき、または「飛ばす」を押したとき、その1件と画像を捨て、次の1件を仮入力してフォーカスをレア度へ移す（AC-6）。保存に失敗したとき（検査のエラー・409 など）は待ち列を進めない。
- 最後の1件を終えたら、フォームを空の登録のモードに戻し（レア度も未選択）、フォーカスを「画像を選ぶ」へ移す。
- 「待ち列を空にする」を押したら、フォームを空の登録のモードに戻し、フォーカスを「画像を選ぶ」へ移す。
- 画面の遷移は増やさない。

### キーボード・読み上げ
- キーボードだけで使う経路は、「画像を選ぶ」と貼り付け（Ctrl+V／⌘V）。受け取りの枠そのものはフォーカスを受けない（ドラッグ＆ドロップの受け口にすぎないため）。
- 進み具合は `<output>` で読み上げる。帯は `ResultAlert` のまま。

### 最小対応幅（360px）
- カードの内幅は 360 − ページ余白 16×2 − 内側余白 16×2 − 枠 1×2 = 294px。
- 受け取りの枠の内幅は 294 − 内側余白 16×2 − 枠 1×2 = 260px。「画像を選ぶ」（約 126px）は1行に収まる。説明は折り返す。
- フォームのボタンの行: 「登録」（最小 96px）＋間隔 8px＋「飛ばす」（約 74px）＝約 178px で、294px に収まる。
- スキルの行の並び（Combobox・Lv・空にするボタン）は変えない。印は行の下に置くので、行の幅は増えない。
- 切り抜きは幅 294px に縮めて縦横比を保つ。読み取らなかった画像の帯のファイル名は折り返し、切り詰めない。

## 受入基準との対応
| AC | 画面での表れ |
|---|---|
| AC-1 | 入力規則の受け取る経路・状態の「読み取り中」「待ち列あり」 |
| AC-2 | 読み取らなかった画像の帯の「20 枚を超えた」 |
| AC-3 | 読み取らなかった画像の帯の「16:9 でない」「画像として読めない」 |

| AC-9 | 状態の「準備中」（最初の読み取りで読み込む） |
| AC-10 | 状態の節の破棄・1件を終えたら画像を捨てる |
| AC-11〜15 | 画面に表れない（テスト・測定・記録） |
