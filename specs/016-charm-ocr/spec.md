# 016: charm-ocr

## 目的 / ユーザーストーリー
プレイヤーとして、手持ちの鑑定護石を1件ずつ手で入力する代わりに、PC 版の護石の詳細画面のスクリーンショットを何枚かまとめて渡し、読み取った内容を確かめて直したうえで護石一覧に登録したい。画像はサーバーへ送らず、ブラウザの中だけで読み取ってほしい。

OCR は 015 ocr-spike の Tesseract.js を使い続け、読み取り結果は登録のフォームに仮に入れるだけにして、登録の前にユーザーが確かめて直す（decisions.md Q117）。

用語:
- 読み取り結果: 1枚の画像から読んだ護石のスキル（スキルと Lv）とスロット（武器用・防具用の別と Lv）の並び。レア度は読まない（decisions.md Q160）。読めなかった行は空欄（`null`）にする。015 の `CharmReadResult`。
- 待ち列: 1回に渡した画像の読み取り結果を、渡した順に並べたもの。先頭の1件ずつ登録のフォームに仮入力する（decisions.md Q161）。
- 誤った値で埋めた行: 読み取り結果のうち、空欄でなく、正解ラベルと違うスキル・Lv・スロットの別・スロットの Lv が入った行（decisions.md Q117）。

## 受入基準（EARS記法）
- AC-1: WHEN ユーザーが護石の画面で、ファイル選択・クリップボードの貼り付け・ドラッグ＆ドロップのいずれかで1枚以上の画像を渡したとき THE system SHALL 渡された画像をブラウザ内で順に読み取り、読み取り結果を渡した順に待ち列へ並べなければならない（decisions.md Q161・Q162）。
- AC-2: IF 1回に渡された画像が 20 枚を超えるとき THEN システムは、渡された順の先頭の 20 枚だけを読み取り、読み取らなかった枚数と理由を表示しなければならない（decisions.md Q163）。
- AC-3: IF 渡された画像が 16:9 でない、または画像として読めないとき THEN システムは、その画像を読み取らずにファイルごとの理由を表示し、ほかの画像の読み取りを続けなければならない（decisions.md Q164）。
- AC-4: WHEN 待ち列に読み取り結果があるとき THE system SHALL 先頭の1件のスキルとスロットを登録のモードのフォームに画面の表示順のまま仮入力し、レア度を未選択にし、待ち列の残りの件数を表示しなければならない（decisions.md Q160・Q161）。
- AC-5: THE system SHALL 読み取れなかったスキルとスロットの行を推測で埋めず空欄のまま仮入力し、読み取れなかった行があることをフォームに示さなければならない。
- AC-6: WHEN ユーザーが仮入力したフォームから護石を登録して保存に成功したとき、または「飛ばす」を選んだとき THE system SHALL その1件を待ち列から除き、次の1件を仮入力しなければならない。登録には既存の登録と同じ検査（構造上の制約と抽選テーブルの照合）と保存先（端末・アカウント）を使い、API を変えてはならない（decisions.md Q161）。
- AC-7: THE system SHALL スキルを枠ごとに認識し、ある枠を読めなかったときも、以降の枠のスキルを前の位置に詰めず、その枠を空欄として返さなければならない（015 handoff.md の持ち越し）。
- AC-8: IF Tesseract.js の初期化または読み取りに失敗したとき THEN システムは、作りかけの worker を終了して残さず、読み取れなかったことと理由を表示し、手入力での登録を引き続き使えるようにしなければならない（015 handoff.md の持ち越し）。
- AC-9: THE system SHALL Tesseract.js の worker・WASM コア・言語データを、最初の読み取りのときに自オリジンから読み込み、護石の画面を開いただけでは読み込んではならない（decisions.md Q165・015 decisions.md Q112）。
- AC-10: THE system SHALL 画像をサーバーへ送らず、IndexedDB などの端末内の保存先にも書かず、待ち列の1件を終えたらその画像への参照を捨て、護石の画面を離れたら待ち列と Tesseract.js の worker を破棄しなければならない（憲法・decisions.md Q165）。
- AC-11: THE system SHALL 画像の受け取り・待ち列・仮入力・登録と「飛ばす」の流れを、ゲームの画像を使わずに CI で実行する単体テストと e2e テストで検査しなければならない（015 decisions.md Q108）。
- AC-12: WHEN 測定を実行したとき THE system SHALL 015 の画像と正解ラベル（20 枚）で、画像ごとの誤った値で埋めた行と空欄の行・1枚の認識時間と、全体の誤った値で埋めた行の数・完全一致率・1枚の認識時間の最大・初期化の時間を出力しなければならない（decisions.md Q117）。
- AC-13: THE system SHALL 誤った値で埋めた行が 0 件かつ1枚の認識時間の最大が 3 秒以内のときに合格と判定し、完全一致率を合否に使ってはならない（decisions.md Q117）。
- AC-14: WHEN 測定を実行したとき THE system SHALL 測定中のリクエストに、自オリジン以外へのリクエストか、GET 以外のメソッドのリクエストがあれば失敗にしなければならない（AC-10 の確認。015 handoff.md の持ち越し）。
- AC-15: THE system SHALL 再測定の結果（AC-12 の項目・合否・測定環境・版）と Tesseract.js の採用を `design/tech-stack.md` に記録しなければならない（decisions.md Q117）。

## スコープ外
- 読み取り結果を一覧の確認画面に並べて、まとめて直して一括で登録すること（decisions.md Q161）
- レア度の読み取り（decisions.md Q160）
- 既存の護石の編集のモードへの仮入力（読み取り結果は登録のモードにだけ入れる）
- 読み取った護石と登録済みの護石の重複の検出
- 家庭用機のキャプチャ・画面をスマホで撮った写真・英語の画面・1枚に複数の護石が写る画像（015 decisions.md Q109・Q114）
- 1920x1080 以外の解像度の精度の測定（16:9 なら読み取りはする。decisions.md Q164）
- 別の OCR エンジンへの切り替え・読み取り範囲の手動指定（decisions.md Q117）
- PWA としてのオフライン配信（018）

## 契約差分
- なし（API を変えない。OCR はブラウザ内で動き、登録は既存の護石の保存を使う）

## 影響範囲
触る領域: web
