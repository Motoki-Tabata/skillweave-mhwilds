# 020 armor-lock-exclude の決定記録

## Q79（決定: 2026-10-28）
- 問い: 装飾品の除外をどう扱うか。`packages/solver` の `SolverRequest` には防具の固定（`fixedArmor`）と除外（`excludedArmorIds`）しか無く、装飾品を除外する入力が無い（機能マップの 020 の「ソルバーは 003 で対応済み」は装飾品には当たらない）。
- 決定: 020 で `packages/solver` も直す。`SolverRequest` に `excludedDecorationIds?: DecorationId[]` を足し、除外した装飾品を候補（変数）から外し、マスターに無い ID を要求の検証で弾く。機能マップの 020 の「1行の価値」の文言も直す。
- 理由: ソルバーの変更は候補の絞り込みと検証に1条件を足すだけで小さい。装飾品の除外を別の機能に分けると、同じ検索画面の同じ入力の欄を2回作り直すことになる。触る領域は web と packages の 2 つで、上限の 3 つに収まる。

## Q80（決定: 2026-10-28）
- 問い: 固定した防具が、候補にするランクの絞り込み（004 Q21）で外れるランクの防具だったときにどうするか。ランクの絞り込みは `apps/web` のアダプタが `excludedArmorIds` に入れて実装しており、そのままでは、ソルバーが「固定と除外の両方に指定されている」として要求を弾く。
- 決定: 固定を優先する。固定した防具は、ランクの絞り込みによる除外の対象から外す。固定の候補には、選んでいるランクにかかわらず、その部位の全防具を出す。
- 理由: 部位を固定するのは、その防具を使うと決めたときなので、ランクの絞り込みより明示の指定を優先するのが自然。候補をランクで絞る案は、ランクを切り替えるたびに固定が外れ、入力が消える。

## Q81（決定: 2026-10-28）
- 問い: 固定・除外の設定を、再読み込みの後も残すか。
- 決定: 保存しない。004 Q23（検索条件は保存しない）に揃え、再読み込みすると既定（固定なし・除外なし）に戻る。
- 理由: 検索条件のほかの項目と扱いを揃える。端末内の保存を足すと、マスターの版が変わって ID が消えたときの扱いなどが増え、M に収まりにくい。

## Q82（決定: 2026-10-28）
- 問い: 固定・除外を入力する導線をどこに置くか。
- 決定: 検索条件の欄（検索画面の入力のフォーム）にだけ置く。部位ごとに防具か「何も付けない」を選ぶ「部位の固定」と、防具・装飾品を探して足し、一覧から外せる「除外」を足す。検索結果の構成のカードには、固定・除外の操作を付けない。見た目・位置・部品は区間 B で決める。
- 理由: 結果のカードにも操作を付けると、結果の表示の部品（`ResultBuildCard.vue` など）にも手が入り、サイズが大きくなる。結果から絞り込む導線は、使ってみて要るとわかってから足す。
