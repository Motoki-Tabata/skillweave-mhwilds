# 021: crafted-charm

## 目的 / ユーザーストーリー
プレイヤーとして、鑑定護石を1つも登録していなくても、生産護石（素材で作れる、スキルが固定の護石）を含めた構成を検索で探したい。生産護石は作れば手に入るので、防具と同じく「すべて持っている」とみなして候補にしてほしい。生産護石を使いたくないときは、まとめて候補から外せるようにしたい。

用語:
- 生産護石: マスターの `charms`（ID は `CharmId`。例: `ch:-1137475456:3`）。`ch:<gameId>:<ランク>` の `gameId` が同じものを1つの系統と呼ぶ。マスター 2026.10.4 では 60 系統・183 件で、どの系統でも上位ランクが下位ランクのスキルとスロットを包含する（decisions.md Q77）。
- 鑑定護石: 005 で手入力して登録する護石（ID は UUIDv7）。

## 受入基準（EARS記法）
- AC-1: THE system SHALL `packages/solver` の `SolverCharm.id` と `SolvedBuild.charmId` の型を `Uuid | CharmId` に広げ、渡された護石の ID を求解の処理で読まずに、構成が使った護石の ID として `charmId` にそのまま返さなければならない（decisions.md Q31）。
- AC-2: THE system SHALL 検索画面の護石の節に「生産護石を候補に含める」の切り替えを置き、既定をオンにしなければならない（decisions.md Q31）。
- AC-3: WHEN 切り替えがオンで検索を実行したとき THE system SHALL マスターの生産護石を系統ごとに最上位ランクの1件だけ選び、登録した鑑定護石の候補とあわせて `SolverRequest.charms` に渡さなければならない。下位ランクの生産護石は渡してはならない（decisions.md Q77）。
- AC-4: WHEN 切り替えがオフで検索を実行したとき THE system SHALL 生産護石を候補に含めず、登録した鑑定護石の候補だけを渡さなければならない（鑑定護石が無ければ護石なしで解く。005 と同じ）。
- AC-5: THE system SHALL 検索の前に、検索画面の護石の節で、候補にする鑑定護石の件数と、生産護石を候補に含めるかどうかが分かるように表示し、結果の検索条件の要約にも生産護石を含めたかどうかを示さなければならない。
- AC-6: IF 鑑定護石を読み込めない、または端末に保存できないとき THEN システムは、その旨を示したうえで、切り替えがオンなら生産護石だけを候補にして検索できなければならない。
- AC-7: WHEN 結果の構成が生産護石を使っているとき THE system SHALL 構成のカードの護石の節に、その生産護石の名前（ja の辞書の名前）を、レア度・スキル・スロットとともに表示しなければならない。鑑定護石を使った構成の表示は変えてはならない（decisions.md Q31）。
- AC-8: IF 結果の構成が生産護石を使っているとき THEN システムは、その構成のカードに保存の操作を出さず、生産護石を使った構成は保存できない旨を示さなければならない。鑑定護石を使った構成と護石なしの構成は、これまでどおり保存できなければならない（decisions.md Q78）。
- AC-9: THE system SHALL 系統ごとに最上位ランクを選ぶ処理が、上位ランクが下位ランクを包含することを前提にしていることを、単体テストで示さなければならない（decisions.md Q77）。
- AC-10: THE system SHALL 生産護石を候補に含めた検索の所要時間を `packages/solver` の測定（`--mode measure`）で測り、`design/tech-stack.md` に記録しなければならない。基準を超えても 021 では高速化しない（decisions.md Q77）。
- AC-11: THE system SHALL Playwright（Chromium）の e2e テストで、「鑑定護石を登録せずに、生産護石を使った構成が検索で表示され、その構成に保存の操作が出ない」流れと、「切り替えをオフにすると生産護石が候補に入らない」ことを検証しなければならない。

## スコープ外
- 生産護石を使った構成の保存と、保存した構成の画面での表示（027 crafted-charm-build-save。decisions.md Q78）
- 生産護石の系統ごとの所持の入力・保存と、系統ごと・ランクごとに候補から外す切り替え（decisions.md Q31）
- 結果に出す生産護石のランクを、構成に足りる最小のランクへ下げること（decisions.md Q77）
- 生産護石の包含の関係をパイプラインで検査すること（要否は区間 C で決める。decisions.md Q77）
- 生産護石を候補に含めたことによる求解の高速化（024 worker-solve-perf。decisions.md Q77）
- 生産護石の作り方（素材）の表示
- 検索画面のレイアウトの変更（open-questions.md Q28）

## 契約差分
- なし（API を変えない。生産護石を使った構成は保存させないので、構成の保存の契約 `BuildCharm` も変えない。decisions.md Q78）
