## 0. 前提

- 構成の火力は `packages/solver` の構成の計算（`damage.ts`）が、物理（期待値・攻撃力・会心率・会心倍率）に加えて、武器の属性に応じた値を返す（spec AC-1〜AC-3）。
  - 5 属性（火・水・雷・氷・龍）の武器: 属性値と属性期待値。
  - 状態異常（毒・麻痺・睡眠・爆破）の武器: 強化後の蓄積値。
  - 属性を持たない武器・属性が分からない武器: どちらも無い（AC-4）。
- ソルバーはマスターの単位（表示値 ÷ 10）で計算し、丸めない。画面は表示値（マスターの単位 × 10）に直してから、007 の火力と同じ丸め（小数第1位）で出す（decisions.md Q206）。
- 属性の種類の表示名は `constants/weapons.ts` の表示名（「火属性」…「爆破属性」）を使う。値のラベルは、MASTER.md「スキルの説明と補完」の区別の表示名に「値」を付けた形（「火属性値」「毒属性値」）にそろえる。
- 物理の期待値のラベルは「期待値」のまま変えない（目的の補助文が「物理の期待値」と説明している）。
- 構成カード（`BuildCard.vue`）は、検索結果・逆引きの候補・保存した構成・共有した構成で共通なので、構成カードの変更は 4 つの画面に同時に効く（AC-5）。
- 数値は Inter と `tabular-nums` にする。文字サイズは MASTER.md の Type Scale の4つだけを使う。
- 023 で新しく作る部品は無い。既存の生成物（RadioGroup・Label・Card）と、既存の補助テキスト・エラーの表示だけで作る。shadcn-vue の部品は足さない。

## 2. S1 検索画面「検索条件」カード

### 2.1 目的の選択肢

目的の RadioGroup の末尾に、5つ目の選択肢を足す。

| 選択肢 | 補助文（12px・`--muted-foreground`） | 要求 |
|---|---|---|
| 属性の最大化 | 属性期待値が大きい順に探します。「発動条件」でオンにした効果を数えます。 | 属性の最大化の目的（要求の形は区間 C で決める） |

既定は「条件を満たす構成」のまま。他の4つの選択肢と補助文は変えない。検索条件の要約（007 の 2.5.1）の「<目的>」には「属性の最大化」と出る。

### 2.2 選べないとき（AC-9）

武器の属性が 5 属性のどれでもないかは、検索条件で選んでいる武器（`stores/conditions.ts` の解決済みの武器。マスターの武器の `element`、または個体差のある武器の `element`）で決める。

| 状態 | 「属性の最大化」の選択肢 | 表示 |
|---|---|---|
| 武器を選んでいない | 選べる | 補助文だけ（検索は 004 のとおり「武器を選んでください」で止まる） |
| 5 属性の武器を選んでいる | 選べる | 補助文だけ |
| 無属性・状態異常の武器を選んでいて、目的が他の選択肢 | 選べない（`RadioGroupItem` を `disabled`。ラベルも無効の見た目） | 補助文の下に、選べない理由（12px・`--muted-foreground`）を出し、`aria-describedby` に補助文と理由の両方を入れる |
| 属性の最大化を選んだ後に、無属性・状態異常の武器へ選び直した | 選択を残す（自動で他の目的に戻さない）。選択中の選択肢は無効にしない（フォーカスとエラーの結び付きを保つため） | 目的の RadioGroup の直下にエラー（14px・`--destructive`。ランクのエラーと同じ見た目）を出し、RadioGroup の `aria-describedby` に結ぶ。選択肢の下の理由は出さない（エラーと重複するため）。「検索」を無効にし、検索操作の理由の行に理由を出す |

- エラーは、武器を変えた時点で出す（ラジオの変更は確定の操作なので、MASTER.md の Forms の「検証タイミング」の例外に当たる）。目的を他の選択肢に変えるか、5 属性の武器に選び直したら、すぐ消して「検索」を有効に戻す。
- 「検索」を無効にする理由の優先は、武器を選んでいない → ランクを選んでいない → 目的と武器が合わない、の順にする（`unavailableReason` の既存の順の末尾に足す）。
- 「護石を逆引き」は目的を使わないので、このエラーでは止めない。

### 2.3 項目定義・文言

| 箇所 | 文言 |
|---|---|
| 選べない理由（選択肢の下） | 選んだ武器（<属性の表示名>）では選べません。火・水・雷・氷・龍属性の武器で選べます。 |
| エラー（目的の直下） | 選んだ武器（<属性の表示名>）では、属性の最大化で探せません。目的を選び直すか、火・水・雷・氷・龍属性の武器を選んでください。 |
| 「検索」を無効にする理由（検索操作の理由の行） | 目的の「属性の最大化」は、火・水・雷・氷・龍属性の武器でだけ探せます。 |

- <属性の表示名> は、無属性の武器では「無属性」、状態異常の武器では「毒属性」「麻痺属性」「睡眠属性」「爆破属性」。

### 2.4 キーボード・フォーカス・読み上げ

- 無効の選択肢は、RadioGroup の矢印キーの移動で飛ばす（Reka UI の既定）。選択中のまま選べなくなった選択肢は無効にしないので、フォーカスが行き場を失わない。
- エラーと理由の表示はライブリージョンにしない（ランクのエラーと同じ）。フォーカスは動かさない。

## 3. 構成カード（S1・S2・S3 共通）

### 3.1 見出し行

```
5 属性の武器:   「構成 N」(16px)      期待値 <n.n>   属性期待値 <n.n>   防御力 <合計>
状態異常・無属性: 「構成 N」(16px)      期待値 <n.n>   防御力 <合計>            ← 007 のまま
```

| 項目 | 内容 |
|---|---|
| 属性期待値 | 5 属性の武器のときだけ、「期待値 <値>」と「防御力 <合計>」のあいだに「属性期待値 <値>」を出す。値は 14px・太字・Inter（期待値と同じ）。目的を問わず出す |
| 状態異常の武器 | 見出し行には蓄積値を出さない（最大化の対象でないため。火力の節だけに出す） |

### 3.2 火力の節

```
5 属性の武器（火属性の例）:
火力
  期待値      攻撃力      会心率      会心倍率
  312.5       250.0       35%         1.40
  属性期待値  火属性値
  400.0       380.0
  火属性値は、スキルによる強化の上限を考えずに計算しています。（12px）

状態異常の武器（毒属性の例）:
火力
  期待値      攻撃力      会心率      会心倍率
  280.0       230.0       10%         1.25
  毒属性値
  320.0
  毒属性値は、スキルによる強化の上限を考えずに計算しています。（12px）

無属性の武器・属性が分からない武器: 007 のまま（1行目の4値だけ。注記も出さない）
```

| 項目 | 内容 |
|---|---|
| 並べ方 | 007 の `<dl>`（4列の格子）に、属性の値を2行目として足す。2行目の列は1行目にそろえる（列の幅・間隔は1行目と同じ） |
| 属性期待値（5 属性） | 2行目の1列目（期待値の真下）。`dt`「属性期待値」は 12px・`--muted-foreground`。`dd` は 16px・太字（期待値と同じ） |
| 属性値（5 属性） | 2行目の2列目（攻撃力の真下）。`dt`「<属性の表示名>値」（例: 「火属性値」）。`dd` は 14px |
| 蓄積値（状態異常） | 2行目の1列目。`dt`「<属性の表示名>値」（例: 「毒属性値」）。`dd` は 14px（期待値ではないので太字にしない） |
| 2行目の残りの列 | 空けておく（物の置かれない列。`dt`・`dd` を置かない） |
| 丸め | 表示値（マスターの単位 × 10）を小数第1位に四捨五入する（007 の期待値・攻撃力と同じ。`formatDamageValue`）。負の値は半角の `-`。並び順はソルバーが返した順のままにし、丸めた値で並べ直さない |
| 上限の注記（AC-6） | `<dl>` の直下に、12px・`--muted-foreground` で「<属性の表示名>値は、スキルによる強化の上限を考えずに計算しています。」を出す。属性の値を出すときだけ出す |
| 計算の入力 | 007 のとおり（検索したときの武器・構成の発動スキル・検索したときにオンだった条件）に、武器の属性（種類と値）を足す。保存した構成・共有した構成は `lib/solver/buildView.ts` が解決した武器の属性を使う |
| 属性が分からないとき（AC-4） | 保存した構成の武器が今のマスターに無いときは、007 のまま「武器が現在のマスターに無いため、火力を計算できません。」だけを出す。物理が計算できて属性だけが分からない場合は、属性の行と注記を出さない |

- 検索の後に武器やトグルを変えても、カードの属性の値は変えない（007 と同じく、検索したときの武器と条件で固定する）。
- 逐次表示（007 の 2.5.3）で届いた構成のカードにも、届いた時点で属性の値を出す。
- 読み上げの順は、1行目の4値 → 2行目 → 注記（DOM の順のまま）。

## 6. MASTER.md の変更

spec.md の「常時許可外の変更予定」のとおり、`design-system/skillweave/MASTER.md` の Component Specs「火力の表示」を、3.2 の内容に合わせて直す（書く時期は plan で決める）。

- 武器の属性に応じて、`<dl>` の2行目に属性期待値と属性値（5 属性）、または蓄積値（状態異常）を、1行目の列にそろえて並べること。ラベル・文字の大きさ・太字の扱い。
- 属性の値は表示値（マスターの単位 × 10）を小数第1位に丸めること。
- 属性の値を出すときは、`<dl>` の直下に強化の上限を考えていない旨の注記（12px・`--muted-foreground`）を出すこと。

「用語の統一」に「属性期待値」（属性値 × 属性の会心補正）を足す。
