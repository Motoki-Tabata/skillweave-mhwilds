# 023: element-damage

## 目的 / ユーザーストーリー
プレイヤーとして、属性の武器で組んだ構成について、物理の期待値だけでなく、スキルで強化した後の属性値と属性期待値を結果の火力で確かめたい。さらに、属性期待値の大きい順に構成を探したい。状態異常の武器では、強化した後の蓄積値を確かめたい。今の火力は物理（攻撃力・会心率・会心倍率）だけを数えている（006 decisions.md Q35）。そのため、属性攻撃強化・会心撃【属性】などを積んだ構成の差が数字に出ない。

用語:
- 5 属性: 火・水・雷・氷・龍（マスターの `element.type` の `fire`・`water`・`thunder`・`ice`・`dragon`）。状態異常: 毒・麻痺・睡眠・爆破（`poison`・`paralysis`・`sleep`・`blastblight`）。
- 武器の属性: マスターの武器の `element`。個体差のある武器は `SolverWeapon` の `custom` の `element`（008 で保存する値）。単位はマスターの単位（表示値 ÷ 10）。
- 有効な効果: 発動スキルのレベルの効果のうち、発動条件と武器種の絞り込み（`isCounted`。043）を通るもの。
- 種類が合う効果: `element` が武器の属性の種類と一致する効果、または `element` を省略した効果（`design/master-data.md` §6）。
- 属性の最大化: 新しく足す目的関数。属性期待値の大きい順に構成を返す（decisions.md Q183）。

画面に出す値の出どころ: 属性値・属性期待値・蓄積値は、`packages/data` が生成する JSON（武器の `element`・スキルの `effectsByLevel`）から、ソルバーの関数（`packages/solver/src/main/damage.ts` の構成の計算）が求める。武器の属性は、検索画面と逆引きでは `stores/conditions.ts` の解決済みの武器（マスターの武器、または `custom` の `element`）から取る。保存した構成・共有した構成では、`lib/solver/buildView.ts` がマスターの武器か、保存した個体差のある武器の `element`（既存の契約 `CustomWeaponPayload.element`）から取る。API の応答に新しい値は要らない。

## 受入基準（EARS記法）
- AC-1: THE system SHALL 構成の属性値を「武器の属性値 × 有効で種類が合う `element_mul` の値の積 ＋ 有効で種類が合う `element_add` の値の和」で計算しなければならない。順序は攻撃力（006 decisions.md Q35）に揃え、強化の上限は設けてはならない（decisions.md Q40）。
- AC-2: THE system SHALL 属性期待値を「属性値 × 属性の会心補正」で計算しなければならない。属性の会心補正は、会心率が 0 より大きければ「1 ＋ 会心率 ÷ 100 ×（属性の会心倍率 − 1）」、0 以下なら 1 とする。属性の会心倍率は、有効な `element_crit_mul` の最大とし、無ければ 1 とする。会心率は、物理と同じく −100〜100 に丸めた値を使う。ソルバーは丸めてはならない（decisions.md Q40・Q184）。
- AC-3: WHERE 武器の属性が状態異常である THE system SHALL 強化後の蓄積値を「武器の値 × 有効で種類が合う `status_mul` の積 ＋ 有効で種類が合う `status_add` の和」で計算しなければならない。会心の補正はかけず、どの目的関数の最大化にも使ってはならない（decisions.md Q40）。
- AC-4: IF 武器が属性を持たない、または武器の属性が分からない（保存した構成の武器が今のマスターに無いなど）THEN システムは、属性値・属性期待値・蓄積値を計算せず、表示もしてはならない。物理の期待値の表示は今のままにする。
- AC-5: WHEN 構成の火力を表示するとき THE system SHALL 物理の期待値・攻撃力・会心率・会心倍率に加えて、次を表示しなければならない。5 属性の武器では属性値と属性期待値、状態異常の武器では強化後の蓄積値を出す。目的関数を問わず出し、値は表示値（マスターの単位 × 10）にする。丸めは 007 の火力の表示と同じにする（decisions.md Q183・Q206）。対象の画面は、検索結果・逆引きの候補・保存した構成・共有した構成のすべてとする。
- AC-6: WHERE 属性値または蓄積値を表示する THE system SHALL その近くに、属性値・状態異常値の強化の上限を考えていないことを注記しなければならない（decisions.md Q40）。
- AC-7: WHEN 目的関数が属性の最大化のとき THE system SHALL 必須スキルを満たす構成のうち、属性期待値が最大のものから順に返さなければならない。2 件目以降は、それまでに返した構成を除いた中での最大を返す。同点の構成では、防具用の空きスロットの Lv の合計が大きいもの、次に武器用の空きスロットの Lv の合計が大きいものを選ぶ。数える効果は、検索画面の「発動条件」でオンにした条件の下で有効なものとする（decisions.md Q183・006 decisions.md Q36）。
- AC-8: IF 属性の最大化の要求で、武器の属性が 5 属性のどれでもない THEN ソルバーは、003 decisions.md Q18 と同じく不正な要求としてエラーを返さなければならない（decisions.md Q183）。
- AC-9: WHERE 選んだ武器の属性が 5 属性のどれでもない THE system SHALL 検索画面の目的で属性の最大化を選べなくし、選べない理由を示さなければならない。属性の最大化を選んだ後に武器を変えて選べなくなったときの扱いは、区間 B で決める（decisions.md Q183）。
- AC-10: THE system SHALL 既存の目的関数（`feasible`・`defense`・`freeSlots`・`expectedDamage`）の結果（構成・並び・物理の期待値）を変えてはならない。`expectedDamage` は、属性を足さない物理の期待値のままにする（decisions.md Q183）。
- AC-11: THE system SHALL `packages/solver` のテストで、次を確かめなければならない。属性の最大化の結果の並びが、小さな手作りのマスターで全構成を総当たりして求めた属性期待値の順と一致すること。構成の計算（AC-1〜AC-3）が、種類の不一致・`element` の省略・発動条件・武器種の絞り込み・会心率が負と 100 超の場合を含めて正しいこと。
- AC-12: WHEN 属性の最大化で検索の時間を測るとき THE system SHALL 実データを使い、`design/tech-stack.md` の既存の画面の測り方で測らなければならない。測り方は、発動条件をすべてオン、生産護石のオンとオフの両方、6 ケース × 各 3 回、`pnpm --filter @swv/web run measure --workers=1` とする。結果は `design/tech-stack.md` に記録する。IF 1 件目までの時間の最大が 5 秒を超えたなら THEN システムは、区間 D を止めて報告しなければならない。5 秒は、Q183 が引く 006 の基準を 019 decisions.md Q41・024 decisions.md Q50 で読み替えた現行の基準である。
- AC-13: THE system SHALL `design/master-data.md` §9 の「023 element-damage の前提の確認」を、決定に合わせて書き換えなければならない。説明文の属性値の単位は decisions.md Q205、負会心は Q184 の確定に揃える。

## スコープ外
- 物理と属性の合算（肉質・モーション値の仮定を要する。decisions.md Q183）
- 属性値・状態異常値の強化の上限の計算（注記だけにする。decisions.md Q40）
- 状態異常の会心（`status_crit_mul`。会心撃【特殊】）と、蓄積値の最大化（decisions.md Q40）
- ボウガンの弾と弓のビンの属性（decisions.md Q40）
- 会心撃【属性】の重い 6 武器種の Lv1・Lv2 など、マスターで値が空の効果を補う注記・計算（decisions.md Q207。値は 044 などで入れる）
- 説明文に数値が無い効果の値の追加（038・043・044 の範囲）
- 目的関数や火力の結果の保存（保存した構成・共有した構成の形は変えない）
- `expectedDamage` の性能の改善

## 契約差分
- なし（属性の計算はブラウザ内のソルバーで行う。保存した個体差のある武器の属性は、既存の `CustomWeaponPayload.element` で足りる。目的関数は保存しない）
