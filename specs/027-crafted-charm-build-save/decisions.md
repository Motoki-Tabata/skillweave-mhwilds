# 027 crafted-charm-build-save の決定記録

## Q92（決定: 2026-10-29）
- 問い: 構成の保存の契約 `BuildCharm` の形をどうするか。いまの `BuildCharm` は `{id, payload}`（`id` は `format: uuid`、`payload` は `CharmPayload` でレア度 5〜8）で、生産護石の ID（`CharmId`。例: `ch:-1137475456:3`）も、生産護石のレア度（マスター 2026.10.4 で 2〜8）も通らない（021 decisions.md Q78）。
- 決定: 鑑定護石の形 `{id, payload}` は変えず、生産護石の形 `{kind: 'crafted', charmId}` を `oneOf` で足す。`schemaVersion` は 1 のままにする。`charmId` は生産護石の ID の形（接頭辞 `ch:`・系統の数値・ランクの数値）だけを検査し、マスターにあるかどうかはサーバーで検査しない（011 decisions.md Q68 と同じ）。
- 理由: 足すだけなら、保存済みの行（鑑定護石の形）とそのまま互換で、版を上げて読み出し時に変換する処理（`design/data-model-standard.md`「jsonb と `schema_version`」）が要らない。両方に `kind` を付ける案は、構成の武器（`BuildWeapon`）と書き方がそろうが、版 1 の行の変換が API か Web に増える。`id` の形を広げる案は差分が最小だが、同じ形の中で ID の種類によって検査の規則（レア度の範囲など）が変わり、読みにくい。

## Q93（決定: 2026-10-29）
- 問い: 生産護石を使った構成には、護石について何を保存するか。鑑定護石は ID の参照と内容の写しの両方を持つ（011 decisions.md Q64）。
- 決定: 生産護石の ID の参照（`charmId`）だけを保存し、写しは持たない。保存した構成の画面では、護石の名前・レア度・スキル・スロットを、開いたときのマスターと辞書から ID で引く。いまのマスターにその ID が無ければ、不明な護石である旨を ID とともに示す（防具・武器などの「不明な〜（ID）」と同じ）。マスターの版が保存したときと違う旨は、既存の版の違いの警告に任せる。
- 理由: 生産護石はマスターの値なので、マスターの武器・防具（ID だけを保存して開いたときに引く。011 decisions.md Q63）と同じ扱いにそろえる。写しを持つと、生産護石の写しのための専用のスキーマ（レア度 2〜8）が要る。鑑定護石が写しを持つ理由（ユーザーが後から編集・削除できる、別の端末で引けない）は生産護石には当たらない。
