## フッター（`CreditBar`）

### 画面構成
1行のバーの左に出典、右端にリンクを置く。

```text
| 出典: LartTyler/mhdb-wilds-data @abc1234          プライバシー |
```

出典の文言・切り詰め方（リポジトリ名だけを省略記号で切り詰める）・`footer` の `aria-label` と `title` は変えない。

### 項目定義
| 項目 | 内容 |
|---|---|
| 部品 | `RouterLink`（`to="/privacy"`） |
| 文言 | `プライバシー`（補助テキストの大きさ・ウェイト 400・`--foreground`） |
| リンクの手がかり | 常に下線を付ける（色だけに頼らない） |
| `title` | `プライバシーの表記を開く`（`footer` の `title` の出典の説明が、リンクの上に出ないようにする） |
| 操作領域 | 高さはバーと同じ。左右に余白を 8px ずつ取り、右の余白はバーの内側余白に重ねて、文字の右端をページの余白にそろえる |
| フォーカス | `--ring` のリングを内側に出す（画面の下端で切れないようにする） |
| `/privacy` にいるとき | `aria-current="page"` が付く。見た目は変えない |
| 切り詰め | リンクは切り詰めず、折り返さない |

### 操作領域の高さ
リンクの高さはバーと同じにし、MASTER.md の操作領域の 44px にはそろえない。

- 採る理由: 別ページへの1本のリンクで、頻繁に押す操作ではない。バーと同じ高さなら WCAG 2.2 の 2.5.8（24×24px）を満たす。
- 44px の透明な領域を上へ広げる案は採らない。固定のバーの上に重なり、スクロールして通る本文のタップを奪う。
- バーを高くする案は採らない。MASTER.md の画面骨格と全画面の余白に波及する。

### 最小対応幅での幅の概算（360px）
使える幅はページの余白を除いた 328px。

| 要素 | 幅の目安 | 切り詰め |
|---|---|---|
| `出典: ` | 31px | しない |
| リポジトリ名 | 165px（全文）・最小 80px | する |
| ` @abc1234` | 65px | しない |
| リンク（文字 72px + 左の余白 8px） | 80px | しない |

切り詰めないものの合計は 176px で、リポジトリ名に 152px が残る。いまの名前は 360px で末尾が少し切り詰められる。最小の 80px でも合計 256px で収まる。

## プライバシー（`/privacy`）

### 画面構成
1. 見出し `プライバシー`（`h1`）
2. 導入の文と最終更新日
3. 下の「表記の文面」の節を順に縦に並べる

- 枠は他の画面と同じコンテナを使い、見出しの左端がそろう。本文は読みやすさのため最大幅を 720px にし、`lg` でも左に寄せて1カラムのままにする。
- 文字の大きさは、`h1` が見出し、`h2` が小見出し、本文が基準、最終更新日が補助テキスト。
- カードで囲まず、節の間隔だけで区切る。差し色の面は使わない。

### 状態
静的な文章だけで、API もマスターデータも読まない。

| 状態 | 表示 |
|---|---|
| 未ログイン・ログイン中・認証状態の取得不能 | すべて同じ本文 |
| マスターの読込中・読込失敗 | 影響を受けない。本文をそのまま出す |
| 読込中・空・エラーの画面 | 無い |

### 遷移
| きっかけ | 結果 |
|---|---|
| フッターのリンク | 画面の先頭を表示し、フォーカスを `h1`（`tabindex="-1"`）へ移す。ルーターに `scrollBehavior` が無く、そのままでは前の画面のスクロール位置を引き継ぐため。ルーター全体の挙動は変えず、この画面の中で行う |
| URL の直接入力 | 同じ |
| ページのタイトル | `プライバシー \| SkillWeave` |

### リンク
本文のリンクはすべて常に下線を付ける。

| 文言 | 先 | 開き方 |
|---|---|---|
| Google Fonts の FAQ | `https://fonts.google.com/faq#privacy` | 新しいタブ（`rel="noopener noreferrer"`）。元の画面の検索結果などを失わないため。lucide の `ExternalLink` を添え、読み上げに「新しいタブで開く」を足す |

### 表記の文面
事実の正は decisions.md の Q135 の表。外部のログは「記録されることがあります」とし、Google 側の用途は断定しない。

**導入**

SkillWeave で、データがどこへ送られ、何が保存され、どう消せるかを説明します。

最終更新日: YYYY/MM/DD（値は実装のときに決める）

**この端末に保存するデータ**（AC-8）

装備検索の計算はブラウザ内で行います。次のデータはこの端末に保存します。

- 護石と個体差のある武器の下書き
- テーマの設定
- ログイン後に戻る画面

下書きは、ログインして取り込むとサーバーへ送られます。

**Discord でのログイン**（AC-4）

ログインで使うのは Discord の ID と表示名だけです。メールアドレスは受け取らず、アクセストークンは保持しません。Discord から受け取る項目のうち、保存するのは Discord の ID と、ログインの維持のために記録する表示名（最長 30 日）だけで、他の項目は保存しません。

**サーバーに保存するデータ**（AC-5）

ログイン中に保存した護石・構成・個体差のある武器・共有は、サーバーのデータベース（シンガポールなど日本国外）に保存します。データベースに IP アドレスは保存しません。

**データの削除**（AC-6）

画面から削除しても、データはデータベース上に残ります。完全に消去したいときは、下の連絡先へ依頼してください。

**共有**（AC-7）

共有した構成は、名前を含めて、URL を知っていれば誰でも読めます。共有の内容に Discord の ID や表示名は含まれません。

**Cookie**（AC-9）

- `SESSION`: ログインの維持
- `XSRF-TOKEN`: 不正な要求の防止

アクセス解析と広告は入れていません。

**Web フォント**（AC-3）

画面の文字に Google Fonts を使っています。フォントの読み込みで、IP アドレス・要求の URL・User-Agent などが Google に届きます。Google での扱いは [Google Fonts の FAQ] を確認してください。

**アクセスログ**（AC-10）

Cloudflare と Google Cloud のアクセスログに、IP アドレス・User-Agent・参照元・要求の URL などが記録されることがあります。Google Cloud のログの保持期間は、既定で 30 日です。Cloudflare での扱いは [Cloudflare のプライバシーポリシー] を確認してください。

**連絡先**（AC-11）

データの消去などの依頼は `contact@skillweave.app` へ送ってください。
