# 033: privacy-backup

## 目的 / ユーザーストーリー
利用者として、データの消去を依頼する前に、いつ消え、バックアップにいつまで、どんな形で残るかを `/privacy` で読みたい。依頼の結果を正しく判断するためである。運営者として、表記どおりに消去と復元を行えるよう、消去の手順とバックアップの消し方を `design/tech-stack.md` に持ちたい。

用語:
- 追記の文面: `/privacy` の「データの削除」節に足す文。文面の正は decisions.md Q143 である。
- 消去の記録: 消去した利用者の `users.id` を、リポジトリの外に残す記録（decisions.md Q144）。

## 受入基準（EARS記法）
- AC-1: THE system SHALL `/privacy` の「データの削除」節に、既存の2文を変えずに、依頼を受けてから 14 日以内を目安に消去することを書かなければならない（decisions.md Q143・Q145）。
- AC-2: THE system SHALL 同じ節に、バックアップを週に 1 回ほど取り、暗号化して、運営者が管理する保存先に保管することを書かなければならない。保存先の具体的な場所と事業者を書いてはならない（decisions.md Q146）。
- AC-3: THE system SHALL 同じ節に、消去の前に取ったバックアップには消去の後も約 4 週間データが残ること、取得が手作業なのでこの期間は前後することを書かなければならない。「最大」のように上限と読める語を、この期間に使ってはならない（decisions.md Q145）。
- AC-4: THE system SHALL 同じ節に、バックアップに画面から削除したデータと Discord の ID が含まれること、ログインの状態と表示名が含まれないことを書かなければならない（decisions.md Q147）。
- AC-5: THE system SHALL 同じ節に、復元したときは消去したデータを消し直すこと、そのために消去した利用者の内部の ID をバックアップが消えるまで記録することを書かなければならない（decisions.md Q144）。
- AC-6: THE system SHALL `/privacy` の節の並びを変えず、新しい節を足してはならない。
- AC-7: WHEN 表記の文面を変えたとき THE system SHALL 最終更新日を、変えた日の日付にしなければならない。
- AC-8: THE system SHALL `design/tech-stack.md` の「バックアップ」に、マイグレーションの前のダンプも世代に数えること、ダンプを取って確かめた後に、4 世代を超えたものと取得から 28 日を過ぎたものを消すことを書かなければならない（decisions.md Q145）。
- AC-9: THE system SHALL `design/tech-stack.md` に消去の手順を設け、1つのトランザクションで `spring_session` の該当行、`shares`、`builds`・`charms`・`weapons`、`users` の順に消すことと、消去の記録の書き方と残す期間を書かなければならない（decisions.md Q144）。
- AC-10: THE system SHALL `design/tech-stack.md` の「復元」に、Neon の復元とダンプからの復元のどちらでも、API を起動する前に消去の記録の利用者を消し直す工程を書かなければならない（decisions.md Q144）。
- AC-11: WHEN AC-9 の消去の手順を、マイグレーションを流した使い捨ての DB で、2人の利用者の護石・構成・武器・共有・セッションがある状態で実行したとき THE system SHALL 対象の利用者の行とセッションだけが消え、もう一人の行とセッションが残らなければならない。確かめた日と結果を `design/tech-stack.md` に書かなければならない。
- AC-12: THE system SHALL Web の単体テストで AC-1〜AC-7 を検証し、032 の AC-8 のテストをこの仕様の日付に合わせなければならない。
- AC-13: THE system SHALL Playwright（Chromium）の e2e テストで、`/privacy` を開くと「データの削除」の見出しとバックアップの説明が表示されることを検証しなければならない。
