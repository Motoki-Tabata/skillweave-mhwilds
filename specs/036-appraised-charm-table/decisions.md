# 036 appraised-charm-table の決定記録

## Q170（決定: 2026-11-15）
- 問い（`open-questions.md` からの移設）: 036 appraised-charm-table の抽選テーブルの出典をどれにするか。MHDB（`c50a1eb`）に抽選テーブルは無く、候補は攻略サイト・データマインの紹介記事・コミュニティ Wiki・オーナーとフレンドの手持ちの護石（`temp/appraised-charm-table.md` §5）。005 decisions.md Q3 で「攻略サイトのスクレイピングはしない」と決めており、どの候補にも再利用の許諾が見当たらない（Phantom Brawlers は規約で複製を禁止）。一次資料（Dtlnor 氏のデータマイン）の所在も未確認（仮: 権利面はオーナーが判断する。Monster Hunter Wiki のライセンスと Dtlnor 氏の元資料を先に確かめ、再利用できる出典が無ければ、オーナーが複数のサイトを読み比べて自分で表を作り、手持ちの護石で裏付ける形にする。出典と取得日は `design/master-data.md` に残す）
- 調べた結果（2026-11-15）: Monster Hunter Wiki（`MHWilds/Talismans`）の読めた範囲に抽選テーブルは無く、ライセンスのページは 404 で確かめられなかった。再利用できる出典は見つかっていない。リポジトリは公開なので、表は overlay と `dist/` を通じて公開される。
- 決定: 区間 D の最初のタスクで、エージェントが出典の候補のサイトを読み、抽選テーブル（パターン・スロットの並び・群の中身）の下書きを作る。オーナーが下書きの内容を確かめ、採用するかを決める。権利面の判断はオーナーが行う。
  - 005 decisions.md Q3（スクレイピングしない）は、この下書きに限って適用しない（オーナーの判断）。005 Q3 そのものは変えない。
  - サイトの取得は `curl` で HTML の全文を取って行う。要約や切り詰めのある取得手段で読まない（抜け漏れを防ぐため）。各ページを手で1回ずつ取得し、繰り返しの自動取得はしない。
  - Phantom Brawlers は、自らの規約でスクレイピングと大部分の複製を禁じているので、取得の対象から外す。
  - 取得した HTML と下書きはコミットしない（置き場は区間 C で決める）。
  - 採用した表について、読み比べたサイトと取得日を `design/master-data.md` に記録する。
  - オーナーが採用しないときは、区間 D を止めて出典の扱いを決め直す（017 も止まったままになる）。

## Q171（決定: 2026-11-15）
- 問い（`open-questions.md` からの移設）: 出典の間の食い違いをどう解くか。レア6 のパターン（mhw-blog は 6 件で A-G-J があり A-A-J と B-H-H が無い。gamerch・nettoge は 7 件）、レア7 B-A-G のスロット（mhw-blog は ②① を含む 4 種、gamerch は 3 種）、群の中身（砲術・B の Lv1 の 6 件・ボマー・G の環境適応系など）が食い違う（`temp/appraised-charm-table.md` §3.2〜§3.4）（仮: 手持ちの護石で裏付けられた側を採る。裏付けが無い食い違いは、多数のサイトが一致する側を採り、`design/master-data.md` に未検証として記録する）
- 決定: 次の順で採る。
  1. 手持ちの護石で裏付けられた側。
  2. 裏付けが無ければ、多数のサイトが一致する側。
  3. 同数のときは両方を入れる（和集合）。実在する護石に誤って「テーブル不一致」が出るのを避けるため。
- 2 と 3 で採った箇所は、`design/master-data.md` に未検証として記録する。

- spec.md の受入基準は、レア5〜8 のすべてではなく「表に入れたレア度」を対象に書く（外すレア度が出ても 036 をマージできるようにするため）。

## Q173（決定: 2026-11-15）

## Q174（決定: 2026-11-15）
- 問い（`open-questions.md` からの移設）: 同じ群が 2 枠に出るパターン（A-A-G・D-A-A・F-F など）で、同じスキルが重複しうるか。どのサイトも断定していない。今の照合（`apps/web/src/main/lib/charms/match.ts`）は枠ごとに群に含まれるかだけを見ており、重複を禁じていない（仮: 036 では重複を禁じない（今の照合のまま）。手持ちの護石に重複の例があれば「重複しうる」と確定する。「重複しない」と分かったら、照合の変更は触る領域 web が加わるので 036 に含めるか別の機能にするかをそのとき決め、017 のソルバーの候補の作り方にも反映する）
- 区間 A で判明: 005 decisions.md Q32 の構造上の制約（スキルは 0〜3 個で重複がない）により、同じスキルを 2 つ持つ護石は入力の時点で保存できない。照合（`match.ts`）に重複が届くことはないので、問いの前提（照合が重複を禁じていない）は実害を持たない。
- 決定: 照合（`match.ts`）は変えない。重複の禁止は 005 Q32 の入力の制約に任せる。017 の仮想の護石の候補も、同じスキルを重複させない（005 Q32 と同じ前提）。ゲーム内で同じスキルが重複する護石が見つかったら、005 Q32 の制約と 017 の候補の作り方を合わせて見直す。

## Q175（決定: 2026-11-15）
- 問い（`open-questions.md` からの移設）: 抽選テーブルの入力の形式と変換の手段。overlay はスキルを `sk:<gameId>` の ID で書くが、出典の表は日本語のスキル名で、群の中身は計 288 件ある（仮: オーナーが日本語のスキル名・レベルの表（CSV か Markdown）を用意し、ja 辞書で `sk:` の ID に直して overlay の YAML にする。変換は使い捨てのスクリプトで行い、パイプラインには組み込まない。変換できない名前は誤字として止める。憲法の「マスターデータを `packages/data` のパイプラインだけで生成する」は overlay を入力とするので満たす）
- 決定: Q170 の下書き（日本語のスキル名とレベルの表）を、使い捨てのスクリプトで ja 辞書から `sk:` の ID に直し、`packages/data/overlays/appraised-charm.yaml` に書く。YAML には日本語のスキル名をコメントで残す（`categories.yaml` と同じ）。
  - 変換できない名前があれば、その名前を示して止める（サイトの表記と辞書の表記の違いは、オーナーが確かめて直す）。
  - スクリプトと元の表はコミットせず、パイプラインにも組み込まない。`packages/data/scripts/` は使わない（どのワーカーの担当でもないため）。
  - 憲法の「マスターデータを `packages/data` のパイプラインだけで生成する」は、overlay を入力とするので満たす。

## Q176（決定: 2026-11-15）
- 問い（`open-questions.md` からの移設）: 表の正しさを手持ちの護石でどう検証するか。手持ちの護石が全件 `match.ts` で「合格」になれば表と矛盾しない（`temp/appraised-charm-table.md` §6）。集め方の候補は 016 の OCR・005 の手入力・端末に保存した護石の書き出しだが、端末の護石を書き出す機能は無い（仮: オーナーの手持ちをレア度ごとに数件以上、016 の OCR か手入力で登録し、表を入れた後のマスターで全件「合格」になることを手で確かめる。件数の下限は区間 A で決める。検証用の護石をテストの fixture にするかもそこで決める）
- 決定: オーナーの手持ちの鑑定護石（レア度・スキルとレベル・スロットの並び）を fixture にする。生成した実際のマスターを使い、`matchCharm` が全件「合格」を返すことを確かめる単体テストを `apps/web/src/test` に置く（`match.ts` が web にあり、`packages/data` からは使えないため）。
  - 件数は、表に入れたレア度ごとに 3 件以上を目安にする。満たないレア度も表には入れ、`design/master-data.md` に未検証として記録する。
  - fixture のスキルは、Q175 と同じ使い捨てのスクリプトで日本語のスキル名から `sk:` の ID に直す。
  - このテストのために、触る領域に web が加わる（テストだけで、画面は変わらない）。

## Q177（決定: 2026-11-15）
- 問い（`open-questions.md` からの移設）: 表を入れると、保存済みの護石の照合が「未検査」から「合格」か「テーブル不一致」に変わる。表に誤りがあると、正しい護石に「テーブル不一致」が出て、護石のフォーム（`CharmForm.vue`）が保存の前に確認を求める（仮: 照合は警告で保存を妨げないので、誤りの見込みがある表でも出す。画面に出典が非公式で未検証であることを示すかは区間 A で決める。マスターの版を上げる扱いは既存の版の更新と同じにする）
- 決定: 照合は警告だけで保存を妨げない（005 decisions.md Q29）ので、誤りの見込みがある表でも出す。出典が非公式で未検証であることは、画面に示さない（036 は画面を変えない）。マスターの版は、既存の版の更新と同じ扱いで 2026.10.5 から上げる。
