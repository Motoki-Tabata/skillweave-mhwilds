# 037: skill-effect-stats

## 目的 / ユーザーストーリー
プレイヤーとして、属性攻撃強化・状態異常強化・防御・各耐性のスキルを選ぶときに、説明文の後ろの補完で効果の数値を、攻撃・会心のスキルと同じように確かめたい。開発者としては、属性値・状態異常値・防御力・耐性値に効く数値をマスターの項目として持ち、023 element-damage（属性の期待値）と 038 skill-effect-values（説明文に数値が無いスキルの値）の土台にしたい。今のマスターは効果の種類が攻撃力・会心の 4 つ（`attack_add`・`attack_mul`・`affinity_add`・`crit_mul`）だけで、属性・状態異常・防御力に効く部分を書いていない（006 decisions.md Q37）。

用語:
- 効果の種類: マスターのスキルの `effectsByLevel` の各効果の `stat`。037 では decisions.md Q187 の表の 9 種類にする（攻撃力・会心率・会心倍率は既存）。種類の名前と書式は区間 C で決める。
- 種類の区別: 属性値・状態異常値・耐性値の効果が持つ、対象の属性または状態異常（火・水・雷・氷・龍・毒・麻痺・睡眠・爆破・全属性、または武器の属性を問わない）。
- 対象のスキル: 037 で効果の値を入れるスキル。火・水・雷・氷・龍属性攻撃強化、毒・麻痺・睡眠・爆破属性強化、防御、火・水・雷・氷・龍耐性の 15 件（decisions.md Q187）。
- 補完: スキルの説明文の後ろに `effectsByLevel` から画面で作る「効果: 」で始まる文（007 screen-design.md §4）。

画面に出す値の出どころ: 補完は、`packages/data` が生成する JSON の `effectsByLevel` を、`apps/web/src/main/lib/skills/effectSummary.ts` が文にする。火力の数値は、同じ JSON をソルバー（`packages/solver/src/main/damage.ts`）が計算して出し、037 では変えない。

## 受入基準（EARS記法）
- AC-1: THE system SHALL 効果の種類を decisions.md Q187 の表の 9 種類（攻撃力・会心率・会心倍率・属性値・状態異常値・属性の会心倍率・状態異常の会心倍率・防御力・耐性値。加算・乗算の別を含む）にし、`@swv/data` の型と overlay の規則の両方に定めなければならない。属性値・状態異常値・耐性値の効果は、種類の区別を持てなければならない。
- AC-2: IF overlay の効果が、新しい種類について値の規則（区間 C で決める）か種類の区別の規則（その種類で取れない区別・区別の欠落）に反するなら THEN システムは、ファイル名と行・桁を示してマスターの生成を失敗させなければならない。出力前の検証（規則 `skill-effects`）も同じ規則で検査しなければならない。
- AC-3: THE system SHALL 対象のスキルの全レベルの効果を、ゲーム内の説明文（ja の `levelDescriptions`）の数値から `packages/data/overlays/effects.yaml` に書かなければならない。属性値・状態異常値の加算の値はマスターの単位（説明文の値 ÷ 10）で、その他の値は説明文のままで書かなければならない（decisions.md Q193）。回数・段階を数える数値と、種類の区別が定まらない値は書いてはならない（decisions.md Q187）。
- AC-4: THE system SHALL 属性の会心倍率・状態異常の会心倍率を種類として受け付け、会心撃【属性】・会心撃【特殊】を含む説明文に数値が無いスキルの効果は空のままにしなければならない（値は 038 で入れる。decisions.md Q187）。
- AC-5: WHEN 効果を足したマスターを生成したとき THE system SHALL 版を 2026.11.1 から上げて `dist/` に現行の版だけを残し、対象のスキルの `effectsByLevel` 以外の内容（ID・名前・読み・分類・既存の 22 件の効果・抽選テーブル・防具など）を 2026.11.1 から変えてはならない。
- AC-6: THE system SHALL 生成した実際のマスターについて、次を `packages/data` のテストで検証しなければならない。火属性攻撃強化 Lv3 が火の属性値の ×1.2 と +6 を持つ。毒属性強化 Lv3 が毒の状態異常値の ×1.2 と +5 を持つ。防御 Lv7 が防御力の ×1.1 と +35 と全属性の耐性値 +5 を持つ。火耐性 Lv3 が火の耐性値 +20 と防御力 +10 を持つ。対象のスキルのすべてのレベルが空でない。説明文に属性値・状態異常値・防御力・耐性値の数値があるスキルは、効果を持つか、理由を添えた除外の一覧にある（006 の受入基準 3 の検査と同じ形）。
- AC-7: WHEN 構成の火力を計算するか、検索で構成を探すとき THE system SHALL 新しい種類の効果を数えず、攻撃力・会心率・会心倍率の効果だけで計算しなければならない。これを `packages/solver` のテストで、同じマスターから新しい種類の効果だけを除いたものと比べ、火力（攻撃力・会心率・会心倍率・期待値）と検索結果（構成と並び）が一致することで検証しなければならない。
- AC-8: THE system SHALL 検索の目的関数「防御力」を、防具の防御力だけで並べたままにし、防御力の効果を数えてはならない（decisions.md Q192）。
- AC-9: WHEN 新しい種類の効果を持つスキルのレベルの説明文を出すとき THE system SHALL その効果を補完に出さなければならない。属性値・状態異常値の加算は表示値（マスターの値 × 10）で出し、説明文と同じ数字に見せなければならない（decisions.md Q193）。種類ごとの文言は区間 B で決め、007 の書式（符号・小数第2位・発動条件の組）に揃えなければならない。
- AC-10: THE system SHALL `design/master-data.md` の §6（overlay の効果の規則）と §8（効果の数値の出典と書く範囲）を 037 の種類と範囲に合わせて書き直し、`effects.yaml` の冒頭のコメントの「属性・状態異常・オトモ・防御力に効く部分は書かない」を同じ範囲に改めなければならない。

## スコープ外
- 属性値・属性の会心倍率の火力の計算と、属性の最大化（023 element-damage）
- 防御力の効果を目的関数「防御力」に数えること（decisions.md Q192）
- 説明文に数値が無いスキル（会心撃【属性】・会心撃【特殊】・連撃など）の値と、Web の情報源を出典にする方針の変更（038 skill-effect-values）
- 攻撃の種類・部位・斬れ味で範囲を限るダメージ倍率、斬れ味、被ダメージの軽減、行動の数値の項目化（Q194）
- 回数・段階を数える数値と、属性吸収の「発動時に受けた属性の耐性値」のような種類の区別が定まらない値
- 構成カードなど、補完以外の画面に属性値・状態異常値・防御力・耐性値を出すこと
- 発動条件の追加（対象のスキルの効果はすべて常時）
- 属性値の強化の上限

## 契約差分
- なし（API は効果を持たない。マスターは静的配信の JSON で、保存済みの構成の `masterVersion` の形も変えない）
