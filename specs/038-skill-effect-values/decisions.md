# 038 skill-effect-values の決定記録

## Q185（決定: 2026-11-16）
- 問い（`open-questions.md` からの移設）: 038 skill-effect-values の出典の方針をどう変えるか。006 decisions.md Q37 と `design/master-data.md` §8 は効果の数値の出典をゲーム内の説明文に限り、§2 と 005 decisions.md Q3 は「攻略サイトはスクレイピングしない。人が照合するための参照にとどめる」としている。036 decisions.md Q170 は抽選テーブルの下書きに限ってこの方針を適用しないとし、方針そのものは変えていない。リポジトリは公開なので、採った値は overlay と `dist/` を通じて公開される（仮: §2 の原則を「MHDB とゲーム内の説明文に無い値は、オーナーが採用を決めた Web の情報源を出典にできる」に改め、Q37 と §8 を説明文に数値が無いスキルにも広げる。取得は 036 decisions.md Q170 と同じく、エージェントが候補のサイトを `curl` で 1 ページずつ全文を取って下書きを作り、オーナーが確かめて採用する。データマインの一次資料と Monster Hunter Wiki のライセンスを先に確かめる。Phantom Brawlers は規約で複製を禁じているので外す。権利面の判断はオーナーが行う）
- 決定:
  - `design/master-data.md` §2 の「攻略サイトはスクレイピングしない。人が照合するための参照にとどめる」を、「MHDB とゲーム内の説明文に無い値は、オーナーが採用を決めた Web の情報源を出典にできる。取得は 1 ページずつ手で行い、繰り返しの自動取得はしない」に改める。005 decisions.md Q3 と 006 decisions.md Q37 は、この改定で置き換わる範囲（説明文に無い値の出典）について見直したものとし、§8 の効果の数値の出典を「説明文。説明文に数値が無いものは Web の情報源」に広げる。
  - 取得と採用は 036 decisions.md Q170 と同じ形で行う。区間 D の最初のタスクで、エージェントが候補のサイトを `curl` で 1 ページずつ全文を取り、スキルごとの値の下書きを作る。要約や切り詰めのある取得手段で読まない。オーナーが下書きを確かめ、採用するかを決める。オーナーが採用しないときは区間 D を止めて出典の扱いを決め直す。
  - 候補のサイトは区間 C で列挙する。データマインの一次資料（ゲームファイルから値を取った表）と Monster Hunter Wiki のライセンスを、下書きの前に確かめる。Phantom Brawlers は規約で複製を禁じているので取得の対象から外す。
  - 権利面の判断はオーナーが行う。
- 理由: 会心撃【属性】などの値はゲーム内のどこにも無く、Web の情報源のほかに出典が無い。036 は下書きに限った例外にしたが、効果の数値はスキルが増えるたびに同じ判断が要るので、例外ではなく方針として改める。

## Q186（決定: 2026-11-16）
- 問い（`open-questions.md` からの移設）: Web から採った値の出典をどう記録するか。036 は読み比べたサイト・取得日・最終更新日・ゲームの版・未検証の箇所を `design/master-data.md` §10 にまとめて記録した。効果の数値はスキルごとに出典が分かれうる（仮: `design/master-data.md` に効果の数値の出典の節を足し、036 と同じ項目を記録する。`effects.yaml` の各スキルの名前のコメントに出典の種別（説明文／Web）を添え、説明文由来の値と区別できるようにする。取得した HTML と下書きはコミットしない）
- 決定: 仮のとおり。
  - `design/master-data.md` に「効果の数値の出典（Web）」の節を足し、読み比べたサイト・取得日・最終更新日・ゲームの版を節の冒頭にまとめ、スキルごとに採った値の出典のサイトと未検証の箇所を書く。
  - `effects.yaml` の Web 由来のスキルは、名前のコメントに `（Web）` を添える（例: `# 会心撃【属性】（Web）`）。説明文由来のスキルのコメントは変えない。冒頭のコメントの出典の記述も合わせて直す。
  - 取得した HTML と下書きはコミットしない（置き場は区間 C で決める）。

## Q189（決定: 2026-11-16）
- 問い（`open-questions.md` からの移設）: 二値の条件（006 decisions.md Q39）で表せない効果をどう扱うか。連撃のようにヒット数などで段階が上がる効果、時間や回数で変わる効果は、「発動している／していない」の 1 つの条件に収まらない（仮: 最大の段階を 1 つの条件の発動中の値として入れ、条件の名前で最大の段階であることが分かるようにする。段階の途中の値は入れない。最大の段階が出典で定まらない効果は空のままにする）
- 決定: 仮のとおり。加えて次のとおりにする。
  - 段階が同じきっかけの積み重ね（ヒット数・経過時間・力尽きた回数など）なら、最大の段階を 1 つの条件にする。条件の名前は最大であることが分かるものにする（例: 研鑽の「30 分経過」）。
  - きっかけが質的に違う段階（例: 黒蝕竜の力の「狂竜症に感染」と「克服」）は、条件を分ける。既存の条件と同じきっかけなら既存の条件を使う（例: 克服は `cd:antivirus`）。
  - 値がビルドの他の値で決まる効果（耐性変換の「耐性値が高いほど」）は二値に収まらないので入れない（Q195）。

## Q190（決定: 2026-11-16）
- 問い（`open-questions.md` からの移設）: 出典の間で値が食い違うときと、裏付けの取り方。036 decisions.md Q171 は手持ちの護石で裏付けたが、効果の数値は手持ちのもので確かめにくい。値は和集合にできない（仮: ① データマインの一次資料に値があればそれを採る。② 無ければ、その値を載せているサイトのうち多数が一致する側を採る。③ 同数なら入れずに空のままにする。② で採った値は `design/master-data.md` に未検証として記録する）
- 決定: 仮のとおり。値を載せているサイトが 1 つだけのときは ② に当たらないので、データマインの一次資料でなければ入れない。
- 理由: 値は和集合にできず、誤った値はソルバーの火力と並びをそのまま変える。空なら今と同じ結果のままで、害が小さい。

## Q191（決定: 2026-11-16）
- 問い（`open-questions.md` からの移設）: Web から採った値を画面で区別して示すか。007 はスキルの説明文の後ろに `effectsByLevel` から効果の数値を補完して表示する（`design/master-data.md` §8）ので、Web 由来の値もゲーム内の値と同じに見える（仮: 038 では画面を変えず、区別は `design/master-data.md` の記録だけにする。区別を画面に示すなら触る領域に web が加わるので、038 の区間 A で決める）
- 決定: 仮のとおり。038 では画面のコードを変えない。Web 由来の値も、補完と発動条件のトグルに既存の書式のまま出る。区別は `design/master-data.md` と `effects.yaml` のコメントだけにする。
- 理由: 区別を出すにはマスターの型に出典の項目を足すことになり、data・web にまたがる。必要になったら別の機能として起票する。

## Q195（決定: 2026-11-16）
- 問い（038 の区間 A で判明）: 038 で値を入れるスキルの範囲。マスター（2026.11.2）で効果が空のスキルのうち、説明文にステータスに関わる語があるものは 50 件余りあり、037 decisions.md Q187 の 9 種類に当たらない効果（追加ダメージ・攻撃の種類を限る倍率など）を含む。
- 決定: 037 decisions.md Q187 の 9 種類（攻撃力・会心率・会心倍率・属性値・状態異常値・属性の会心倍率・状態異常の会心倍率・防御力・耐性値）に当たり、説明文に数値が無い効果だけを対象にする。Q187 で書かないとした値（攻撃の種類・部位・斬れ味で範囲を限る倍率、オトモ、被ダメージの軽減、行動の数値、種類の区別が定まらない値）は、Web の値があっても入れない。
  - 対象の候補（値が出典で定まれば入れる）: 会心撃【属性】・会心撃【特殊】・連撃・災禍転福・属性吸収（属性値の部分）・属性変換（龍属性値の部分）・黒蝕竜の力・凍峰竜の反逆・千刃竜の闘志（Lv2 の攻撃力）・毛皮の昂揚・ヌシの憤激・ヌシの魂（攻撃力・防御力・耐性値の部分）・ヌシの誇り・花舞／夢灯／祝謡／踊火の祈り（Lv2）・波衣竜の守護・革細工の滑性・雪獅子の闘志・巨戟龍の黙示録・暗黒騎士の証（属性値の部分）・海竜の渦雷（会心率の部分）・オメガレゾナンス・研鑽・パワーストーン・暗黒・連携プログラム・シールドオプション。
  - 対象外: チャージマスター・フォースショット・通常弾／散弾／貫通弾の強化・砲術・焼き砲モロコシ・にぎりめし（攻撃の種類を限る）、鎖刃刺撃・火竜の力・白熾の奔流（追加ダメージ）、オトモへの采配（オトモ）、護竜の守り（被ダメージの軽減）、耐性変換【水】【雷】（値がビルドの耐性値で決まる。Q189）。
  - 仲間にも効く効果（雪獅子の闘志・連携プログラム・シールドオプション・ヌシの誇り）は、自分に効く値だけを入れる。自分に効くかが出典で定まらなければ入れない。
  - 候補の一覧は区間 C で実データから確定し、`packages/data` のテストの除外の一覧（037 の受入基準 6 と同じ形）に理由を添えて載せる。
- 理由: 037 decisions.md Q187 は、038 が overlay に値を書くだけで済むように種類を用意したとしている。9 種類の外の値は Q194 の後続の機能で扱う。

## Q196（決定: 2026-11-16）
- 問い（038 の区間 A で判明）: 武器種で値が変わる効果をどう扱うか。連撃の説明文は「上昇効果は武器種ごとに異なる」とし、マスターの効果は武器種の区別を持てない（037 の 9 種類の書式は属性・状態異常の区別だけ）。037 decisions.md Q187 は「038 で 037 に無い種類が要ると分かったら、038 では足さずに別の機能として起票する」とした。会心撃【属性】なども、調べると武器種で違う可能性がある。
- 決定: 038 では効果に武器種の区別を足さない。出典で武器種によって値が違うと分かった効果は、空のままにし、`design/master-data.md` の出典の節に武器種ごとの値を記録しておく。武器種の区別を足して値を入れる機能を、038 の区間 E で `/tsod-discover` により起票する。
  - 出典で全武器種に同じ値と分かった効果は、武器種の区別なしで入れる。
- 理由: 武器種の区別を足すと、`@swv/data` の型・overlay の規則・ソルバーの計算（武器種による効果の絞り込み）・補完の文言が変わり、data・solver・web にまたがって 1〜3 日に収まらない。037 decisions.md Q187 の取り決めにも沿う。
