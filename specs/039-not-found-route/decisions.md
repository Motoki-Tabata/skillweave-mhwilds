# 039 not-found-route の決定記録

## Q136（決定: 2026-11-16）
- 問い（`open-questions.md` からの移設）: 存在しない URL の扱い。`router/index.ts` に一致しない経路の定義が無く、存在しない URL を開くと空の画面になる。また `wrangler.jsonc` の `not_found_handling: single-page-application` により、存在しないファイル（例: デプロイで消えたハッシュ付きの JS）にも `index.html` が 200 で返る。デプロイの後に古いタブが `import()` で旧チャンクを読むと、JS として HTML を受け取って読み込みに失敗する可能性がある。本番で確かめた（2026-11-03）。`/no-such-page` は 200 の HTML で、ヘッダーとフッターだけの空の画面になる。存在しないファイル（`/assets/no-such-chunk-AAAAAAAA.js`・`/no-such-file.png`）にも 200 の `text/html` が返る。存在しないチャンクの `import()` は `TypeError: Failed to fetch dynamically imported module` で失敗する。古いタブを開いたままデプロイする再現はしていない（仮: 経路の定義に「見つかりません」の画面を足す。チャンクの読み込み失敗は再読み込みを案内する。URL を配る前には直さず、公開後に扱う。機能マップに 039 not-found-route として追加した。古いタブの問題は再読み込みで解消する見込みで、フレンド公開の規模なら許容できる）
- 決定: 仮のとおり。細部は次のとおりにする。
  - 存在しない経路: どの経路にも一致しないパスに、キャッチオールの経路（`/:pathMatch(.*)*`）で「見つかりません」の画面を出す。画面はヘッダー・ナビ・クレジットのバーを持つ既存の枠の中に出し、ページのタイトルを付け、装備検索（`/`）へ戻るリンクを置く。URL は書き換えない（開いたパスのまま）。見た目は区間 B で決める。
  - ログインからの戻り先（`safeReturnPath`）: キャッチオールを足すとすべてのパスがどれかの経路に一致するので、「一致する経路がある」だけでは不明なパスを弾けなくなる（009 handoff.md の持ち越し）。キャッチオールの経路に一致したパスは、今と同じく `/` に戻す。
  - チャンクの読み込み失敗: 画面の移動で経路の部品（遅延読み込みのチャンク）を読めなかったとき、読み込めなかった旨と再読み込みのボタンを、利用者が閉じるまで出し続ける通知で示す。自動では読み込み直さない（理由: 入力中の内容を予告なく失わせない）。ボタンを押したら、失敗した移動の行き先の画面を新しく読み込んで開く（理由: もう一度ナビを押す手間を省く）。既存の新しい版の通知（018）と同じ場所・同じ部品で出すかは区間 B で決める。
  - 新しい版の Service Worker が待機中のときに再読み込みすると、古い版の Service Worker が古い `index.html` を返して同じ失敗を繰り返しうる。再読み込みの経路は区間 C で、待機中の版を先に有効にするか（018 の更新通知の再読み込みと同じ経路）を決める。
  - 配信の設定（`wrangler.jsonc` の `not_found_handling`）と Worker（`worker/index.ts`）は変えない。理由: 存在しないファイルに 404 を返しても、ブラウザでは `import()` が同じく失敗するので、利用者から見た扱いはクライアントで決まる。`/builds/:id`・`/s/:shortId` のような経路の妥当性は配信側で判定できないので、存在しないページにも `index.html` を 200 で返すのは変えない。
  - Service Worker（018）は変えない。ナビゲーションの要求は拡張子の無いパスなら事前キャッシュの `index.html`（`shell`）を返すので、存在しない経路でもオフラインでも「見つかりません」の画面がクライアントで出る。
  - 対象にしないもの: 経路の部品以外の動的 `import()`（OCR の `tesseract.js`。OCR の既存のエラー表示で扱う）・Web Worker（ソルバー。既存の停止の表示で扱う）・存在しない ID（`/builds/:id`・`/s/:shortId` の 404 は各画面が既に扱う）。
