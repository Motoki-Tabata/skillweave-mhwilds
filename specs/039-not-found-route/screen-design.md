## 0. 前提

- 「見つかりません」の画面は、キャッチオールの経路（`/:pathMatch(.*)*`）で出す（decisions.md Q136）。ヘッダー・ナビ・クレジットのバーを持つ既存の枠（`App.vue`）の `RouterView` の中に出す。URL は開いたパスのまま変えない。
- 見た目は、既存の「共有された構成が見つかりません」の表示（`SharedBuildView.vue` の `notFound`）に揃える。見出し・本文・「装備検索へ」のリンクの3つだけを置く。
- 読み込み失敗の通知は、018 の新しい版の通知（MASTER.md「新しい版の通知」）と同じ置き場・同じ面・同じ部品で出す（decisions.md Q136 で区間 B に残した問い）。理由: 利用者に求める行動（再読み込み）が同じで、作業領域を押し下げない置き場がすでにあるため。
- 文字サイズは MASTER.md の Type Scale の4サイズのうち、20px（見出し）・14px（本文・通知の見出し）・12px（通知の本文）だけを使う。

## 2. S9「見つかりません」の画面

### 2.1 画面構成

作業領域の枠は既存の画面と同じ（`mx-auto w-full px-4 py-4 md:max-w-[720px] md:px-6 lg:max-w-[1280px]`）。その中で、見出し・本文・リンクを最大幅 720px のまとまりに入れる（`lg` 以上で本文の1行が長くなりすぎないため。`PrivacyView.vue` と同じ）。上から縦に並べる。

| 順 | 部品 | 内容 |
|---|---|---|
| 1 | 見出し `h1` | 「ページが見つかりません」。20px・700・行間 1.4。下に 12px の間隔 |
| 2 | 本文 `p` | 「URL が間違っているか、ページが移動または削除された可能性があります。URL を確かめるか、装備検索から使い始めてください。」。14px・400・`--foreground` |
| 3 | リンク | Button `outline`（高さ 40px）の見た目の `RouterLink`（`to="/"`）。文言「装備検索へ」。本文の下に 12px の間隔、左寄せ |

- 本文とリンクは `flex flex-col items-start gap-3` で並べる（`SharedBuildView.vue` の `notFound` と同じ）。
- 主要ボタン（橙の面）は置かない。リンクは outline にする（既存の notFound の表示と揃える。「Buttons」節の「主要ボタンは1画面に1つ」の上限に触れない）。
- 開いたパスは画面に出さない（長いパスの折り返しを考えずに済み、URL バーで見えるため）。
- アイコン・画像・イラストは置かない（Page Pattern の「装飾のイラストは置かない」）。

### 2.2 項目定義

| 項目 | 値 |
|---|---|
| ページのタイトル（`document.title`） | `ページが見つかりません | SkillWeave`（経路の `meta.title`） |
| `h1` | `tabindex="-1"`・`outline-none`。既存の画面と同じく、表示したときにフォーカスは移さない |
| リンクの行き先 | `/`（装備検索） |

入力項目は無い。

### 2.3 状態

| 状態 | 表示 |
|---|---|
| 通常 | 2.1 のとおり。読込中・空・エラーの状態は持たない（データを読まない） |
| オフライン（Service Worker が制御中） | 通常と同じ（AC-3。Service Worker が返す `index.html` から同じ画面が出る） |

### 2.4 遷移

| 操作 | 行き先 |
|---|---|
| 「装備検索へ」 | `/`（装備検索）。アプリ内の移動 |
| ナビのリンク | 各画面（既存のまま） |

### 2.5 幅の見積もり（最小幅 360px）

作業領域の内幅は 360 − 16 × 2 = 328px。

| 要素 | 幅 | 判定 |

## 3. N2 読み込み失敗の通知

### 3.1 置き場と並び

- 置き場は N1 と同じ `AppToaster` の `ToastViewport`（ヘッダーの下・右端、幅 320px・画面の幅から左右 16px を引いた幅を超えない）。
- トースト・N1 と同じ1つの並びに入り、出た順に上から積む（間隔 8px）。N1 と N2 が同時に出ていてもよい（互いに消し合わない。AC-9 で N1 の挙動を変えないため）。

### 3.2 部品と項目定義

N1 と同じ面（`--card`・`--border` の 1px・角丸 4px・内側余白 上下 12px・左 16px・右 56px）。

| 部品 | 内容 |
|---|---|
| 見出し `ToastTitle` | 「画面を読み込めませんでした」。14px・500 |
| 本文 `ToastDescription` | 「新しい版が公開された可能性があります。再読み込みすると、開こうとした画面を開きます。保存していない入力は消えます。」。12px・`--muted-foreground`。見出しの下 4px |
| 再読み込みのボタン | Button `outline`（高さ 40px）「再読み込み」。本文の下 12px・左寄せ。押した直後は無効にして「再読み込み中…」にする |
| 閉じるボタン | Button `ghost` のアイコンボタン（44×44px・右上・lucide `X` 20px）。`aria-label`・`title` は「通知を閉じる」 |

- 文言は「エラー文言は原因と次の行動をセットで書く」（UI Copy）に従う。原因（部品を読み込めなかった・新しい版の公開）と次の行動（再読み込み）を書く。
- 見出しの色は `--foreground` のまま（`--destructive` にしない）。利用者の操作の誤りではなく、再読み込みで解消するため。N1 と同じ見た目にして、同じ種類の案内であることを示す。

### 3.3 状態

| 状態 | 表示 |
|---|---|
| 出ていない | 何も出さない |
| 出ている | 3.2 のとおり。自動では消さない（`duration` は `Infinity`）。自動で読み込み直さない |
| 再読み込み中 | ボタンを無効にし「再読み込み中…」 |
| 出ている間に再び読み込みに失敗した | 通知は1つのまま（増やさない）。再読み込みの行き先を、最後に失敗した移動の行き先に替える |
| 閉じた後に再び読み込みに失敗した | 通知をもう一度出す（AC-7。並びの位置はそのときに出た順） |
| 読み込み失敗以外の理由で移動が失敗した | 出さない（AC-8） |

### 3.4 遷移・操作

| 操作 | 結果 |
|---|---|
| 「再読み込み」 | 失敗した移動の行き先の画面を、ページを読み込み直して開く（AC-6）。待機中の新しい版を先に有効にするかは区間 C で決める（decisions.md Q136） |
| 閉じる（✕・Esc・スワイプ） | 通知を消す。今の画面はそのまま操作を続けられる（AC-7） |

- 移動が失敗したとき、画面は移動の前の画面のまま変えない（vue-router の既定のまま）。URL も移動の前のまま。
- 読み上げは `ToastRoot` の `type="foreground"`（`aria-live="assertive"`）。利用者がナビを押した直後に画面が変わらない理由を、すぐに伝えるため（N1 は利用者の操作と無関係に出るので `background` のまま）。フォーカスは移さず、モーダルにしない。

### 3.5 幅の見積もり（最小幅 360px）

通知の幅は 320px、内側の幅は 320 − 16 − 56 = 248px。

| 要素 | 幅 | 判定 |
|---|---|---|
| 見出し「画面を読み込めませんでした」（13字 × 14px） | 約 182px | 1行に収まる |
| 本文（約 55字 × 12px） | 約 660px | 折り返す（3行程度）。切り詰めない |
| 「再読み込み中…」のボタン（7字 × 14px ＋ 左右 16px） | 約 130px | 収まる |

## 4. MASTER.md に足す規範

`design-system/skillweave/MASTER.md` の Component Specs に次の2節を足す（spec.md の影響範囲「常時許可外の変更予定」のとおり）。値は本書 2 節・3 節の確定内容から、画面を問わず守る規範だけを写す。

- 「見つからない画面の表示」: 見出し（h1）・本文（原因と次の行動）・「装備検索へ」の outline のリンクの3つ。主要ボタン・アイコン・イラストは置かない。既存の「共有された構成が見つかりません」と同じ構成。
- 「読み込み失敗の通知」: 「新しい版の通知」と同じ置き場・面・部品・自動で消さないこと。違いは、見出しと本文の文言、読み上げを `foreground` にすること、閉じた後に再び失敗したらまた出すこと、出ている間は1つにまとめること。
