# 039: not-found-route

## 目的 / ユーザーストーリー
利用者として、打ち間違えた URL や古いリンクを開いたときに、空の画面ではなく「ページが見つかりません」と分かり、装備検索へ戻りたい。また、アプリを開いたままの間に新しい版が公開され、画面を移ろうとして読み込めなかったときに、無反応のまま止まらず、再読み込みすれば使えると分かりたい。

用語:
- 「見つかりません」の画面: どの経路にも一致しないパスで出す画面。キャッチオールの経路（`/:pathMatch(.*)*`）で出す（decisions.md Q136）。
- 部品の読み込み失敗: 画面の移動で、遷移先の画面の部品（遅延読み込みのチャンク）を読めずに移動が失敗すること。デプロイで旧チャンクが消えたときに起きる。
- 読み込み失敗の通知: 部品の読み込み失敗を知らせ、再読み込みのボタンを持つ通知。

## 受入基準（EARS記法）
- AC-1: WHEN 利用者がどの経路にも一致しないパスを開いたとき（URL を直接開く・アプリ内で移る、のどちらでも） THE system SHALL ヘッダー・ナビ・クレジットのバーを持つ既存の枠の中に「ページが見つかりません」の画面を出し、ページのタイトルを `ページが見つかりません | SkillWeave` にしなければならない。URL は開いたパスのまま変えてはならない。
- AC-2: THE system SHALL 「見つかりません」の画面に、装備検索（`/`）へ移るリンクを出さなければならない。
- AC-3: WHILE Service Worker が画面を制御し、端末がオフラインのとき WHEN 利用者がどの経路にも一致しないパスを開いたとき THE system SHALL AC-1 と同じ画面を出さなければならない（decisions.md Q136。Service Worker は変えない）。
- AC-4: IF ログインの前に覚えた戻り先のパスが、キャッチオールの経路にだけ一致するパスなら THEN システムは、ログインから戻ったときに `/` を開かなければならない。既存の経路に一致する戻り先は、今と同じくそのパスを開かなければならない。
- AC-5: WHEN 画面の移動で部品の読み込みに失敗したとき THE system SHALL 読み込めなかったことを伝える文と「再読み込み」のボタンを持つ通知を出し、利用者が閉じるまで出し続けなければならない。自動で読み込み直してはならない（decisions.md Q136）。
- AC-6: WHEN 利用者が読み込み失敗の通知の「再読み込み」を押したとき THE system SHALL 失敗した移動の行き先の画面を、ページを読み込み直して開かなければならない。
- AC-7: WHEN 利用者が読み込み失敗の通知を閉じたとき THE system SHALL 通知を消し、今の画面の操作を続けられるようにしなければならない。その後に再び部品の読み込みに失敗したときは、通知をもう一度出さなければならない。
- AC-8: IF 画面の移動が部品の読み込み失敗以外の理由で失敗したなら THEN システムは、読み込み失敗の通知を出してはならない。
- AC-9: THE system SHALL 既存の経路（`/`・`/builds`・`/builds/:id`・`/shares`・`/s/:shortId`・`/charms`・`/weapons`・`/privacy`）の表示とページのタイトル、新しい版の通知（018）の挙動を変えてはならない。

## スコープ外
- 配信の設定（`apps/web/wrangler.jsonc` の `not_found_handling`）と Worker（`apps/web/worker/index.ts`）の変更。存在しないページ・ファイルに `index.html` を 200 で返すのは変えない（decisions.md Q136）
- Service Worker（`apps/web/src/main/sw/**`）の振り分けと事前キャッシュの変更
- 経路の部品以外の動的 `import()`（OCR の `tesseract.js`）と Web Worker（ソルバー）の読み込み失敗。既存のエラー表示で扱う
- 存在しない ID（`/builds/:id`・`/s/:shortId` の 404）。各画面が既に扱う
- 自動での読み込み直し、読み込み失敗の再現の自動検知（版の照合など）
- 「見つかりません」の画面での HTTP ステータス 404 の応答

## 契約差分
- なし（API を持たない。エンドポイント・スキーマを変えない）
