# 機能マップ

入力: `temp/initial-design.md`（§1・§2・§5・§7〜§9・§11）・`temp/solver-types.ts`。
機能 ID は実装順に振る（依存の表を満たす順で、同じ段では優先度の高いものを先にする）。

### 機能マップ
| 機能ID | 名称 | 1行の価値 | 優先度 | 想定サイズ | 状態 |
|---|---|---|---|---|---|
| 001 | solver-spike | HiGHS WASM で実データ規模の ILP（必須スキル・防具5部位・護石・スロット Lv 別の装飾品個数）が数秒以内に解けるかを測り、最大の技術リスクを先に潰す | P0 | M | 未着手 |
| 002 | master-data-pipeline | MHDB（SHA 固定）の取得→gameId からの ID 生成→YAML オーバーレイ→検証→`master-<version>.json` と ja/en 辞書の出力を、1コマンドで再現できるようにする | P0 | L | 未着手 |
| 003 | solver-engine | `SolverRequest`→`SolverResponse` の本実装（シリーズ／グループスキル・部位の固定と除外・武器固定・装飾品の配置の後処理・複数解・タイムアウトとキャンセル・`masterVersion` 照合・Worker のメッセージ型）を DOM 非依存の純関数で提供する | P0 | M | 未着手 |
| 004 | solver-ui | ログインなしで、武器と必須スキルを指定して検索し、結果の構成（防具・装飾品・発動スキル・空きスロット）を見られる最初の画面（マスター読込・Worker 結線・二次創作表記とクレジット・e2e 基盤を含む） | P0 | L | 未着手 |
| 005 | charm-input | ゲストが鑑定護石を手入力して端末内（IndexedDB）に保存し、抽選テーブルで入力の妥当性を検査し、ソルバーの護石候補に使える | P0 | M | 未着手 |
| 006 | damage-model | スキル効果（`effectsByLevel`）と発動条件をオーバーレイで定義し、構成の期待値を計算して、ソルバーの `maximize: expectedDamage` で使えるようにする | P1 | M | 未着手 |
| 007 | damage-ui | 結果の構成ごとに火力（期待値）を表示し、発動条件をトグルで切り替え、スキル説明文の後ろに効果の数値を補完して表示する | P1 | M | 未着手 |
| 008 | user-weapon | 巨戟アーティア等の個体差がある武器（復元ボーナス・付与シリーズ／グループスキル）を端末内に入力し、ソルバーの固定武器に使える | P1 | M | 未着手 |
| 009 | discord-login | Discord OAuth でログイン・ログアウトでき、セッションを Spring Session JDBC で保持する | P1 | M | 未着手 |
| 010 | charm-save | ログインユーザーが護石をサーバーに保存し、複数端末で同じ護石一覧を使える（attributes.yaml の最初の確定） | P1 | M | 未着手 |
| 011 | build-save | ログインユーザーが検索結果の構成に名前を付けて保存し、一覧から開き直せる（作成時の `master_version` を記録する） | P1 | M | 未着手 |
| 012 | build-share | 保存した構成のスナップショットを短縮 ID の URL で共有し、受け手が閲覧できる（元を編集・削除しても内容は変わらない） | P1 | S | 未着手 |
| 013 | user-weapon-save | ログインユーザーが個体差のある武器をサーバーに保存し、複数端末で使える | P2 | S | 未着手 |
| 014 | guest-draft-import | ログイン時に、ゲストの端末内の下書き（護石・武器・構成）を一方向・一回きりでサーバーへ取り込む | P2 | M | 未着手 |
| 015 | ocr-spike | Tesseract.js でゲーム画面のスクリーンショットから護石を、実用的な精度と時間でブラウザ内で読み取れるかを測る | P2 | S | 未着手 |
| 016 | charm-ocr | スクリーンショットから護石を読み取り、確認・修正のうえで護石一覧に登録できる（画像はサーバーへ送らない） | P2 | M | 未着手 |
| 017 | reverse-lookup | 「この護石があれば組める」構成を抽選テーブルから逆引きし、狙う護石の候補を示す | P2 | L | 未着手 |
| 018 | pwa-offline | アプリをインストールでき、オフラインでも閲覧とソルバー実行ができる | P2 | S | 未着手 |
